# 跬步 · 古诗词背诵

面向小朋友的**古诗文复习与背诵**应用。覆盖**小学一年级到高中三年级**（人教/统编版教材）共 **261 首**古诗文，首首配白话译文；另设独立的**小古文**学习库（100 篇）。

纯前端单页应用（PWA），**打开即用、无需注册、可离线**，所有学习进度保存在本机浏览器里，不上传任何服务器。支持电脑、安卓手机、苹果手机（iPhone / iPad）。

> 应用正式名称为 **跬步**。填了用户名后标题显示为「跬步 · 小明的古诗词」。

> 《敕勒歌》《长歌行》《迢迢牵牛星》《观沧海》《短歌行》《木兰诗》《归园田居（其一）》这几首课内已收，乐府集子里按「同一篇只落一份正文」并进课内那一条，乐府这边只留条目（与唐诗 / 宋词 / 元曲的判重同一条路）。

从 `/library/` 点进一部集子时，那一部的索引是**就地**铺在同一个页面上的（地址栏不动），再点一篇才叠上阅读器 —— 于是「目录 → 索引 → 正文」是同一页里的三层，右上角的返回键一层退一层。各集子自己的 `/xxx/` 页面照旧可通过直接访问或在新标签页打开。

> ⚠️ 这「两层」都住在 `library/index.html` **同一个 `.app` 里**：就地铺上来那一层
> 只是一块 `<div data-lib-view="book">`，**不再套 `.app`**。`.app` 是全站「一列纸」的
> 宽度来源（`max-width: --col-w` + 左右各一条 `--col-side` 的边），套在 `.app` 里面
> 就会把列宽与两侧的边各算两遍 —— 里面那张卷次卡与搜索框会比页顶那一条顶栏
> 左右各窄一条边（手机 28px、桌面 112px），看着就是「卡片莫名其妙变窄了」。
> 同页的课内诗词索引页 `/poems/` 里没有这一层嵌套，所以只有它看着是对的。

## 版式：手机 / 平板 / 桌面

三档断点（≥560 / ≥768 / ≥1024px），**手机是基准，宽屏是另一套排布而不是拉宽**：

| | 手机 | 平板 ≥768px | 桌面 ≥1024px |
|---|---|---|---|
| 一列纸 `--col-w` | 720px | `min(1040px, 100vw)` | `100vw`（跟窗口走，两侧各 56px） |
| 一整块内容 `--block-w` | — | 940px | 940px |
| 卡片内边距 / 块距 | 14 / 14px | 22 / 26px | 26 / 26px |
| 篇目列表 | 一列 | 两列 → 三列 | 列宽封顶 280~320px，列数随窗口（940px 里 3 列，1808px 里 5 列） |
| 首页 | 一列到底（进度 → 今日 → 全部） | 同手机 | 进度 ‖ 今日 并排，全部跨行（`grid-template-areas`，DOM 顺序不变） |
| 设置分组 | 一列 | 两列 | 三列 |
| 入口页集子卡 | 一列 | 两列 → 三列 | 3 列栅格（按窗口换行） |
| 行宽 `--read-w` | 720px | 720px | 720px（**不跟屏幕变**，一行 35~40 字是阅读上限） |

⚠️ 三条容易踩的口径：

- **「布满屏幕」管的是页面，不是每一张卡**。桌面那一档一列纸跟视口走
  （不要明信片式的 960px 定宽），但纸上**每一块内容**封顶
  `--block-w`（940px）—— 1808px 宽、100px 高的一张卡不是明信片，是一条横幅。
- **块距与行距必须分开**。卡片与卡片之间 26px，条目之间 10~14px：
  距离本身要能说出「这是两块」还是「这是一组」。两者同值时整页会糊成一片。
- **两条顶栏（列表页那条 + 阅读器那条）的左右内缩是同一个数**，
  都由 `--col-side` 给。阅读器顶栏是 `.reader` 的直接子项，
  默认会收到 `.topbar` 上那份 `max-width: var(--content-w)` 与 `margin: 0 auto` ——
  两者叠加会让返回键比列表页更贴边（手机少一条边、桌面少两条）。
  `css/classic.css` 的 `.reader > .topbar` 因此显式 `max-width: none; margin: 0;`，
  左右另按 `calc(var(--col-side) + var(--safe-*))` 内缩，与 `.app` 逐像素对齐。

版式那一档集中在 `css/style.css` 的「平板 / 桌面版式」一段，
由 `test/ui-consistency.test.js` 的「四之三」那一节守着（块距与行距分开、
`--block-w` 只在 ≥768px 定义且**没有**替换 `--col-w`、首页三块真的认领了各自的
`grid-area`、宽屏那一档的分组不再自己写 `margin-top`）。

## 功能

- **每日背诵任务**：每次进入应用自动列出今天要背的诗词（默认 5 首，可调 3 / 5 / 8 / 10 首），分「复习」与「新学」两类。
- **复习算法自动排期**：点开诗词后如实选择掌握程度（记住 / 模糊 / 忘记），系统自动算出下次复习时间。内置四套算法（遗忘曲线 / 莱特纳盒 / SM-2 / FSRS），在设置页切换，**换算法不清进度**。四套**按层级开放**：游客只有遗忘曲线，登录的 Free 加莱特纳盒，Pro 加 SM-2，Max 四套齐备。
- **背诵范围 6 选 1**：本册及之前 / 小学随机 / 初中随机 / 小初随机 / 高中随机 / 全部随机。范围外已学过且到期的仍会排入复习。
- **今日加背**：小朋友今天临时想多背一首时，在今日背诵页顶上那个「今日加背」的输入框里搜到、点「＋」就行 —— 5 首当场变 6 首。集子页与搜索页的**列表每一行**、**详情页**（插在译文与「加入背诵」之间）也有同一颗「＋」。加进来的与课内篇目一样走当前复习算法排下次，但**不写进自选集合**，也不受背诵范围限制；设置「背诵」页里单列一块可多选删除。它只属于今天：跨过 0 点自动归零（判据是「今天」这个日期，不是定时任务）；开了云端同步之后它也跟着走 —— 两台设备**同一天**加的那几首会并起来，不会互相覆盖。
- **进度可视化**：今日环形进度、单篇记忆阶段与掌握度、背诵进度总览 `/progress/`（到期日历 + 全部到期篇目 + 掌握度分布 + 记忆阶段）。
- **自选背诵**：除教材之外自己额外想背的篇目，可建多个集合、增删改查、导入导出、排进遗忘曲线，管理入口在设置的「我的清单」页（`/settings/lists/`）。
- **全站搜索 `/search/`**：一次搜遍九部集子，搜篇名 / 作者 / 朝代 / 出处，也搜正文与白话译文。
- **生字注音**：三档「不注音 / 生字 / 全文」，由设置的「朗读」页（`/settings/reader/`）里的注音总开关统一控制。
- **注音勘误**：注音是算出来的（按字查表 + 按词消歧），古文里总有表与词表都没料到的组合。**通例进词表**（《滕王阁序》「秋水共长天一色」的「长」就是这一类：`WORDS` 里补上「长天」「长空」后全站各处都对），**个例进勘误层**。管理后台（`/admin/`）里有一块「注音勘误」：搜篇目 → 点一句 → 填「这一句里第几次出现」与「应读作 cháng」，**钉住那一处**即刻生效（不必等发版）。它只改**这一篇的这一句**，别的篇不受影响；随账号同步，换台设备也照着读；随时可删。详见 `docs/architecture.md` §4.36。
- **自动朗读**：基于系统语音，零音频文件、断网可用。可读单篇、读当日全部、随机连读，底部有播放栏控制。
- **古诗词大会**（`/poems/` 上就地铺开的那一层）：**飞花令**（Max）与**试题模拟**（Max）、**题库复习**（Pro）。
  判分不花钱也不接 AI —— 用的是仓库里的同一个出题内核。详见下面「古诗词大会 / 试题模拟」一节。
- **PWA 离线**：安装到桌面后可离线背诵，首次打开需联网加载一次。

## 使用方法

### 直接打开
用浏览器打开根目录的 `index.html`（建议起本地服务，避免个别浏览器 `file://` 限制）。

### 本地起服务
```bash
node scripts/serve.js        # 项目自带的零依赖服务器（支持目录化地址，推荐）
python3 -m http.server 8080  # 或 Python 3
# 然后访问 http://localhost:8080
```

服务器需支持「目录索引」：所有地址都是目录形式，不带 `.html`（根 `/` → `index.html`，`/classic/` → `classic/index.html`），Nginx / GitHub Pages / CNB Pages 无需额外配置。

### 手机上使用
把整个目录放到任意静态服务器，用手机浏览器打开即可。

- **苹果 / iPad**：用 Safari 打开 → 底部「分享」→「添加到主屏幕」→「添加」。微信等 App 内置浏览器不支持安装，应用会提示改用 Safari。
- **安卓**：用 Chrome / Edge 打开，浏览器会提示「安装应用」。
- **电脑**：浏览器直接打开，或点地址栏右侧安装图标装成独立窗口应用。

## 扩展数据

在 `data/poems-N.js` 中按以下结构追加即可，`id` 需唯一：

```js
{
  id: "xx1-13",
  title: "诗题",
  author: "作者",
  dynasty: "唐",
  grade: 1,      // 1-12
  term: 1,       // 1 上学期 / 2 下学期
  text: "第一句，\n第二句。",
  translation: "白话译文，必填 —— 全库 261 首目前 100% 齐备。",
  translationSource: "school"   // 译文口径，四类取值见下
}
```

各选集（`data/poems-classic.js` / `-tangshi.js` / `-songci.js` / `-guwen.js` / `-zhaoming.js`）结构相同，只是分组字段换成 `gradeGroup`（分类 / 卷次 / 词牌 / 文体）。

**译文是必填项**，且须标注来源口径（`translationSource`）。译文为本项目**自拟的白话直译**，不逐字搬用任何一家译本，四类取值：

| 取值 | 含义 |
|---|---|
| `school` | 依据统编版教材与教师用书课后释义 |
| `academic` | 依据《唐诗鉴赏辞典》等工具书的通行讲法 |
| `public-domain` | 原文属公有领域，依据公认注本与通行译注 |
| `modern` | 依据现行通用选本与通行讲法 |

加完新篇目后跑一遍：

```bash
node scripts/audit-translations.js             # 逐首体检：缺译文 / 过短 / 抄原文 / 来源标注
node scripts/tag-translation-source.js --dry   # 看新篇目的来源标注
node scripts/tag-translation-source.js         # 补上（幂等，只补缺的）
python3 scripts/supplement-fonts.py            # 新译文带来的新字补进字体子集
node test/run.sh                               # 全量测试
```

新增译文往往带来字体里没有的字，不补字体那些字会缺笔画（表现为字被吃掉半边）。

## Service Worker 约定

`sw.js` 负责离线缓存，三条硬约定：

1. **`sw.js` 里不写任何注释**（`//` 行注释与 `/* */` 块注释都不写）。顶部注释块漏一个 `*/` 就会让整份文件解析失败、Service Worker 从不注册、离线能力静默失效，页面上完全看不出来。`test/theme.test.js` 有源码扫描断言守住。
2. **静态资源是「缓存优先」**：css / js / 字体命中缓存就直接返回，不回源比对。因此**只要动了 `css/` 或 `js/` 里的文件，就必须把 `CACHE_NAME` 的版本号 +1**，否则老用户会一直拿着旧副本（改样式必须升级版本）。同时有几个 PR 在改时，每个 PR +5，避免撞号。
3. **`/api/*` 一律早退，不缓存也不由 SW 应答**（1 期新增）。接口的每个响应都带 Cookie 与时效：缓存它等于「换个人打开手机还是上一个人的会话」，离线应答更糟 —— 会让人以为「登录成功了」，其实什么都没发生。现在 `req.method !== "GET"` 已经天然挡住了这些接口，这一条是防**将来有人把它改成 GET**。它必须排在 `navigate` 分支之前（`test/api.test.js` 有断言同时守这两件事）。

第 1、2 条写在 `test/theme.test.js` 里，第 3 条写在 `test/api.test.js` 里，改错了测试会拦下来。原先这份维护约定与逐版沿革单独记在 `SW-NOTE.md`，现已删除并禁止再加：`sw.js` 不写注释是硬规矩，约定本身写在本节即可，逐版沿革交给版本控制。

## 数据与隐私

- 学习进度与用户名**默认只存在本机浏览器**（localStorage），不建账号就一行数据都不往外发。
  哪些数据跨设备一致、哪些只属于这台设备，有一份可枚举的清单（见文末「存储分域」）。
- **不注册也能用全部功能**；可自愿用**邮箱 + 密码**注册账号，也可以不记密码、
  每次用邮箱收一串**随机码**登录（两条路签发的是同一枚会话）。
  注册后我们会发一封**确认邮件**，**点开那条链接之后才能登录**
  （没确认就登不进来 —— 这是为了保护账号；确认之前本站的背诵功能照旧完全可用，
  被拦住的只有云端账号那一部分）。
  账号域数据（背诵档案、年级学期、背诵范围、昵称印记）会上传到服务器
  以便跨设备同步，**设备偏好（字号 / 对齐 / 注音开关 / 连读档）不上云**；
  可在「设置 · 通用 · 账号」关掉云端同步退回只存本机，注销即删除服务器上的数据。
- **邮箱会保存到服务器**（登录与找回密码要用它）；**密码不存明文** ——
  库里只有一段加盐的单向摘要（scrypt），所以**找不回原密码**，
  忘记时走「忘记密码」重设一个新密码（重设后其它设备上的登录会全部退出）。
  这些在 `/privacy/` 里逐条写明（「条款跟随代码」：代码改了条款就跟着改）。
- 无统计脚本、无广告，断网可用 —— 服务器连不上时背书、朗读、导出一切照旧。
- 想手动搬数据，设置里有「导出备份 / 导入备份」。
- 联系邮箱不以明文出现在源码里，由 `js/contact.js` 在运行时拼装，防爬虫抓取。

详见 `/terms/`（用户协议）与 `/privacy/`（隐私条款）。

### 服务端接口（已落地）

Vercel Serverless，**同源、无 CORS**：

| 接口 | 做什么 |
|---|---|
| `POST /api/send-code` | 邮箱归一化 → 四层频控 → 生成 6 位码 → 哈希落库 → 发信 |
| `POST /api/verify-code` | 校验码 → 建/取账号 → 签发 **HttpOnly Cookie** 会话 |
| `GET  /api/me` | 权益的唯一来源：`{uid, nickname, plan, features[], mask, channel}` |
| `GET  /api/config` | 本站**公开**配置（**不需要登录**）：人机校验的 `turnstile.{enabled,siteKey}` 与发信 `mail.delivered` |
| `POST /api/sync/pull` | 增量拉云端进度（游标是**服务端时间**，不是客户端时钟） |
| `POST /api/sync/push` | 按条合并写回；载荷白名单化，时间戳老的盖不掉新的 |
| `DELETE /api/account` | 注销：**先导出、再删行**，并清掉会话 |
| `POST /api/avatar` | 头像上传：请求体是**裸字节**（压缩 + 裁切都在客户端做完），按 magic number 判类型，存 Supabase Storage |
| `DELETE /api/avatar` | 删掉云端那张（回到用户名首字印）|
| `POST /api/admin/grant` | 2.2 **权威发放**层级：写 `accounts.plan`，按邮箱掩码 |
| `DELETE /api/admin/grant` | 2.2 收回：等价于发一个 `free`，不删账号、不删进度 |
| `POST /api/admin/grants` | 2.2 看权威名单（只回掩码，只列**发过层级**的那几条） |
| `POST /api/register` | 注册：邮箱 + 密码 → **立刻建号**（待确认）+ 发确认邮件 |
| `POST /api/login` | 邮箱 + 密码登录 → 签发**同一枚** HttpOnly Cookie 会话（**没确认回 403**） |
| `POST /api/verify-email` | 点邮件里那条链接确认邮箱（**不需要登录**） |
| `POST /api/resend-verification` | 重发确认邮件（**要登录**，否则任何人都能拿别人邮箱刷） |
| `POST /api/resend-verification-by-email` | 重发确认邮件（**匿名**）—— 「没确认就不让登录」这条路上，**登不进来的人正是最需要那封信的人** |
| `POST /api/reset-request` | 忘记密码第一步：发重设邮件（**不泄露邮箱是否存在**） |
| `POST /api/reset-confirm` | 忘记密码第二步：换新密码 + **吊销全部会话** + 如实回 `emailVerified`（未确认的人仍然登不进去，那一句必须说出来） |
| `POST /api/admin/accounts` | 账号名录：列出**全部注册账号**（含**明文邮箱**），只读 |
| `GET /api/diag` | 自助排查：会话密钥配没配、库是内存还是 Supabase、六张表逐张的 HTTP、列形状、**写入实跑一次**（插一行标 `__diag__` 的 progress，读完即删）、**本次请求里哪几列没写进去**（`degraded`）。**只回形状与 HTTP 状态，永不回密钥** |

业务内核全在 `api/_lib/core.js`（handler 只做「读请求 → 调内核 → 写响应」），
所以能在 Node 里直接测 —— `test/api.test.js` 用**真 http 请求**跑完整链路。

**函数数：线上只有 1 个，不是 19 个。** Vercel Hobby 档一个部署最多 **12 个**
Serverless 函数，而上面这 19 条路由按「一个文件 = 一个函数」数就是 19 个
（构建直接失败：`No more than 12 serverless functions can be added to a
deployment on the hobby plan`）。所以：

- 19 条路由的实现放在 `api/_routes/`（`_` 开头的目录 Vercel 不当函数）；
- `api/[...path].js` 是**唯一那个函数**（catch-all），按 `api/_lib/routes.js`
  那张**唯一的路由表**把请求交给对应的 handler；
- `vercel.json` 里**一条 rewrite**（`/api/:path*` → `/api/handler/:path*`）
  把外部地址接进去。

**外部 URL 一个都没变**（`/api/me` 还是 `/api/me`），客户端、文档、`npm run doctor`
的 curl 全部照旧。

⚠️ **收口必须是「catch-all 文件 + 一条 rewrite」，不能靠目录兜底**（2026-09-18 的教训，
见 `docs/architecture.md` §2.2.1.1）：2026-09-17 那版把 `index.js` 直接放在 `api/` 下
当 `/api` 目录的兜底函数，**线上从来没生效** —— 全站 `/api/*` 回 Vercel 平台层的 404
（`The page could not be found` + `x-vercel-error: NOT_FOUND`，连函数日志都没有），
静态页面照旧 200，本地测试还全绿（测试挂的是模块，平台那一层在测试里不存在）。
现在 `api/` 下只有 `[...path].js` 这**一个**函数，`test/api.test.js` 末节同时守着
三件事：函数数 = 1、`vercel.json` 里**有**那条 rewrite 且 destination 等于
`routes.js` 的 `PREFIX`、以及**按用户地址与按 rewrite 之后的地址各真打一次**。

**验收这一条**（第 E 步第 ⑥ 条）：`curl -sS "$SITE_URL/api/config"` 期望 **200**；
回 404 且正文是 `The page could not be found` = 打到了平台层，`/api/*` 没接到函数上。

**四条硬规矩**：明文验证码不进任何日志（`api/_lib/http.js` 的 `log()` 会把 `code` 之类一律抹掉）；
权益只从 `/api/me` 来，请求体里的 `plan` 一律忽略；所有写接口都有频控；
**能改别人数据的那条接口有服务端角色闸**（`accounts.role` 是 owner / admin 才放行，
否则 `403` —— 把入口藏起来**不是**安全边界）。

**2.2 权威发放的前提**：对方**先登录过一次**（库里得先有那一行），
否则接口如实回 `{matched:0, changed:false}` 并说明成因。
⚠️ 绝不「查不到就替他建一条」—— 掩码不可逆，造出来的是**永远登不上的幽灵行**。

**降级路径**（服务端不可用时如实退回本机，不假装）：

| 情况 | 表现 |
|---|---|
| 没配 `SUPABASE_URL` / `SUPABASE_SERVICE_KEY` | 用进程内 store（只适合本地与测试） |
| 没配 `SESSION_SECRET` | 接口回 **503 `E_NOT_CONFIGURED`**（不是 500），前端标为「本机体验版」 |
| 没配 `SENDGRID_API_KEY` / `RESEND_API_KEY` | 落到 `console` 通道：**不发信、也不打印明文码** |
| 断网 / 超时 / 连不上 | 发码静默回落本机；校验那一步如实说「连不上」（不回落，因为码在服务端） |

部署与建表见 `api/_lib/schema.sql`（四张表，RLS 全开且不给任何策略 = 默认拒绝）。

`/api/me` 还会**如实自报这台服务器开通到哪一步**：

```jsonc
"channel": { "mail": "sendgrid"|"console", "delivered": true, "db": "db"|"memory", "sms": false,
             "turnstile": true|false, "emailGate": true|false, "rate": "instance" }
```

`mail` 是 `console` 就是「真实用户收不到信」、`db` 是 `memory` 就是「重启即丢」——
界面在说「由服务器判定」时，得让用户看得见说的是**哪一台服务器**。
这一份**不落盘、不参与判权**（只用来如实标注）。

### 开通自检与配置清单（2C 已落地）

「让它真的能用」这件事只需要配几个环境变量 —— 它没有业务代码可写，
所以做成**可执行**的，而不是一篇要人手抄的文档：

```bash
npm run doctor                        # 缺哪个、缺了会怎样、怎么补（退出码 = 体检结论）
npm run doctor -- --json              # 程序看的形状（CI / 部署前检查）
npm run doctor -- --steps             # 怎么补：六步（配 Supabase / 发信商 / Turnstile / 探活 / 验收）
npm run doctor -- --steps --check     # 同上，外加「据当前环境变量，走到第几步了」
npm run env:example > .env.example    # 生成可直接粘贴的模板
```

清单**只有一处**（`api/_lib/ops.js` 的 `ENTRY`），自检与 `.env.example` 读的是同一份 ——
手抄的清单必然与代码分叉。

三档分得清：

| 档 | 哪些 | 缺了会怎样 |
|---|---|---|
| **必须** | `SESSION_SECRET`（或 `SESSION_KEY`，二选一，前者优先）、`SUPABASE_URL`、`SUPABASE_SERVICE_KEY` | 接口整体 503 / 只用内存存储（重启即丢） |
| **这一件需要** | `SENDGRID_API_KEY` | 发不出真邮件，落到 `console`（只写服务端日志） |
| **可选** | `MAIL_TRANSPORT`、`MAIL_FROM`、`SITE_URL`、`COOKIE_NAME`、`SMS_*`、`ALLOW_CODE_ECHO`、`MAIL_RETRY_MAX`、`MAIL_RETRY_BUDGET_MS`、`PASSWORD_MIN`/`PASSWORD_MAX`、`VERIFY_TTL_MS`、`RESET_TTL_MS` | 用默认值 |
| **默认开** | `REQUIRE_EMAIL_VERIFIED` | 邮箱没确认就不让登录；**只在没配好发信商的实例上**显式设 `0` 关掉（关掉时界面会如实说「这台服务器没有拦确认」） |
| **默认关** | `TURNSTILE_ENABLED` / `TURNSTILE_SITE_KEY` / `TURNSTILE_SECRET_KEY` | 人机校验（Cloudflare Turnstile）。**没配好两个 key 就别打开开关**（否则谁也别想登录）；本地开发 / CI 用 `TURNSTILE_BYPASS=1`（**只在服务端读**，生产绝不许开） |

⚠️ 其中两个要留意：
- `REQUIRE_EMAIL_VERIFIED` **默认 `1` = 邮箱没确认就不让登录**（用户裁决）。
  只在**发信真的通不了**的实例上才写 `0` —— 那时确认邮件送不到收件箱，
  开着这道闸等于谁也别想注册。关掉时界面会如实标注。
- `MAIL_RETRY_*` 是发信失败时的**退避重试**（默认重试 2 次、总预算 6 秒）。
  ⚠️ 它不是后台补发队列 —— Serverless 里没有常驻进程，「过五分钟再试」需要真队列。

**一个都不配也照样能完全离线使用** —— 自检把这句话写在报告里，免得「未配置」被读成「坏掉」。
⚠️ 报告里**只出现变量名、绝不出现值**（连长度都不报），因为这段文字就是给人贴进 Issue 的。
真值放 `.env`（`.gitignore` 挡着），空模板 `.env.example` 要提交。

`test/ops.test.js` 拿三个假密钥钉死「不报值」，并断言清单与 `config.js` **双向同源**。

**六步是按顺序走的**（`--steps` 打的就是这六步；F 是本轮加的人机校验）：

| 步 | 做什么 | 判据 |
|---|---|---|
| **A** | 生成 `SESSION_SECRET`（`openssl rand -hex 32`） | 自检里它从「未设置」变「已设置」 |
| **B** | 建 Supabase 项目 → 跑 `api/_lib/schema.sql` → 拿 URL + **service_role**（不是 anon） | 自检「最低线已过」；`rest/v1/accounts` 回 **200** |
| **C** | 注册 **Resend**（主选）→ 建 key → **验发信子域 + SPF/DKIM/DMARC 三条 DNS** | 自检里发信通道不再是 `console`；真发一封信 `delivered:true` |
| **F** | **Cloudflare → Turnstile → Add site** → 拿一对 key（Site / Secret）→ 填进托管平台三个变量（见下节） | `/api/config` 回 `turnstile.enabled:true`；不勾提交时服务端回 `400 E_TURNSTILE` |
| **D** | 上探活与备份（`.cnb.yml` 里两条 `crontab`）；备份另需 `SUPABASE_DB_URL` | 流水线列表里看得见；手动触发探活成功 |
| **E** | 配完当场验收四步 | `/api/me` 回 **401**（回 503 就是 A 没生效）、发码 `delivered:true`、注销回 **401** |

**这一步 AI 做不了**：注册 Supabase / 发信商都要本人邮箱与手机号。能自动化的部分是
**「步骤本身」与「判据本身」**（都在 `api/_lib/ops.js` 的 `STEPS` 里，与清单同一份数据）。

#### 环境变量都填完了，下一步是什么

**不要照着这张表再念一遍步骤，而是拿判据去问那台实例**：
「配好了」与「配对了吗」是两件事，而**「配了」这件事本身也可能没生效** ——
Vercel 的环境变量**只在新部署里生效**（这是「我明明配了」里最常见的一种）。
按 E 步的四条判据逐条打一遍，每一条都有一个明确结论：

```
curl -sS -o /dev/null -w '%{http_code}\n' "$SUPABASE_URL/rest/v1/accounts?select=uid&limit=1" \
  -H "apikey: $SUPABASE_SERVICE_KEY" -H "Authorization: Bearer $SUPABASE_SERVICE_KEY"  # 期望 200
curl -sS "$SITE_URL/api/me" | head -c 200                      # 期望 401（回 503 就是 SESSION_SECRET 没生效）
curl -sS "$SITE_URL/api/config"                                # 期望 200 + turnstile.enabled:true 且带 siteKey
# ⚠️ 若上面两条回 404 且正文是「The page could not be found」，那是 **Vercel 平台层**
#    报的（本站的 404 形状是 {"code":"E_404",...}）—— 意思是 /api/* 没接到函数上
# 发一次码：delivered 必须是 true，transport 要是你配的那一家
```

⚠️ 其中**最容易被跳过、也最容易假绿**的一条是**发信**：
`delivered:true` 才算真发出了去了。旧的界面在**没配成**时会照着说
「重设链接已经发出去了 / 确认邮件已经发出了去了」—— 现在这三处落点都读了
同一份事实（`/api/config` 的 `mail.delivered`），发信不通时当场改口成
「这台服务器还没接上发信商」并指路第 C 步。设计与全部口径见 `docs/architecture.md` §5.11。

#### 发信商到底在哪配：**托管平台的环境变量**，不是 Resend、也不是 Supabase

这一条被问过好几次，所以写死在这里：

| 你做了什么 | 它管什么 | 它**不管**什么 |
|---|---|---|
| 在 **Resend** 后台建 key / 验域名 | Resend 那一家**允许**你用它的服务发信 | 我们的代码不知道有这枚 key |
| 在 **Supabase** 建项目 / 跑 `schema.sql` | 账号与进度**存哪**（数据库） | 与发信**完全无关**（Supabase 的邮件是它自己的注册信，不是本站的验证码） |
| 在 **托管平台**（Vercel / CNB / 自建）配环境变量 | 把上面那枚 key **交给本站的服务端** | — |

所以：**Resend 配好只是「钥匙配好了」，还得把钥匙插到这把锁上** ——
那把锁就是**跑着本站服务端的那台机器**的环境变量。本站的 `api/*` 是 Vercel
Serverless 函数（`docs/architecture.md` §4.1），所以那台机器就是**Vercel 这个项目**：
Vercel → 你的项目 → Settings → Environment Variables。

要填的就是这一枚（`MAIL_TRANSPORT` 不必填 —— 只填 Resend 一枚时推断就是它）：

```
RESEND_API_KEY = re_xxxxxxxx        # Resend → API Keys → 建一枚（Sending access 即可）
MAIL_FROM      = noreply@mail.你的域  # 必须是 Resend 里**验过的那个子域**里的地址
```

顺序只能这样走，**倒过来不行**：

1. Resend → Domains → 加一个发信子域（如 `mail.kuibu.app`），按提示加 **SPF / DKIM / DMARC** 三条 DNS 记录，等到状态是 **Verified**
2. Resend → API Keys → 建一枚 key（**Sending access** 就够，别给 Full access）
3. **Vercel → 项目 → Settings → Environment Variables** → 建 `RESEND_API_KEY`（值填第 2 步那枚 key），`MAIL_FROM` 填第 1 步验过的子域里的地址
4. **重新部署一次**：Vercel 的环境变量**只在新部署里生效**，光改不重新部署 = 没改（这是最常见的「我明明配了」）
5. 回来验：终端里 `curl -sS "$SITE_URL/api/me"` 那段照 `npm run doctor -- --steps` 的第 E 步走，或直接在 `/login/` 发一次码 —— `delivered:true` 才算成了。`npm run doctor` 里「发信通道」那一行从 `console` 变成 `resend` 是同一件事的另一种看法

⚠️ 三条容易踩的：

- **只验域名不够**：SPF / DKIM / DMARC 缺一条，QQ / 163 会直接判垃圾邮件或拒收。先看垃圾箱，再看 Resend 的投递日志（那里会说 ISP 为什么拒）
- **`MAIL_FROM` 必须落在验过的子域里**：`noreply@gmail.com` 这类会被发信商直接拒（你不是那个域的主人）
- **`RESEND_API_KEY` 只在服务端**：它是密钥，不进浏览器、不进仓库、不写进 `.env.example`

不必填 `MAIL_TRANSPORT=resend` 的前提是「**只有** Resend 一枚密钥」。
哪天又填了 `SENDGRID_API_KEY`，缺省推断会**挑 SendGrid**（推断顺序里它在前面），
这时必须显式写 `MAIL_TRANSPORT=resend` —— `npm run doctor` 会主动点破这一条。

#### 人机校验在哪配：**Cloudflare 拿 key、托管平台填环境变量**

登录 / 注册 / 密码找回 / 发送随机码这几条**匿名可写、会发信、会建号**的口子
可以加一道**人机校验**（Cloudflare Turnstile）。设计与「挡在哪几条、为什么不挡另几条」
见 `docs/auth-design.md` §4.4.12；这里只写**在哪配、怎么配、怎么知道配成了**。

⚠️ 与发信商那一节同一条纪律：**Cloudflare 那边只是「允许你用它的服务」，
锁在跑着本站服务端的那台机器的环境变量上。**

四步（`npm run doctor -- --steps` 的第 F 步就是这四步）：

1. **Cloudflare 控制台 → Turnstile → Add site** → 填本站域名（`kuibu.app` 这种，
   **不带** `https://`）→ Create
2. 建完那一页给你**两个 key**，它们是一对，**缺一个都跑不起来**：
   - **Site Key** —— 公开值（由 `/api/config` 下发给浏览器渲染 widget）
   - **Secret Key** —— 保密（只在服务端核 token 时用）
3. **托管平台 → 项目 → Settings → Environment Variables** → 建**三个**：

   ```
   TURNSTILE_ENABLED    = 1                      # 开关（默认 0 / 关）
   TURNSTILE_SITE_KEY   = 0x4AAAAAAA...          # Add site 那一页的 Site Key
   TURNSTILE_SECRET_KEY = 0x4AAAAAAA...          # 同一页的 Secret Key
   ```
4. **重新部署一次** —— 环境变量**只在新部署里生效**，光改不重新部署 = 没改

**怎么知道配成了**（四条，每条一个明确结论）：

```bash
curl -sS "$SITE_URL/api/config"      # 期望 {"turnstile":{"enabled":true,"siteKey":"0x…"}}
```

- 打开 `/login/`，密码那一屏下方应当出现 Cloudflare 的方框
- 故意不勾就点「注册」→ 前端就地提示「请先完成人机校验」，**不发请求**
- 把 widget 删掉再点（模拟绕过前端）→ 服务端回 **`400 E_TURNSTILE`**
  —— **这一条才证明闸在服务端**（前端那一道只省一次必然失败的请求）

⚠️ 四条容易踩的：

- **两个 key 是一对，缺一个都是坏的**：只填 Site Key（前端渲染了）而缺 Secret Key，
  服务端视为「没开」→ **跳过校验**（看着像开着，实际没拦）；
  只填 Secret Key 而缺 Site Key，前端不渲染 → **每次登录都被服务端拒**。
  `npm run doctor` 的提醒会把这两档分别点破。
- **`TURNSTILE_SECRET_KEY` 只在服务端**：不进浏览器、不进仓库、不写进 `.env.example`。
  而 `TURNSTILE_SITE_KEY` 相反 —— 它**必须**进浏览器，这是它的设计。
- **本地开发 / CI** 用 `TURNSTILE_BYPASS=1`（**只在服务端读**，绝不随任何响应下发）。
  也正因如此，生产开着它时客户端无从察觉 —— `npm run doctor` 会为它单独喊一条警告。
- **widget 要允许本站域名**：Add site 时填的域名与实际访问域名不一致时，
  widget 会渲染失败（浏览器控制台看得见）。

⚠️ **没配就如实降级**：`turnstileReady()` 为 false 时服务端**跳过**校验，
并自报在 `/api/config`（`turnstile.enabled:false`）与 `/api/me` 的 `channel.turnstile` 里。
前端**一个字节都不发给 Cloudflare**（不渲染、连脚本都不加载）——
绝不摆一个空壳让人以为「本站有人机校验」（与 `mail: "console"` 同一条纪律）。

#### 出问题了怎么查

注册（或登录）报一句「服务端出了点问题，稍后再试」时，**不要从日志开始 —— 从自检开始**。
那句话是 `E_INTERNAL`（HTTP 500），它把**四种互斥**的原因合并成了一句：

| 真实原因 | 自检怎么说 |
|---|---|
| 什么库都没配 | 数据存储：**内存**（账号重启即丢） |
| 库地址错 / 项目被暂停 | `取一行 accounts`：HTTP **0** + `fetch failed` |
| 建表 SQL 没跑 | HTTP **404**（`PGRST205 Could not find the table`） |
| 表是旧形状（缺列） | HTTP **400**（`42703 column … does not exist`） |
| key 填成了 anon / 改完没重新部署 | HTTP **401**（`Invalid API key`） |
| 读得通、写不通 | `写入实跑`：失败 |

**但「表是旧形状」这一档，不该再让用户看到那句话了。** 建号写的是老表认得的列，
迁移列（`email` / `email_verified_at` / `password_hash` / `password_salt`）
另发一发去补；哪几列没落库**如实写在响应里**（`storeDegraded`），
自检再照实说。也就是说：库没迁的后果是「密码暂时登录不了」，
**不是**「注册时丢一句服务端出了点问题」。

> 为什么值得单独写一段：这处是第一例「用户什么都没做错、配置也没错，
> 却被自己的兜底 catch 甩了一句 500」。`test/register-legacy-db.test.js`
> 用一个真 HTTP、真 PostgREST 形状（`PGRST204` / `42703`）的**旧表库**把注册跑穿，
> 守着两件事：旧表上注册仍是 202 且账号真的落库；新表上一个降级字段都不许冒出来。

两种用法，都不需要终端：

1. **页面上跑**：「我的 → 设置（齿轮）→ 关于 → 自检」（`/self-check/`）。
   它逐条给**过 / 未过 / 无**，外加 `/api/diag` 的服务端结论，还有一颗「复制报告」——
   报告里只有结论、HTTP 状态与上游原话，**没有密钥**，贴到 Issue 里就能接着往下定。
2. **一条命令**：`curl -sS "$SITE_URL/api/diag"`。返回的 `verdict` 是互斥的一个值：
   `no_secret` / `db_not_configured` / `db_unreachable` / `db_bad_key` /
   `db_no_table` / `db_no_column` / `db_write_fail` / `ok`。

页面**打不开**（多半正是 `/api/*` 没挂上）时，自检页面上还摊着六条 `curl` 判据：
API 挂上没 / 会话签得出来没 / 库读得动没 / 库写得动没 / 注册真跑一遍 / 日志里搜 `api.error`。

自检那发 `/api/register` 探针**一个字都不写**：它用**形状不合法**的邮箱
（`selfcheck-probe@invalid`），服务端在归一化那一步就回 400。反之，用合法邮箱
跑一发在「没配库」的内存模式下**真会建号**（实测 202），所以这一句不许改 ——
`test/self-check.test.js` 里有一条对照断言守着它。

> `diag` 只回**形状**不回**值**：主机名脱敏成前 3 位 + 后 12 位，
> 密钥只说「是不是 service_role」。`test/self-check.test.js` 拿一个假 Supabase
> 把四种坏法逐个跑出来，并断言报告里不出现任何密钥值，也不出现那四个变量名。

  `/progress/` 的「背诵进度总览」）、子用户、危险区（注销）。一屏之内，不用再点。
- **设置整页（`/settings/`）只回答「怎么调机器」**：四组入口一行不减地搬过去，
  入口是「我的」页右上角那颗**齿轮**（`<body data-top-action="settings">`，
  `js/chrome.js` 认这一个值）。

四条口径：

- **分类一个字没改**：四张页合起来把原来那几组摊开 —— 拆页不是重新分类。
  两条各只有一条设置的组（阅读辅助 / 朗读播放）后来并成了一组「朗读」，
  这一页的两条设置（自动注音 · 五档连读方式）同组，全站分组由六组变五组；
  3 期的「打印」（篇目打印页，Pro）随后长在「我的清单」页上，全站现在是六组
- **一页只有一组时，正文顶部不再重复写组名**：「通用」「朗读」已经写在
  顶栏页名上（`data-page`），正文再写一遍是同一句话在同一屏里说两次。
  有两段的那两张页仍留分组名（「背诵」页的 `背诵` / `复习算法`、
  「我的清单」页的 `打印`）—— 它们分的是页里两段，仍有信息量
- **一份逻辑跑多张页**：`js/settings.js` 仍是每张设置页共用的那一份，控件取不到就跳过；
  「我的」页只加载 `js/mine.js` + `js/avatar-edit.js` + `js/family-ui.js`，
  不把整页设置逻辑拖进来。**头像上传 / 裁切**（`js/avatar-edit.js`）与
  **子用户那一块**（`js/family-ui.js`）各自只有一个来源 —— 这一轮之前它们
  长在 `js/settings.js` 里，两页要共用就得整份拖过去，所以先抽出来
- **二级页的返回键回上一层**：`settings/general|recite|lists|reader` 仍是
  `data-back="/settings/"`，而设置整页自己是 `data-back="/mine/"` ——
  `js/chrome.js` 只认站内绝对路径，从「朗读」返回背诵首页等于把用户一脚踢出设置。
  **「我的」页没有返回键**（它是页签落点，右端让给齿轮）
- **「关于」是设置整页最底下一块只读信息，不是一张独立页**：应用名 / 版本 /
  离线状态 + 权限对比 / 用户协议 / 隐私条款**六行**。它的样式在 `css/style.css`
  的 `.settings-about` 那一段（标题 15px + `--font-poem`，六行读共享的
  `.kv-row` 节奏）—— 这一块曾经一行 CSS 都没有，`h2` 顶着浏览器默认样子，
  比四张入口卡还大
- **那三条法务 / 权限链接是「左格本身当链接」**（不是「左格文字 + 右格一颗
  『查看』」）。对应的是 `css/style.css` 里的 **`.kv-k a`** 那一条 ——
  天青主色 + 一道 `--celadon` 细线 + 30px 触达高度。**这一条不能少**：
  少了它，这几处就落回浏览器默认的蓝紫链接（改形状忘了改规则，出过两次）。
  个人中心「关于」里那两行是**同一个形状**，两处共用这一条规则

新页面与新脚本都进了 `sw.js` 的预缓存清单，断网也能进「我的」与设置。

### 跨设备同步（1B 已落地）

学习进度默认**只存在本机**。要换设备接着背，需要两件事同时成立：
**建了账号** + **在「设置 · 通用」把跨设备同步开关打开**（**出厂是关着的** ——
不主动打开就不会有任何上传，`docs/architecture.md` §4.2）。

| 什么会同步 | 什么不会 |
|---|---|
| 背诵进度（每首的等级 / 复习次数 / 下次复习时间） | **设备上的阅读偏好**：字号、对齐、注音开关、连读档 |
| 账号域设置：学段 / 年级 / 学期 / 范围 / 每日数量 / 复习算法 | 今日计划缓存（`sessionStorage`，本就是会话级） |
| 各部集子的「已读」标记 | 开关本身（那是这台设备自己的意愿） |

**同步失败不打断背诵**，这是这一层最重要的一条：断网、超时、后端挂了、
服务端没配好、会话过期、被频控 —— 十种坏情况在 `test/sync.test.js` 里逐条验过，
判据是三条：① `now()` 永不抛异常 ② 本机进度一字不动 ③ 失败之后照样能写新进度。
另外**本机那份始终是完整的一份**：关掉开关、退出登录、后端整体停摆，
背书 / 朗读 / 导出一切照旧。

**冲突不自动合并。** 同一篇在两台设备上都改过、又判不出来源时，
个人中心会列出两边各有几篇让你自己选：

| 选法 | 会发生什么 |
|---|---|
| 保留本机 | 本机那一份打上「刚改过」的标，下一轮推上去 |
| 保留账号 | 按云端那一份覆盖 —— **覆盖前先在本机留一份快照**（点错了还能捞回来） |
| 先导出再决定 | **一个字节都不改**，导出一份含「本机进度 + 待裁决篇目清单」的 JSON |

内部记账有三个字段值得知道（都在本机，不进 `localStorage` 以外的地方）：
`poem_sync_pref_v1`（开关，默认关）、`poem_sync_seen_v1`（每条「见过的云端时间戳」，
`-1` 表示待裁决的冲突）、`poem_pre_merge_backup_v1`（合并前的快照）。

### 账号三页：/login/ /profile/ /admin/（已落地）

架构与排期的全文在 `docs/architecture.md`；「用邮箱登录」的流程细节在
`docs/auth-design.md`，配套的纯逻辑内核是 `js/auth-core.js`（零 DOM 依赖，
可在 Node 里直接跑）。**「现在不做、以后做」的条目另有一份 `docs/todo.md`**
（短信登录真开通、微信小程序版等）—— 那是唯一一处，别把「以后做」读成「快好了」。

| 地址 | 页名 | 做什么 |
|---|---|---|
| `/login/` | 登录 | **两个页签**（密码登录 / 快捷登录）+ 注册、忘记密码两屏支路；信任期内一点即入 |
| `/verify/` | 确认邮箱 | 邮件里那条链接的落地页（`?vid=&token=`），点开即确认 |
| `/reset/` | 重设密码 | 邮件里那条链接的落地页（`?rid=&token=`），设完新密码回登录页 |
| `/profile/` | 个人中心 | 四张卡：身份（印 + 昵称 + 掩码 + 层级，附一行操作键）· 本机数据 · 关于（法务 / 层级对比 / 跨设备同步 / 管理后台）· 注销账号 |
| `/admin/` | 管理后台 | **服务端权威发放**（2.2）+ **本机名单**（1 期之前的兜底，两份分开）；「以 Free 身份预览」 |
| `/plans/` | 层级对比 | 四列横向对照：未登录 / Free / Pro / Max，逐条打钩打叉 |

**两条主路**：

- **密码登录**：邮箱 + 密码。注册时设的那个密码，之后走这条路。
- **随机码快捷登录**：邮箱 → 收 6 位码 → 填码。**不记密码的人走这条**，
  该邮箱没有账号就顺手建号 —— 用户不需要理解自己在做「注册」还是「登录」。

**四条支路**：注册（邮箱 + 密码 ×2 → 邮件确认）、确认邮箱、
忘记密码（发重设邮件）、重设密码（设新密码 → 踢掉其它设备）。
这四条都**住在登录页的两个页签旁边**（文字链进去的那两屏 + 两张独立落地页），
一次只显示一件事：一页只有**一件主动作**（实心按钮），其余动作收成文字链。

**人机校验（Cloudflare Turnstile，可选）**：配上之后，登录页的四条主动作
（密码登录 / 发送随机码 / 注册 / 忘记密码）以及两处「重发确认邮件」
各会多一块 Cloudflare 的方框。「配在哪几条、为什么不配另几条」见
`docs/auth-design.md` §4.4.12。三条口径：

- **默认关**，且**没配就一个字节都不发给 Cloudflare**（不渲染、连脚本都不加载）——
  页面上不会出现一个空壳让人以为「本站有人机校验」（与 `mail: "console"` 同一条纪律）
- **真闸在服务端**：前端那一道只省一次必然失败的请求；绕过前端直接打接口
  会拿到 `400 E_TURNSTILE`
- **失败一律一句话**（「人机校验没通过，请刷新页面再试一次」），
  不回 Cloudflare 的 `error-codes`（那些码会把「密钥配错了」暴露给调用方）——
  它只进服务端日志（`api.turnstile_blocked`）

配置步骤见上一节「**人机校验在哪配**」（四步 + 四条自检）。

**口令与随机码并存是刻意的，不是过渡状态**：家长群体记不住密码
（「忘记密码是最高频的求助」），所以「不想记口令的人」必须还有得走；
反过来只有随机码也不够 —— 找回凭证、跨设备、将来的第三方绑定
都要一个稳定的账号锚点。两条路签发的是**同一枚会话**，下游不必知道
用户从哪条路进来。

**四个页签里没有账号的位置**（背诵 / 课外 / 搜索 / 我的，每格才两三个字），
所以入口从已有结构里长出来，一共两个落点：

| 落点 | 什么时候出现 | 指向 |
|---|---|---|
| 「我的」页**身份卡里那行操作键** | 总是 | 未登录 → `/login/`；已登录 → `/login/`（管理登录状态） |
| 个人中心身份卡里那行操作键 | 总是 | `/login/` |

「我的」页那颗键的**文案**按登录态分两种（未登录「登录」/ 已登录「管理登录状态」），
**落点是同一个 `/login/`** —— 登录页自己管两件事（进来 / 出去），不摆两颗各有说法的键。

返回落点：`/login/` → 个人中心 → 「我的」页；登录**成功之后**也回 `/profile/`
（「我去哪一层」那一行在那里）。**已登录时不再摆「去登录」**（自相矛盾），
未登录时那颗键才叫「登录」。详情见
`docs/auth-design.md` §3.6.2。

**服务端不可用时哪几屏会说实话**（两类动作分开）：

- **随机码那一路**照旧**静默回落到「本地体验版」**（随机码由本机生成，
  可复制到自己邮箱保管）—— 它本来就是本机自证。
- **口令那四屏**（注册 / 密码登录 / 确认 / 重设）**整体如实说「暂时不可用」**，
  **绝不**回落本机：口令摘要要有服务端 pepper、要落库，在浏览器里存一份
  等于把「谁都改得动」的东西当凭据。偷偷回落会给出一个「注册成功了」
  但换台设备就登不上去的假承诺。

两条路的说明**互斥** —— 一块说「进度会保存到服务器」，另一块说
「本应用没有服务器」，任一情况下摆错一句都等于对用户说谎；
界面用的是「已**生成**随机码」而不是「已发送」，有反向断言拦着后者。

已经定下的规矩：

- 登录有**两条路**：邮箱**随机码**（6 位、10 分钟、单次使用）与
  **邮箱 + 密码**。两条路签发**同一枚会话**
- 短信登录**只留口子**：`channel: "email" | "sms"` 走同一套 `requestCode` / `verifyCode`，
  将来加通道不用改签名、不用改表结构（登录页里那段「其他登录方式」现在**是注释**，
  不渲染，也不写「即将上线」）
- 明文验证码与明文令牌**绝不落盘**（只存摘要）；**明文口令也不落盘**
  （只存 `scrypt$N$r$p$salt$hash`，参数写在串里 —— 将来调参数老用户仍能登录）
- **邮箱明文落库**（按用户裁决「邮箱必须记录到数据库」）：
  `accounts.email` 是明文，`email_hash` 仍用于登录查找。
  明文只下发给「你自己」（`/api/me`）与**管理员**（`POST /api/admin/accounts`），
  别人的邮箱永远只以掩码出现

**退出与注销都不碰背诵进度**：退出只清会话，注销只删账号记录（要二次确认 +
重输一次邮箱）。界面上如实写出来，实测注销后进度键原封不动。
三张页**一个字节都不写进度键**，有源码扫描守着。

**`role` 与 `tier` 是两条正交的轴**：`Entitlement.isOwner()` 是全站唯一回答
「谁能进管理后台」的函数，落在 `poem_owner_v1` 上 —— 首次打开的这个浏览器
自动成为本机主人（否则 `/admin/` 永远对所有人关着）。所以「管理员不是买了 Max 的人」：
`role: owner` 的同时 `tier` 仍是 `free`。

⚠️ 与层级同理：本机那一份是**本机登记**，手改存储就能绕过。
**2.2 之后「谁来拦人」这件事有答案了**：真正拦人的是服务端
（`accounts.role`，`POST /api/admin/grant` 对有会话但没权限的请求如实回 **403**）。
入口藏不藏只影响体验，不影响权限。

**层级现在由服务端判定**（`accounts.plan` → `/api/me` 下发），
`/admin/` 上的**服务端名单**才是权威；**本机名单**降级为
「没配服务端 / 连不上」时的兜底，界面上明写**它不是权威**，
两份**不自动同步**（本机名单那条「要对方自己导入」的局限仍然成立）。

> 管理页的逻辑文件叫 `js/admin-page.js`，**不叫** `js/admin.js` ——
> 那个名字归早年已被整体删除的「访问统计」脚本，`test/legal.test.js`
> 有一条反向断言守着它必须不存在。

### 层级对比页：/plans/（已落地）

个人中心的「权限」一节是**只讲你自己**那一列。要看「四种身份各是什么样」，
去 `/plans/` —— 最左一列是对比项，右边四列是**未登录 / Free / Pro / Max**，
逐条打钩打叉，表尾给出每列能用的项数。

三条要紧的：

- **这张表不许手抄**：每一格都由 `Entitlement.compare()` 当场问 `can()` 算出来，
  与个人中心的清单同源。手抄一份的下场是内核改了门槛、这张表还是老话 ——
  而这张表恰恰是用户唯一会逐条对着看的页面（测试里逐格比一遍，不一致就红）
- **未登录 ≠ Free，且只差三条**：差的是「语音朗读」「进度导出」「莱特纳盒」
  都要登录（`minTier: free` + `login: true` 那一档）。单独给它一列，是因为不这么摆的话，
  用户会把「游客不能听 / 不能导 / 只能用遗忘曲线」读成「免费版也不行」
- **绿色那颗勾是一枚 SVG，不是字体里的 ✓**：
  `✓` 是各家字体的自由发挥、笔形带手写的歪劲，用户点名要「很正的 √」。
  现在按坐标落线（`js/plans.js` 的 `CHECK_PATH`，`plans/index.html` 的图例
  引用同一条路径），与字号 / 字体无关，任何机器上都是同一个形状
- **诚实口径**：页面上不出现任何促销话术，也没有收款入口；
  「层级是谁定的」不在这一页解释 —— 说了三遍等于没说（最后那张说明卡也撤了）。
  这一页一个字节都不写存储 —— 看表不该留下痕迹

手机上四列表会挤，所以表**横向可滚**，但**第一列（对比项）粘在左边不跟着滚** ——
滚到第三列还得知道自己在看哪一行。平板上表跟着正文列一起放宽，不再需要滚动。

`test/plans-page.test.js`（105 条）守着「每格 === `can()`」「层级单调不回退」
「表尾与表身相符」「不出现收款话术」「页面不自己拼 tier」这几条。

### 权益分层：free / pro / max（本机版，已接入）

`js/entitlement.js` 是**全站唯一回答「这个用户能不能用这个功能」的地方**
（`Entitlement.can(cap)`）。页面里不许自己比 `plan` / `tier`，有源码扫描测试守住 ——
将来层级改成服务端 `/api/me` 下发时，只换这一个实现，页面一行不用动。

三条已经定下的规矩：

- **免费不残缺**：今天能用的功能一件都不收回（261 首课内 + 2320 篇集子 + 排程 +
  注音 + 导出）；pro / max 只**加**新能力与额度
- **要登录的三件（免费档）**：**语音播放**、**进度导出**与**莱特纳盒**。
  未登录（游客）不能听、不能导、只能用遗忘曲线，登录后的 free 一键不少。两道门都只设在**唯一出口**上 ——
  声音在 `js/speech.js`、导出在 `js/settings.js` 的 `#btn-export` ——
  按钮照旧看得见、点得到，点下去得到的是 `denyReason()` 那句「登录可用」
  （隐藏按钮就成了「点了没反应」）
  - 语音：按钮的置灰状态与门同源，不会出现「按钮亮着却没声音」；
    放行之后**停止 / 暂停 / 下一首一律不受门限制**
    （否则会出现「听到一半被拦下，声音停不掉」）
  - 进度导出：改的是 `export.progress` 那一行（`login: true`），
    改台账要**同时改 `api/_lib/core.js` 的 `featuresFor()`**（两端同源）
- **复习算法也按层级开放**（用户口径）：**游客**只有遗忘曲线，
  **Free** 加莱特纳盒，**Pro** 加 SM-2，**Max** 四套齐备（含 FSRS）。
  台账是 `CAPS` 里那四条 `algo.*`（键名 = `"algo." + ReviewModels 里的 key`），
  核心里由 `ReviewModels.allowedKey()` 统一回落 —— **降级 / 退出登录之后不会
  接着用已经没权的那张**，而是从高往低退到当前身份能用的那一张
  （Max 选了 FSRS → 退出登录 → 排期落在遗忘曲线上）。
  设置页那四张卡**永远都在**（看得见才知道有这一档），不够层的只是淡一点、
  右下角写着门槛（「登录可用」/「Pro 起」/「Max 起」），点下去得到同一句话 ——
  与语音朗读 / 进度导出同一条规矩：**藏起来就成了「点了没反应」**
- pro / max 目前覆盖：跨设备云同步、PDF 与打印页、全站课内诗词导出（261 首）、
  **题库（Pro）**、**飞花令 · 古诗词大会集子 · 试题模拟（Max）**、
  子用户（Free 1 / Pro 3 / Max 180）
- ⚠️ **跨设备云同步那道门是「两处都在」**：界面层（`js/sync-store.js`）说清
  「Pro 起可用」，服务端（`/api/sync/push`、`/api/sync/pull`）回 **403 `E_TIER`**。
  只做界面层等于没拦（藏入口不是安全边界），只做服务端会出现
  「点开开关、看着开启中、其实一条都传不上去」的静默失败。
  **关掉同步不过这道门**：层级过期之后仍然关得掉（否则「一直在传、关不掉」）
- ⚠️ **没有 AI 讲解 / 背诵纠音**：那是「每调一次真花钱」的功能，
  用户 2026-09-17 明确不做（`docs/architecture.md` §5.0 ③）

⚠️ 本期这三层是**本机演示版分层**：管理员按邮箱掩码发层级、名单可导出粘贴，
对方改存储就能升级 —— 所以它**不是收费凭据**，也**不是安全边界**。
真正的权益判定要等服务端（`docs/auth-design.md` §3.5 已写明口径）。

`role`（owner / admin / user，谁能管理）与 `tier`（free / pro / max，能用什么）
是**两条正交的轴**：店长不是 VIP。

### 头像：用户名首字，也可以传一张图（已落地）

两档，没有第三档：

- **没传图** → 用户名的第一个字母 / 汉字（英文取首字母并大写）；昵称为空才回落到「诗」
- **传了图** → 那张图。选文件 → **本地压缩 + 方形裁切**（拖动、双指捏合 / 滑杆缩放）
  → 上传到 Supabase Storage

**压缩与裁切全在这台设备上做**（`js/avatar-image.js` 画进离屏 canvas，
压成 256×256 的 JPEG；原图带透明则存 PNG）—— 一个字节都不出去，直到最后那一次上传。
上传走 `POST /api/avatar`，**请求体是裸字节**（不是 JSON + base64），
服务端**按 magic number 判类型**（不看客户端声明的 Content-Type）。

盘上分两处，这一分不是洁癖：

| 键 | 域 | 存什么 |
|---|---|---|
| `poem_profile_v1` | 账号域 | 图片**地址**（跟着同步与导出走 —— 换台设备也该看到同一张脸）|
| `poem_avatar_local_v1` | 设备域 | 那张图的**字节**（离线时画的是它；**不进导出**）|

一句话：**地址属身份，字节属可用性**。几十 KB 的 base64 混进同步载荷，
每一条进度记录推一次就是几十 KB × 篇数；而且**它是全站唯一一处「体积太大、
上不了普通的同步通道」**的数据 —— 所以它走的是 Storage 桶那条路，不是
progress 表（见 `docs/architecture.md` §4.33）。

**新设备上头像会回来**：`GET /api/me` 带上图片的公开地址，客户端在
账号域还空着时把它写回去（`js/account-api.js` 的 `adoptAvatar()`）——
不写的话换台设备头像就退回昵称首字，用户会以为「头像没同步」。

**上一版那套「固定 12 字 + 固定四色」的字符印整块删了**（用户 2026-09-19 原话：
「头像印记设置和传统用户头像流程不符，让人困惑」）。教训不是「做得不好」，
是**自造的流程就是困惑本身** —— 要改的是条款，不是功能。
`/privacy/` 已经如实补上「自己传的那张图会存到服务器，别用真人照片」。

布局上：**头像永远在最右**（身份锚点，落点不能变），返回键在它左边（落点本就会变）；
**阅读器里不画头像**（全屏沉浸，身份入口不压在正文上）。
顶栏那一枚与左上角 logo 徽标**同径 42px、整圆**（用户要求「和 logo 一模一样大小的圆形」）
—— 尺寸只有一个来源（CSS 的 `--user-size`），`js/chrome.js` 不再自己传一个数字。
点击落点是 `/profile/`。

### 存储分域：进度 / 账号 / 设备

数据不是「都存在本机」一句话能说清的：**哪些该跟着人走、哪些只属于这台设备**，
以前散在各页面读写点的默契里。现在收在 `js/progress-store.js` 一份清单里，
`js/storage.js` 只是它的**薄转发层**（对外签名一个都没改，所以调用点一行没动）。

| 域 | 键 | 跨设备 |
|---|---|---|
| 进度域 | `poem_recite_progress_v1` | ✅ |
| 账号域 | `poem_recite_settings_v1`（年级 / 学期 / 范围 / 每日数量 / 算法）、`poem_profile_v1`（昵称 + 印）、`poem_recite_collections_v1`（自选集合） | ✅ |
| 设备域 | `poem_device_prefs_v1`（注音总开关）、字号、对齐、连读档、播放模式、iOS 引导条、搜索框里那个词 | ❌ |
| 已读域 | 各部集子各一把 `poem_*_read_v1` | ✅ |
| 临时域 | `poem_daily_extra_v1`（今日加背，只属于当天） | ✅（按天并集）|
| 勘误域 | `poem_pinyin_fix_v1`（注音勘误：某篇某句某字读什么） | ✅（谁最后改谁赢）|

口径一句话：**「这个账号学到哪」上云，「这台设备长什么样」不上云。**
逐把键的判定（含云端行号、合并规则、体积上界）收在 `js/sync-coverage.js`
一张运行时表里，`test/sync-coverage.test.js` 会拿源码扫描本仓库所有
`poem_*` 字面量来对表 —— 漏一把就红（详见 `docs/architecture.md` §4.33）。

**注音总开关属于设备域** —— 手机上开了阅读辅助，不该让电脑也满屏拼音。
集子页与设置页仍从老设置对象里读它，所以写的时候**两把键一起写**
（新键是正主、老键里那份是镜像），避免「首页说已开启、集子页是纯文本」。

三条**不许变**的盘上形状：进度域仍是 `{id: rec}` 平铺（不包信封）、
六把已读键不合并不改名、清空进度**只清进度**（绝不动昵称与阅读偏好）。

**家庭子用户（多个孩子）就落在这一层上**：上面每一把「✅ 跨设备」的键
都**按孩子再分一层**（键名加 `::<子用户 id>` 后缀），设备域那把不带后缀 ——
于是「进度 / 年级 / 已读跟着孩子走，字号不跟」这条边界就是**一条规则**，
不是四处特判。拼法只在 `js/family.js` 的 `keyFor()` 一处
（同步层的记账表在 `js/sync-store.js` 的 `seenKey()`，那是它自己的簿记，
不在上面这张表里）。
