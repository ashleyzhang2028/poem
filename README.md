# 跬步 · 古诗词背诵

面向小朋友的**古诗文复习与背诵**应用。覆盖**小学一年级到高中三年级**（人教/统编版教材）共 **251 首**古诗文，首首配白话译文；另设独立的**小古文**学习库（102 篇）。

纯前端单页应用（PWA），**打开即用、无需注册、可离线**，所有学习进度默认只存在本机浏览器里。支持电脑、安卓手机、苹果手机（iPhone / iPad）。

> 应用正式名称为 **跬步**。填了用户名后标题显示为「跬步 · 小明的古诗词」。

## 功能

- **每日背诵任务**：自动列出今天要背的诗词（默认 5 首，可调 3 / 5 / 8 / 10 首），分「复习」与「新学」两类。
- **复习算法自动排期**：点开诗词后选择掌握程度（记住 / 模糊 / 忘记），系统自动算出下次复习时间。内置四套算法（遗忘曲线 / 莱特纳盒 / SM-2 / FSRS），设置页可切换，**换算法不清进度**。
- **背诵范围 6 选 1**：本册及之前 / 小学随机 / 初中随机 / 小初随机 / 高中随机 / 全部随机。
- **今日加背**：今日页顶上的输入框里搜到、点「＋」就行；集子页与搜索页的每一行、详情页也有同一颗。只属于今天，跨过 0 点自动归零。
- **进度可视化**：今日环形进度、单篇记忆阶段与掌握度；背诵进度总览 `/progress/` 在「我的」页与设置 · 背诵页各有一处入口。
- **自选背诵**：教材之外想额外背的篇目，可建多个集合、增删改查、导入导出（`/settings/lists/`）。
- **全站搜索 `/search/`**：一次搜遍全部集子，搜篇名 / 作者 / 朝代 / 出处，也搜正文与白话译文。
- **生字注音 / 注音勘误**：三档「不注音 / 生字 / 全文」；算错的读音可在管理后台**钉住**某一篇某一句，即刻生效，随账号同步。
- **自动朗读**：基于系统语音，零音频文件、断网可用。可读单篇、读当日全部、随机连读。
- **古诗词大会**（`/poems/` 上就地铺开）：**飞花令**（Max）、**试题模拟**（Max）、**题库复习**（Pro）。判分不花钱也不接 AI，用的是仓库里的同一个出题内核（`js/quiz.js`）。
- **报告错误 / 勘误**：篇目页那颗**小旗**能报错字 / 注音 / 译文 / 朗读 / 界面问题，报告送到服务端台账，管理员在 `/admin/` 处理，自己报过的在「关于 → 我的报告」里看进度。
- **PWA 离线**：安装到桌面后可离线背诵，首次打开需联网加载一次。

层级口径（用户 2026-09-17 的裁决）：**「现场考试和飞花令归 max 所有，题库归 pro.」** 设计与实现见 `docs/architecture.md` §4.15。

## 使用方法

用浏览器打开根目录的 `index.html`，或起本地服务（建议，避免个别浏览器 `file://` 限制）：

```bash
npm run dev:auth             # 静态页面与 /api/* 同源，调试登录 / 注册时用这个
python3 -m http.server 8080  # 只提供静态页面，不提供账号 API
# 然后访问 http://localhost:8080
```

未提供 Supabase 或发信环境变量时，`dev:auth` 使用进程内存储与 console 发信：重启后账号数据清空，也不会真发邮件。

服务器需支持「目录索引」：所有地址都是目录形式，不带 `.html`（根 `/` → `index.html`，`/classic/` → `classic/index.html`），Nginx / GitHub Pages / CNB Pages 无需额外配置。

**手机上使用**：

- **苹果 / iPad**：Safari 打开 → 「分享」→「添加到主屏幕」。微信等内置浏览器不支持安装，应用会提示改用 Safari。
- **安卓**：Chrome / Edge 打开，浏览器会提示「安装应用」。
- **电脑**：浏览器直接打开，或点地址栏右侧安装图标装成独立窗口应用。

## 扩展数据

在 `data/poems-N.js` 中按以下结构追加即可，`id` 需唯一：

```js
{
  id: "xx1-13",
  title: "诗题",
  author: "作者",
  dynasty: "唐",
  grade: 1,      // 1-12
  term: 1,       // 1 上学期 / 2 下学期
  text: "第一句，\n第二句。",
  translation: "白话译文，必填 —— 全库 251 首目前 100% 齐备。",
  translationSource: "school"   // 译文口径，四类取值见下
}
```

各选集（`data/poems-classic.js` / `-tangshi.js` / `-songci.js` / `-guwen.js` / `-zhaoming.js`）结构相同，只是分组字段换成 `gradeGroup`（分类 / 卷次 / 词牌 / 文体）。

**译文是必填项**，且须标注来源口径（`translationSource`）。译文为本项目**自拟的白话直译**，不逐字搬用任何一家译本；四类取值：`school`（统编版教材与教师用书）、`academic`（《唐诗鉴赏辞典》等工具书）、`public-domain`（公有领域原文的公认注本）、`modern`（现行通用选本）。

加完新篇目后跑一遍：

```bash
node scripts/audit-translations.js             # 逐首体检：缺译文 / 过短 / 抄原文 / 来源标注
node scripts/tag-translation-source.js --dry   # 看新篇目的来源标注
node scripts/tag-translation-source.js         # 补上（幂等，只补缺的）
python3 scripts/supplement-fonts.py            # 新译文带来的新字补进字体子集
node test/run.sh                               # 测试
```

新增译文往往带来字体里没有的字，不补字体那些字会缺笔画（表现为字被吃掉半边）。

## Service Worker 约定

`sw.js` 三条硬约定：

1. **`sw.js` 里不写任何注释**：顶部注释块漏一个 `*/` 就会让整份文件解析失败、Service Worker 从不注册、离线能力静默失效。
2. **静态资源是「缓存优先」**：只要动了 `css/` 或 `js/` 里的文件，就必须把 `CACHE_NAME` 的版本号 +1，否则老用户会一直拿着旧副本。同时有几个 PR 在改时，每个 PR +5，避免撞号。
3. **`/api/*` 一律早退**，不缓存也不由 SW 应答 —— 缓存它等于「换个人打开还是上一个人的会话」。

## 数据与隐私

- 学习进度与用户名**默认只存在本机浏览器**（localStorage），不建账号就一行数据都不往外发。
- **不注册也能用全部功能**；可自愿用**邮箱 + 密码**注册，也可以不记密码、每次用邮箱收一串**随机码**登录（两条路签发的是同一枚会话）。注册后需**点开确认邮件里的链接**才能登录。
- 账号域数据（背诵档案、年级学期、背诵范围、昵称）会上传到服务器以便跨设备同步，**设备偏好（字号 / 对齐 / 注音开关 / 连读档）不上云**；可在「我的」页关掉同步退回只存本机，注销即删除服务器上的数据。
- **邮箱会保存到服务器**（登录与找回密码要用它）；**密码不存明文** —— 库里只有一段加盐的单向摘要（scrypt），忘记时走「忘记密码」重设。这些在 `/privacy/` 里逐条写明（**条款跟随代码**）。
- **邮箱不掩码**：库里、界面上、报文里都是明文（掩码那一列 2026-09-25 整块撤掉）。「我的」页默认只写「已登录」，点一下**「我的邮箱」**才把那串真邮箱显示出来 —— 那是本机的临时显示状态，不落库、不参与同步。
- 无统计脚本、无广告，断网可用；想手动搬数据，设置里有「导出备份 / 导入备份」；联系邮箱不以明文出现在源码里，由 `js/contact.js` 运行时拼装，防爬虫抓取。

## 服务端

Vercel Serverless，同源、无 CORS。**线上只有 1 个函数**：`api/handler.js` 按 `api/_lib/routes.js` 那张唯一的路由表把请求交给 `api/_routes/` 里对应的实现（Vercel Hobby 档一个部署最多 12 个函数，所以必须收口）；`vercel.json` 里一条 rewrite 把外部地址与原路径接进去。业务内核全在 `api/_lib/core.js`，能在 Node 里直接测。

主要接口：`/api/me`（权益的唯一来源）、`/api/send-code` 与 `/api/verify-code`（随机码登录）、`/api/register` `/api/login` `/api/verify-email` `/api/reset-*`（完整登录流程）、`/api/sync/pull|push`（跨设备同步）、`/api/avatar`（头像）、`/api/report`（用户报告）、`/api/admin/grant|accounts|role|reports`（管理后台）、`/api/diag`（自助排查，只回形状不回值）。完整台账见 `docs/architecture.md` §4.3。

**四条硬规矩**：明文验证码不进任何日志；权益只从 `/api/me` 来，请求体里的 `plan` 一律忽略；所有写接口都有频控；能改别人数据的接口有服务端角色闸（`403`）—— 把入口藏起来**不是**安全边界。

**登录状态只有一个答案**：会话有两种存在方式 —— 服务端的 `kbsid` Cookie（口令 / 真邮件验证码 / 点确认链接 / 重设这四条路签的都是它）与本机的 `poem_auth_v1.sessions`（云端用不了时前端自己发码的那条降级路）。界面上**每一处**「登录了没」都问同一个出口 `Entitlement.identity()` / `cookieSession()`，没有本机会话时就认「服务端刚认过这个人」那份答案（`poem_plan_v1` 里 `source:"server"` 的那一份）。`js/chrome.js` 在顶栏就位时问一次 `/api/me`，答案一到就喊 `account:ready` —— 于是**从首页到设置，一个判据、一个答案**。退出登录走两半：`POST /api/logout` 撤服务端那枚会话，`AuthCore.signOut()` 清本机那份。

部署与建表见 `api/_lib/schema.sql`。开通只差几个环境变量，做成可执行的：

```bash
npm run doctor             # 缺哪个、缺了会怎样、怎么补（退出码 = 体检结论）
npm run doctor -- --steps  # 六步怎么补：配 Supabase / 发信商 / Turnstile / 探活 / 验收
npm run env:example > .env.example
```

| 步 | 做什么 | 判据 |
|---|---|---|
| **C** | 注册 **Resend**（主选）→ 建 key → 验发信子域 + SPF/DKIM/DMARC 三条 DNS | 自检里发信通道不再是 `console`；真发一封信 `delivered:true` |

**一个都不配也照样能完全离线使用** —— 自检把这句话写在报告里，免得「未配置」被读成「坏掉」。报告里**只出现变量名、绝不出现值**（连长度都不报）。

## 权益分层：free / pro / max

`js/entitlement.js` 是全站唯一回答「这个用户能不能用这个功能」的地方（`Entitlement.can(cap)`），页面里不许自己比 `plan` / `tier`（有源码扫描守着）。层级由**服务端判定**（`accounts.plan` → `/api/me` 下发），`/admin/` 上的服务端名单才是权威，本机那把键只是**服务端答案的缓存**（离线也能按上次的层级放行）。

`role`（owner / admin / user，谁能管理）与 `tier`（free / pro / max，能用什么）是**两条正交的轴**：管理员不是买了 Max 的人。

三条规矩：

- **免费不残缺**：今天能用的功能一件都不收回；pro / max 只**加**新能力与额度。
- **要登录的三件（免费档）**：语音播放、进度导出、莱特纳盒。按钮照旧可见，点下去得到「登录可用」那句 —— 隐藏按钮就成了「点了没反应」。
- **每道门都在服务端**：跨设备云同步在界面层与服务端（`403 E_TIER`）两处都拦 —— 只做界面层等于没拦。

管理员诞生三步（全在数据库侧）：配 `OWNER_EMAILS` 后用它登录一次 → 在 `/admin/` 给他人改角色（只有 owner 改得动、改不了自己、改不了种子主人）→ 或直接在 Supabase 改 `accounts.role`。**不配 `OWNER_EMAILS` 时一个 owner 都没有**，`/admin/` 对所有人如实关门。

⚠️ `role` 与 `tier` 之外的口径（存储分域、跨设备同步的合并规则、界面拆分、版式细节等）都在 `docs/architecture.md` 与 `docs/auth-design.md`；「现在不做、以后做」的条目只在 `docs/todo.md` —— 那是唯一一处，别把「以后做」读成「快好了」。
