# 跬步 · 古诗词背诵

面向小朋友的**古诗文复习与背诵**应用。覆盖**小学一年级到高中三年级**（人教/统编版教材）共 **251 首**古诗文，首首配白话译文；另设独立的**小古文**学习库（102 篇）。

纯前端 PWA，**打开即用、无需注册、可离线**；进度默认只存本机。支持桌面与手机。

> 填了用户名后标题显示为「跬步 · 小明的古诗词」。Pro / Max 可建**家庭子用户**（一个孩子一条名册），切到谁，首页标题、顶栏 / 底栏头像与「我的」页身份行都跟着换那一个。

每一部集子的列表页**顶上摆一张索引卡**（课内诗词、乐府集、古文观止……都一样）：按各自的分类（年级册 / 卷次 / 词牌 / 文体 / 朝代）摊成一格一格，左名右数，手机竖屏一行两列。点一格**就地滚到那一段**并给一道短促高亮 —— 例如课内诗词点「五年级上 11 首」直接落到五年级上那一段。分类特别多的集子（宋词按词牌 147 段、文选按文体 91 段）默认先折起头 6 行，卡头一颗「展开」放全表。搜索或「未读」筛选时索引自动收起（筛出来的是零头，对不上整段）。

## 功能

- **每日背诵任务**：自动列出今天要背的诗词（默认 5 首，可调 3 / 5 / 8 / 10 首），分「复习」与「新学」两类。
- **复习算法自动排期**：点开诗词后选择掌握程度（记住 / 模糊 / 忘记），系统自动算出下次复习时间。内置四套算法（遗忘曲线 / 莱特纳盒 / SM-2 / FSRS），设置页可切换，**换算法不清进度**。
- **背诵范围 6 选 1**：本册及之前 / 小学随机 / 初中随机 / 小初随机 / 高中随机 / 全部随机。
- **今日加背**：今日页顶上的输入框里搜到、点「＋」就行；集子页与搜索页的每一行、详情页也有同一颗。只属于今天，跨过 0 点自动归零。
- **进度可视化**：今日环形进度、单篇记忆阶段与掌握度；背诵进度总览 `/progress/` 在「我的」页与设置 · 背诵页各有一处入口。
- **自选背诵**：教材之外想额外背的篇目，可建多个集合、增删改查、导入导出（`/settings/lists/`）。
- **全站搜索 `/search/`**：一次搜遍全部集子，搜篇名 / 作者 / 朝代 / 出处，也搜正文与白话译文。
- **生字注音 / 注音勘误**：三档「不注音 / 生字 / 全文」；算错的读音可在管理后台**钉住**某一篇某一句预览，提交后经管理员审核批准即对全站生效。
- **自动朗读**：基于系统语音，零音频文件、断网可用。可读单篇、读当日全部、随机连读。
- **古诗词大会**（自成一页 `/dahui/`，**就是飞花令与考试这一页，不是一部集子**）：**飞花令**（Max）、**题库**（Pro）、**模拟考试**（Max）、**考试**（Max）。每一张题型卡各算各的门槛，页面上没有「集子」这层概念 —— 集子归 `/library/`。卷面 = 范围（全部 / 单部集子 / 小学·初中·高中）× 形态 × 题量：模拟逐题给对错、考试交卷后统一批且限时 20 分钟。判分不花钱也不接 AI，用的是仓库里的同一个出题内核（`js/quiz.js`）；范围名单从全站集子自己算，加一部集子就多一个范围。答题有**音效**：答对、答错、闯关过关、交卷出分各一种（Web Audio 现场合成，零音频文件、离线可用），可在「设置 · 阅读与朗读」里关掉，旁边那颗「试听一声」当场验这台设备出不出声。
- **报告错误 / 勘误**：篇目页那颗**小旗**能报错字 / 注音 / 译文 / 朗读 / 界面问题，报告送到服务端台账，管理员在 `/admin/` 处理，自己报过的在「关于 → 我的报告」里看进度。
- **意见反馈**：「我的 → 更多 → 意见反馈」可提交产品建议或使用问题，未登录也能发（按设备号认人）；可来回跟帖，管理员回复后能看到，自己发的内容能删（含跟帖），删不掉管理员回的那些。
- **PWA 离线**：安装到桌面后可离线背诵，首次打开需联网加载一次。

层级口径（用户 2026-09-17 的裁决）：**「现场考试和飞花令归 max 所有，题库归 pro.」** 设计与实现见 `docs/architecture.md` §4.15；考试层的卷面三要素（范围 × 形态 × 题量）与四级门槛见 §4.66。

## 使用方法

用浏览器打开根目录的 `index.html`，或起本地服务（建议，避免个别浏览器 `file://` 限制）：

```bash
npm run dev:auth             # 静态页面与 /api/* 同源，调试登录 / 注册时用这个
python3 -m http.server 8080  # 只提供静态页面，不提供账号 API
# 然后访问 http://localhost:8080
```

未提供 Supabase 或发信环境变量时，`dev:auth` 使用进程内存储与 console 发信：重启后账号数据清空，也不会真发邮件。

服务器需支持目录索引：地址都是目录形式（`/classic/` → `classic/index.html`），Nginx / GitHub Pages / CNB Pages 无需额外配置。

**手机上使用**：

- **苹果 / iPad**：Safari 打开 → 「分享」→「添加到主屏幕」。微信等内置浏览器不支持安装，应用会提示改用 Safari。
- **安卓**：Chrome / Edge 打开，浏览器会提示「安装应用」。
- **电脑**：浏览器直接打开，或点地址栏右侧安装图标装成独立窗口应用。

## 扩展数据

在 `data/poems-N.js` 中按以下结构追加即可，`id` 需唯一：

```js
{
  id: "xx1-13",
  title: "诗题",
  author: "作者",
  dynasty: "唐",
  grade: 1,      // 1-12
  term: 1,       // 1 上学期 / 2 下学期
  text: "第一句，\n第二句。",
  translation: "白话译文，必填 —— 全库 251 首目前 100% 齐备。",
  translationSource: "school"   // 译文口径，四类取值见下
}
```

各选集（`data/poems-classic.js` / `-tangshi.js` / `-songci.js` / `-guwen.js` / `-zhaoming.js`）结构相同，只是分组字段换成 `gradeGroup`（分类 / 卷次 / 词牌 / 文体）。

**译文是必填项**，须标注来源口径（`translationSource`），四类取值：`school`（统编版教材与教师用书）、`academic`（《唐诗鉴赏辞典》等工具书）、`public-domain`（公有领域公认注本）、`modern`（现行通用选本）。

**译文底下那行注脚只说口径**。主表另给每条正文算了**版次**（`data/text-master.js` 的 `version`），供本机快照比对；**版次不上界面**（见 `docs/architecture.md` §4.72）。

加完新篇目后跑一遍：

```bash
node scripts/audit-translations.js             # 逐首体检：缺译文 / 过短 / 抄原文 / 来源标注
node scripts/tag-translation-source.js --dry   # 看新篇目的来源标注
node scripts/tag-translation-source.js         # 补上（幂等，只补缺的）
python3 scripts/supplement-fonts.py            # 新译文带来的新字补进字体子集
node test/run.sh                               # 测试
```

新译文常带来字体里没有的字，不补会缺笔画。

## 详情页里的表格

**正文是纯文本**（`data/text-master.js` 的 `text` 字段），表格也因此写成纯文本，由阅读器（`js/reader-core.js`）认出来渲染成真 `<table>`。作者在正文里照下面两种样子画就行：

```
┌──────┬────────┐        有框表：画了框线的，整块连续的行 = 一张表。
│ 年号 │ 帝王   │        首行是表头；├ ┤ / └ ┘ 那几行只作分隔。
├──────┼────────┤
│ 建元 │ 汉武帝 │
└──────┴────────┘

年号 ｜ 帝王         无框对齐表：两列以上、连着两行以上、行行竖线数相同
──── ｜ ────         = 一张表。首行下面跟一条横线分隔线时，首行当表头。
建元 ｜ 汉武帝
```

全角「｜」与半角「|」都认，一张表里只许用同一种。**认不出来一律原样输出**。

表格样式**全站只有一处**：`css/reader-tables.css`。长表窄屏可横滑。

长表不要手打 —— 竖线少一根整段就会退回纯文本。用 `scripts/lib/table.js` 的 `box()` / `grid()` 生成，可用 `ReaderEngine.tableIssues()` 逐条过。文学常识那十一张表即由此来（`node scripts/changshi-tables.js`）。

**表格按比例分宽**（`width: 100%`），但有一格长过 80 个半角字符（或超过两列）时**不按比例** —— 整表改成按列宽排版、窄屏横滑（`.rd-width-locked`）。不锁的话「写作背景」这类一整段话会被压成一条竖线，表还在、句子读不成。名著导读与历代名家两张表即属此类。

## Service Worker 约定

`sw.js` 三条硬约定：

1. **`sw.js` 里不写任何注释**：顶部注释块漏一个 `*/` 就会让整份文件解析失败、Service Worker 从不注册、离线能力静默失效。
2. **静态资源是「缓存优先」**：只要动了 `css/` 或 `js/` 里的文件，就必须把 `CACHE_NAME` 的版本号 +1，否则老用户会一直拿着旧副本。同时有几个 PR 在改时，每个 PR +5，避免撞号。
3. **`/api/*` 一律早退**，不缓存也不由 SW 应答 —— 缓存它等于「换个人打开还是上一个人的会话」。

缓存版本号不是随手写一个，**要压过当前 main 才算数**（`git fetch` 后照着来）：

```bash
highest=$(git grep -h -o -E 'poem-app-v[0-9]+' origin/main -- sw.js | grep -o -E '[0-9]+' | sort -n | tail -1)
next=$((highest + 5))
sed -i '' -E "s/poem-app-v[0-9]+/poem-app-v$next/" sw.js
grep -n 'CACHE_NAME' sw.js
```

只肯猜一个数、又没落地的，合并时会与 main 上已发布的版本撞号（`sw.js` 那行必然冲突）。

## 数据与隐私

- 学习进度与用户名**默认只存在本机**（localStorage），不建账号就一行数据都不往外发。
- **不注册也能用全部功能**；可自愿用**邮箱 + 密码**或**随机码**登录，两条路签发同一枚会话。注册后需点开确认邮件里的链接。
- 账号域数据（背诵档案、年级学期、范围、昵称）上云以便跨设备同步，**设备偏好不上云**；可在「我的」页关掉同步，注销即删服务器数据。
- **邮箱会存到服务器**；**密码不存明文**（库里只有加盐的 scrypt 摘要），忘记时走「忘记密码」重设。逐条见 `/privacy/`。
- **邮箱不掩码**，库里 / 界面上 / 报文里都是明文。「我的」页默认只写「已登录」，点**「我的邮箱」**才显示真邮箱；那是本机临时状态，不落库、不同步。
- 无统计脚本、无广告，断网可用；设置里有「导出 / 导入备份」；联系邮箱由 `js/contact.js` 运行时拼装，防抓取。

## 服务端

Vercel Serverless，同源、无 CORS。**线上只有 1 个函数**：`api/handler.js` 按 `api/_lib/routes.js` 的路由表派给 `api/_routes/`（Hobby 档上限 12 个函数，故必须收口）；`vercel.json` 一条 rewrite 接外部地址。业务内核在 `api/_lib/core.js`。

主要接口：`/api/me`（权益的唯一来源）、`/api/send-code` 与 `/api/verify-code`（随机码登录）、`/api/register` `/api/login` `/api/verify-email` `/api/reset-*`（完整登录流程）、`/api/sync/pull|push`（跨设备同步）、`/api/avatar`（头像）、`/api/report`（用户报告）、`/api/admin/grant|accounts|role|reports|pinyin|feedback`（管理后台）、`/api/pinyin-fixes`（全站生效的注音勘误，公开只读）、`/api/feedback`（意见反馈，登录与设备号访客都能用）、`/api/diag`（自助排查，只回形状不回值）。完整台账见 `docs/architecture.md` §4.3。

**四条硬规矩**：明文验证码不进日志；权益只从 `/api/me` 来，请求体里的 `plan` 一律忽略；写接口都有频控；改别人数据的接口有服务端角色闸（`403`）。

**登录状态只有一个答案**：会话有两种存在方式 —— 服务端的 `kbsid` Cookie 与本机的 `poem_auth_v1.sessions`（云端不可用时的降级路）。界面上每一处「登录了没」都问同一个出口 `Entitlement.identity()` / `cookieSession()`。`js/chrome.js` 在顶栏就位时问一次 `/api/me`，答案一到就喊 `account:ready`。退出走两半：`POST /api/logout` 撤服务端会话，`AuthCore.signOut()` 清本机那份。

部署与建表见 `api/_lib/schema.sql`。开通只差几个环境变量，做成可执行的：

```bash
npm run doctor             # 缺哪个、缺了会怎样、怎么补（退出码 = 体检结论）
npm run doctor -- --steps  # 六步怎么补：配 Supabase / 发信商 / Turnstile / 探活 / 验收
npm run env:example > .env.example
```

| 步 | 做什么 | 判据 |
|---|---|---|
| **C** | 注册 **Resend**（主选）→ 建 key → 验发信子域 + SPF/DKIM/DMARC 三条 DNS | 自检里发信通道不再是 `console`；真发一封信 `delivered:true` |

**一个都不配也照样能完全离线使用**。自检报告里**只出现变量名，绝不出现值**。

## 权益分层：free / pro / max

`js/entitlement.js` 是全站唯一回答「能不能用这个功能」的地方（`Entitlement.can(cap)`），页面里不许自己比 `plan` / `tier`。层级由**服务端判定**（`accounts.plan` → `/api/me`），本机那把键只是服务端答案的缓存。

`role`（owner / admin / user，谁能管理）与 `tier`（free / pro / max，能用什么）是**两条正交的轴**：管理员不是买了 Max 的人。

三条规矩：

- **免费不残缺**：现有功能不收回；pro / max 只**加**新能力与额度。
- **要登录的三件（免费档）**：语音播放、进度导出、莱特纳盒。按钮可见，点下去得到「登录可用」。
- **每道门都在服务端**：云同步在界面层与服务端（`403 E_TIER`）两处都拦。

管理员诞生：配 `OWNER_EMAILS` 后用它登录一次 → 在 `/admin/` 给他人改角色（只有 owner 改得动，改不了自己与种子主人）→ 或在 Supabase 改 `accounts.role`。**不配 `OWNER_EMAILS` 时一个 owner 都没有**，`/admin/` 如实关门。
