# 跬步 · 古诗词背诵

面向小朋友的**古诗文复习与背诵**应用。覆盖**小学一年级到高中三年级**（人教/统编版教材）共 **261 首**古诗文，**首首配白话译文**（自拟直译，逐首标注来源口径）；
另设独立的**小古文**学习库（100 篇，想读哪篇点哪篇，可注音、朗读、随机连读）。

> 应用正式名称为 **跬步**（kuibu.app）。填了用户名后标题显示为「跬步 · 小明的古诗词」。

纯前端单页应用（PWA），**打开即用、无需注册、可离线**，所有学习进度保存在手机/电脑本机浏览器里。

支持**电脑、安卓手机、苹果手机（iPhone / iPad）**；苹果手机上可通过 Safari「添加到主屏幕」当独立 App 使用。

`/xxx/` 页面里，统一从课外阅读入口页 `/library/` 进；

`poem_tangshi_read_v1` / `poem_songci_read_v1` / `poem_guwen_read_v1` /
`poem_zhaoming_read_v1`），字号与对齐则是全站共用的一份阅读偏好。

为什么小古文要单独一套：
- **篇幅长**：小古文动辄上百字，手机上卡片式弹窗装不下，所以阅读改成**整页阅读器**，可以一路滚下去
- **排版需要**：古诗词短，卡片弹窗就能读完；小古文动辄上百字，只有整页阅读器才装得下，与「要不要背」无关
- **不打扰主线**：小古文独立成页 `/classic/`，有自己的「已读」标记（与古诗词进度互不干扰），不会占用每日 5 首任务的名额

数据字段统一为：`id / title / source / dynasty / author / gradeGroup / text /
excerpt / translation / translationSource`。

`source` 记的是这一篇**真正的出处**：《古文观止》里就是《左传》《国语》
《战国策》《史记》《震川先生集》《李太白集》这些成书之处，不是选本名。
「从哪本选里读到」另有 `selection` 字段（古文观止为《古文观止》），
列表里作为淡色括注、阅读器里作为淡色标签跟在出处后面 —— 选集不是出处，
两件事分开放，搜索两种说法都能命中。

- `excerpt` 是列表里显示的**名句摘句**：宋词、古文篇幅长，截正文前十几字往往
  认不出是哪一篇（开头多是交代性的成句），所以摘句由语料单独给出，没给就不显示
- 译文一律标来源口径（`public-domain`），依据公认注本与通行译注

#### 「其一 / 其二 / 其三」自拟编号：已全部撤销，改用首句副题

《宋词三百首》目录里同一词牌下的多首**本无序号**，编排次序在各本之间还有出入。
早前整理时按「目录先后」给它们标过一批「其一 / 其二 / 其三」，
那是**整理者自拟**的编号 —— 写成「其一」等于替选本定了一个它没有的篇次，
用户点开也看不出是哪一首（「木兰花·其二」反像漏了前半句）。

现有 20 条全部改为**首句副题**（副题就是本篇正文里的第一句，取到第一个逗号为止；
首个逗号前以问号收束的连下一句一并带上）：

| `sc-17` | 木兰花·其一 | 木兰花·**燕鸿过后莺归去** |
| `sc-19` | 木兰花·其三 | 木兰花·**池塘水绿风微暖** |
| `sc-28` | 蝶恋花·其一 | 蝶恋花·**庭院深深深几许？杨柳堆烟** |

（共 20 条，逐条清单在 `test/songci.test.js` 的 `SEQ_FIXED`）

副题是**从本篇正文里取的字**，不是补出来的信息 —— 全站只允许三种副题来源：

#### 「补出来的信息」一律留空

《昭明文选》480 篇里曾逐条填着 `dynasty`（东汉 / 西晋 / 南朝·宋……）。
这个朝代**不是《文选》里的东西** —— 诸家题署只给作者的字（「班孟坚」
「王文考」「孙兴公」），朝代是后人按人名表推出来的。用户给的规矩很干脆：

> 这类「补出来的信息」=> 一律留空

划线口径不是「拿文本去认朝代号」（「窦融」「张说」这类**两个字、其中一个字
也是朝代号**的人名会被误伤），而是看**题署与常用姓名是否同形**：

| 情形 | 例子 | 处理 |
|---|---|---|
| `author === authorName`：选本只给了作者的**字** | 班孟坚、王文考、孙兴公、徐陵、谢灵运 | 朝代**留空**（145 条） |
| `author !== authorName`：选本自己给了**本名 / 帝号 / 谥号** | 班固、张衡、王粲；「魏文帝」「汉武帝」「汉高祖」；贾长沙（贾谊）、荆卿（荆轲） | 朝代**照录**（335 条） |

顺手订正了三处「选本署字、却把字写成本名」的题署：`贾谊 → 贾长沙`、
`荆轲 → 荆卿`（两处同名的《歌》从此各按各的题署走：荆卿那条朝代留空、
汉高祖那条记西汉）。

**留空不是「显示不出来」**：查看器 / 列表 / 搜索 / 收藏四处都改成
「有哪栏排哪栏」，朝代一空只省掉它自己那一段，不渲染空标签、不留
「 · 徐陵」这种以分隔符开头的残句、不写「未知 / 不详」占位。
`test/zhaoming.test.js` 与 `test/search.test.js` 各守着这一条的两端
（数据里确实留空、页面上确实没有残句），`test/collections.test.js`
另守着「快照里也照旧留空」。

### 全站搜索（`/search/`）

一次搜遍六部集子：搜**篇名 / 作者 / 朝代 / 出处**，也搜**正文与白话译文** ——
记不住篇名的时候，往往只记得住一句话（搜「先天下之忧而忧」要能搜到《岳阳楼记》）。

- **页面上只有一条搜索框**，它的位置由用户在做什么决定（三态，一个函数算清）：
  - **居中**（默认）：没焦点、没内容 —— 框在标题栏下方垂直 + 水平居中，
    这一页只有它一个，进来第一眼就看见
  - **贴顶栏下方**（有焦点**或**有内容）：框挪到标题栏下方，候选下拉跟着上去；
    **有搜索内容时，失焦也仍停在页顶** —— 看完结果不必再等它滑回页面中间
  - **回到中心**：清空内容、且没有焦点时才回中间（用户原话：
    「如果用户清除搜索框内容且没有焦点在搜索框，搜索框则回到页面中心」）
  ⚠️ 「有焦点」与「有内容」合成**同一个类**（`.search-active`）：两者的落位
  一模一样，分成两个类就要把同一组数值写两遍。三种摆法只有一个出口
  （`js/search.js` 的 `syncHeroState()`）—— 聚焦 / 失焦 / 输入变化都调它，
  JS 不再往 hero 上写行内样式
- **搜索框比别处高（52px）**：这一页以搜索为主角，没有别的东西要跟它对齐，
  52px 也稳稳越过 iOS 上 44px 的最小可点面积。
  ⚠️ 52px 是**真实高度**（`--toolbar-h`），不是把 40px 的画布纵向拉长出来的 ——
  上一版用 `transform: scaleY(1.3)` 做「绘制层增高」，代价是 12px 的圆角被拉成
  椭圆角、placeholder 的字形被压扁。现在高度长在布局里，四个角是同一个半径的
  圆弧，提示字也不必再用位移去凑垂直居中
- **聚焦时的描边是天青，不是黑框**：用户看到的黑框其实不是我们写的任何一条样式，
  而是浏览器给 `<input>` 的默认 `focus ring`（UA 的 `outline`）。
  现在 `border-color` 落到天青（`--green`）、`outline: none` 关掉那条黑线，
  换成描边之外一圈极淡的天青光晕 —— 不挤占布局，也不像黑框那样生硬
- **进页即聚焦搜索框**：一进来就能打字、键盘应声弹出，少点一次
- **机上的三条硬要求**（用户反馈的「在机上的体验并不太好」）：
  - **键盘弹出时整块顶到键盘上方**：软键盘是盖在页面上的浮层、不改变窗口高度，
    搜索框又在视口居中处，一动键盘就被顶进键盘底下 —— 现在由
    `visualViewport` 实测键盘高度与可视区（`--kb-space` / `--kb-visible`），
    整块贴到顶栏下方，候选下拉据此限高，
    **永远整条落在键盘上方的可视区里**；键盘收起后自动回到居中。
    ⚠️ 贴顶那一条 `.search-hero.search-focus / .kb-open` 曾在 v60 被误删
    （改「52px 真高度」时整条带走），而 JS 仍加类、测试仍量它 ——
    v66 恢复；下拉限高也不再走 `svh`（`svh` 不认软键盘，部分内核下等于 `vh`），
    改按实测的 `--kb-visible` 算，键盘弹着时才真的是「可视区的四成」
  - **候选下拉贴着搜索框**：间隙只有 4px，不再是悬在下方一段空白之外
  - **候选下拉不透明**：它是浮层，用 90% 不透明的卡片色会让下层的结果列表透上来
  - **搜索框与结果列表只隔正常间隔**：框贴顶时列表紧跟其后（间距 0，走列表自己的
    行距）；只有框还浮在页面中间时才留一小段呼吸（`--search-list-gap: 12px`）。
    此前是「框下面一段大留白 + 空态 44px」，第一张卡片被推到很下面 ——
    用户反馈的「不要和搜索框有那么多间距了，只保留正常间隔即可」就是说这里
- **没输入之前一条都不列**：输入几个字才列出命中的篇目，**字数越多、命中越少**
  - 空列表就是**空列表**：原先那句「输入篇名、作者或诗句，即可搜遍六部集子」
    已按用户要求撤掉，只留一小段留白（4px），
    不再是一行与结果区抢位置的说明文字
  - 输入过、但没命中时才有话：「没有找到匹配的篇目」，与结果列表**左对齐** ——
    刚进这一页就说没找到，像这一页坏了，两句必须分开
  - 这一条也是**性能**上的取舍：全站一千余篇，若首屏就铺出来，既没有人会从头翻，
    还要一次渲染上千个 DOM 节点
- 输入的**同时**在框下方浮出**候选下拉**（最多 8 条）：键盘上下键选、回车直接进，
  鼠标点也进；候选与结果列表走的是**同一套匹配口径**，不会出现「候选有、结果没有」
  - **高度有分寸，不占满也不伸进键盘**：取三者里最小 —— 380px（8 条的上限，
    手机 320px）、可视区的**四成**、`(可视区 − 键盘)` 那一片的**六成**。
    前一档保证「下拉下面永远留着一片看得见的结果卡片」（用户要求能先关掉下拉、
    再去点结果卡片），后一档是硬边界：键盘弹着时候选整条落在键盘上方，
    下面几条不会被盖住。上一版那一档是「可视区的六成」，手机上实测太松 ——
    候选铺到可视区下沿前 30px，底下只剩一条缝，「留一片」等于没留。
    ⚠️ 这里的「可视区」一律取 `visualViewport.height` 实测值（`--kb-visible`），
    不用 `svh` —— `svh` 量的是「视口最小时的高度」，它不认软键盘，
    在部分内核 / 无头环境里更会等于 `vh`，那一项于是虚高、下拉照样铺满
  - 手机上一屏大约看见 5～6 条，其余**滚动**看（拖动不会带动页面一起滚）；
    每换一个关键词，下拉滚回顶部 —— 新关键词的第一条不能停在中间
- **怎么把下拉收起来**（四条路，都看得见也摸得着）：
  - **点页面任何一处空白**：收起（用户原话「当用户点击空白地方时，下拉列表消失」）。
    判据只有一条 —— 落点在搜索区（输入框 + 下拉）之外。挂在 `document` 的
    capture 阶段而不是挑几个元素挂：页面上「能点的地方」是数不完的，
    挑着挂必然漏掉一处，而漏掉的那处正是用户会点的那处。
    只收下拉、**不阻断事件**：点卡片该开篇还是开篇，点别处该干嘛干嘛
  - 手指**滚结果列表**：收起（滚 = 用户已经在看下面的东西了）
  - **点结果区**：先收起下拉、**并吃掉这一下** —— 不许穿过浮层直接开一篇
    （用户看到被浮层压住半截的那条，却开了别的篇，最难解释）；
    收起之后关键词与结果都在原位，再点一下才进正文。平时（下拉没开）点卡片
    仍是**一下就进**，不会因为这条防线把最常用的动作变成两下
  - 按 `Esc`、或退掉输入（触屏之外的老路，照旧）
- 结果是「正文 / 译文命中」时，条目里补一句命中上下文（前后各 12 字），
  让用户一眼看到「我搜的句子在哪儿」
- **搜索页不写任何一部的已读**：它是「查东西」的地方，不是「读书」的地方 ——
  在一部集子里点开的进度，不该被搜索页的一下一次点击改掉
  （阅读器里的「标记已读」在这条路径上整颗隐藏）
- 原先搜索框右侧的「全部 / 未读」组合与集子筛选药丸**都已删除**：
  前者筛的是已读，而这一页根本不写已读；后者默认就是「全部」，
  「先选一部再搜」是多出来的一步前置操作

### 自选背诵（除教材之外，自己额外想背的篇目）

课内的每日任务只认教材里的 261 首。孩子想多背一篇《木兰诗》、家长想让孩子
加背《古文观止》里的一段，原先没有地方放。现在有了 **自选集合**。

> ⚠️ 自选集合与「唐诗三百首」「古文观止」那几部集子**不是一回事**：
> 那几部是**既定的选本**（篇目、卷次、词牌照书排，一个字不能改）；
> 自选集合是**用户自己的清单**，想加就加、想删就删，随时改名。
> 所以集合里**不分卷次、不分词牌、不分任何组** —— 就是一串篇目。

- **怎么加**：在课外阅读任一集子的**索引列表**点篇目右边的**书签键**，
  或进**详情页**点工具条上的「加入背诵」；**搜索页**同样能加
  （搜索页与五个集子页共用同一份阅读器引擎，一处实现、处处可用）
- **放哪儿**：一篇可以在**多个**集合里（各存一份引用）。第一次加时自动建一个
  默认集合「我要背的」；已经有集合了则弹出**集合选择器**让你勾选，或当场新建
- **怎么管**：首页「**自选背诵**」折叠卡里，每个集合一行 —— 可**改名**、可**删除**、
  可**导出**，逐篇可**移出**。家长建「我要背的」、孩子建「这周要背的」，互不干扰
- **怎么排**：集合里的顺序**就是用户自己排的**（新建的排在末尾）。
  条目上有 **↑ ↓** 两颗键，一次挪一位；队首的 ↑、队尾的 ↓ 自动禁用。
  集合不按卷次 / 词牌自动重排 —— 那是「集子」的规矩，不是用户清单的规矩
- **怎么一组一组拿掉**：同一部集子、同一个卷次文体的篇目在列表里连成一段，
  段头有「**整组移出**」，按一下拿掉这一组（不必逐篇点）。索引里查不到的条目
  （首页只有快照的那些）算「未分组」，同样可以整组移出
- **怎么互传清单**：每个集合头上有「**导出**」—— 一整个集合就是一串条目 id，
  导出成**纯文本**只有几 KB，微信 / 短信里直接发得出去。
  导出时顺手写进「集子 · 卷次 篇名」当注释，对方看得懂是什么。
  首页「自选背诵」里的「**导入清单**」粘贴进来即可，`#` 开头的说明行会跳过，
  认不出的行**如实报数**（不装作没发生）。导入**总是新建一个集合** ——
  家长传来的清单与自己的那几份混在一起，事后没人分得清哪条是谁的
- **篇名不带「其一 / 其二」**：宋词里同一作者同一词牌有好几首（晏殊三个《木兰花》、
  贺铸两个《蝶恋花》），原始清单没有首句可以分辨，整理时按目录先后标了
  「其一 / 其二 / 其三」。那个编号**只作语料内部的条目区分**，不是选本原名，
  对用户没有意义（「木兰花·其二」看不出是哪一首，反像漏了前半句）。
  所以自选集合显示篇名时一律去掉这个尾巴 —— 只改**显示**，
  集合里存的仍是完整 id（`tangshi-ts-1` / `-2` 仍分得清）；
  课内那 261 首**一个字不动**（那里的「其一」是教材原名）
- **怎么背**：加进来的篇目**并进「今日背诵」的遗忘曲线**（`reason: optional`，
  列表里标「自选」）。到期的排最前；没学过的排在本册课内篇目之后、
  系统「从相邻年级凑数」的那些之前 —— 教材是主线，用户显式加背的优先于系统替它凑的

#### 一篇作品只背一次：主表判重（课内以教材为准，选集以选本原貌为准）

同一首诗常常既在课内教材里、又在某一部选本里（《静夜思》《桃花源记》
《念奴娇·赤壁怀古》……近重复合并后共 **60 组**）。各集子的数据文件各自存一份副本，
所以「加自选」与「搜索」都必须先判重，否则同一首会背两遍、搜出两条。

`data/works-index.js`（主表）+ `data/works-map.js`（60 组同篇对照表）给出口径：

- **正文去标点、去空白后一致 = 同一篇作品**，合并为一条
  （《静夜思》课内与唐诗《夜思》正文一致；《陋室铭》课内作「孔子云何陋之有」、
  古文观止作「孔子云『何陋之有』」，引号剥掉后一致 —— 都算同一篇）
- **正文有出入的**，先看是不是「只差一处用字」的近重复 —— 是的话**按口径合并**，
  不是的话**分成两条并列**，各背各的
  （判重只看正文，不看题名，所以同名的《蝉》两首不会被误并）

规则一句话：**课内以教材文本为准，选集以选本原貌为准；只差一处用字的近重复按
「以教材为准 → 没有教材以简体字为准 → 都裁不了的自行判断」合并，其余有出入的分成两条并列。**

#### 只差一处用字的近重复：按口径**合并**（原本是「并列」）

判重键是「正文去标点后逐字相同」，可文献里常见的是一字之差的两种文本 ——
《黄鹤楼送孟浩然之广陵》教材「**唯**见长江天际流」与选本「**惟**见」、
《夜上受降城闻笛》教材「回乐**烽**」与选本「回乐**峰**」、
《将进酒》教材「但愿长醉不**愿**醒」与选本「不**复**醒」、
贺铸《蝶恋花》「白**苹**」与「白**蘋**」……

早先的处理是**并列而不合并**（理由是「选本原貌 vs 教材 / 通行字」两条文本传统，
谁对谁错没人能裁）。用户后来给了口径：

> 近重复的那批，合并，以教材为准，没有教材的，以简体字为准，无法裁决的，自行判断并合并

于是分三档裁定，逐条写在 `scripts/near-dup-merge.js` 的 `MERGES` 里
（连「为什么是这一档」都写明）：

| 篇目 | 两种写法 | 裁定 | 依据 |
|---|---|---|---|
| 黄鹤楼送孟浩然之广陵 | 唯见 / 惟见 | **唯** | 有教材，以教材为准 |
| 夜上受降城闻笛 | 回乐烽 / 回乐峰 | **烽** | 有教材，以教材为准 |
| 将进酒 | 不愿醒 / 不复醒（另有顿号 / 逗号） | **不愿醒** | 有教材，以教材为准 |
| 蝶恋花（贺铸） | 白苹 / 白蘋 | **苹** | 没教材，以简体字为准 |

用字统一之后**按同一篇收归**：正文只落 `data/text-master.js` 一份，
跨集的那三组（课内 ↔ 唐诗三百首）两条都留在各自的选本列表里、只是共用一份正文；
《蝶恋花》那组两条同在《宋词三百首》，并成一条、
删掉题名是自拟编号的 `蝶恋花·其一`（留下的是选本原名 `蝶恋花·改徐冠卿词`）。

效果：搜索只出一条、自选集合里加不进第二遍、排程只排一次，
学生也不会再读到与课本不一样的那一份。**两组正文的差异被逐字核对过**——
统一写法一律**按下标逐处改**，不做全局替换：《将进酒》里「复」有三处
（不复回 / 还复来 / 不复醒），只有第三处是两种写法之别；
全局替换会把前两处改成「不愿回」「还愿来」，把教材文本改坏。

落地顺序（`scripts/near-dup-merge.js` 只统一用字，其余三个生成器照旧）：

```
node scripts/near-dup-merge.js --apply   # 1. 按裁定统一用字（幂等，已并过的组会跳过）
node scripts/build-works-map.js          # 2. 判重表：并成一篇
node scripts/build-text-master.js        # 3. 存储主表：正文收归一份
node scripts/apply-text-master.js        # 4. 选本那条的正文摘成 textRef
node scripts/build-canonical-texts.js    # 5. 显示层裁定表（预期 0 条）
```

测试逐组守着：用字确实按口径统一了、两条确实判成同一篇、
各选本的条目数只少该少的那一条、全站**不再有「只差一字」的两条并存**。

排每日任务时按**作品**去重：加了唐诗《夜思》，若课内《静夜思》已背到第 4 轮，
进度**合流到课内那一条**（`WorksIndex.repOf` 优先取课内条目）——
既不会重背一遍，老的 `poem_recite_progress_v1` 进度也一条不丢。

#### 收尾一轮：三处「回来之后」才暴露的问题

这一轮没加新集子，补的是前几轮改动留下的边角。

- **自选集合的「今日计划」缓存不再漏更新**。当天计划缓存在 `sessionStorage`
  （`poem_plan_...`），原先靠「改动时主动清缓存」——只在**监听得到事件的那些入口**
  有效。在集子页点过「加入背诵」后**直接刷新首页**（或另开一个标签页），
  缓存还在，刚加的那一篇当天就不出现。现在把「集合里有哪些篇」压成一个短串
  （`js/app.js` 的 `collectionsKey()`）编进缓存键里，集合一变、键就变，缓存自然失效，
  不再依赖「谁记得清缓存」
- **自选快照的来路标了出来，并且首页会自己把它拉回来刷新**。首页只加载课内 12 册
  （约 52KB），五部集子那 4.4MB 不加载，所以自选篇目的正文靠「加入背诵」时存的
  一份最小快照。那一篇后来在集子里被订正过（标题改了、译文补上了），而用户
  **不再打开那一页**，快照就一直是旧的。分两步补：

  1. `js/collections.js` 的 `markStale()`：首页启动时把「首页拿不到新语料」的那些
     标成待刷新，进集子页 / 搜索页刷新后清掉标记。标状态不改任何正文
  2. `js/app.js` 的 `refreshStaleSnapshots()`：**光靠第 1 步还是不够** ——
     集子页 / 搜索页是**另一个页面**，用户在首页停留的整个会话里都不会经过它。
     所以首页发现还有 `stale` 标记时，按需把**那一部集子的数据文件**取回来刷新：

     - **只拉真正需要的**：一部都没涉及就不发请求
     - **一次只拉一部**，串行进行（免得几部大集子同时进来把首屏拖慢）
     - 拉取走「新建 `<script>`」——与页面里那些 `<script>` 是**同一条路**
       （同一个 Service Worker 缓存、同一套相对路径解析），
       不必自己处理「解析出来的文本怎么变成数据」，也就不会有分叉
     - **拉不到就算了**：离线 / 网络不通都不影响用 —— 老快照照常显示，
       `stale` 留着下次再试

     顺带补上一处**真缺口**：首页原先**没加载 `data/site-index.js`**，
     `js/app.js` 里那一串 `window.SITE_INDEX || []` 于是**静默为空** ——
     现象是「自选那一篇在首页显示不出来」，而不是报错（最难查的那种安静失败）。
     现在首页也加载它。
- **空态文案与六部口径统一**。搜索页空列表原写「即可搜遍**全站**」，
  现在写「即可搜遍**六部集子**」—— 与页签、README、入口页同一口径
  （课程诗词 + 五部集子 = 六部）

数据注释里另有两处口径复核：`data/pinyin-table.js` 的覆盖范围补上昭明文选
（表里 3554 字本来就是全站用字，只是说明漏了这一部）；`data/common-chars.js`
写明「常用字表不随语料膨胀」——它是按**小学生该认识的字**划界的，不是按站上出现过的字。

#### 正文收归主表（存储层）：同一篇的正文只落一份（`data/text-master.js`）

上一条判重解决的是「**认不认得是同一篇**」；这一条解决「**那一篇的正文存在哪**」。

同一篇作品此前在**每一部集子的数据文件里各存一份完整正文与译文** ——
《答谢中书书》课内八年级上 + 小古文、《登高》课内高一上 + 唐诗卷五……
磁盘上同一篇正文存了五份：改一处要改五处，漏一处就又不一致。

用户口径是「**正文收归主表，各集子退化成只存归属**」。落地分两张表、两件事：

- **存储主表** `data/text-master.js`（1331 条，由 `scripts/build-text-master.js` 算出）：
  同一篇作品的正文 / 译文**只落一份**，key 是主条目（课内优先，教材口径）。
  表尾另给一个取数入口 `window.masterTextOf(p, book)`——把条目上的 `textRef`
  展开成正文 / 译文，**各消费方共用同一个**（站点索引、阅读引擎、搜索页），
  免得各写一份、某一处忘了取，而表现只是「那一处正文空白」。
- **各集子退化成只存归属**（`scripts/apply-text-master.js`）：被主表收编的条目
  摘掉 `text` / `translation` / `translationSource` 三行，改留一行 `textRef`。
  共 **1391 条条目**收归：120 条跨集重复的（57 组 + 近重复合并进来的 3 组）
  + 480 条《昭明文选》的单篇 + 165 条《古文观止》的单篇 + 283 条《宋词三百首》的单篇
  + 255 条《唐诗三百首》的单篇 + 99 条《课外必背小古文》的单篇。
  条目仍带齐归属信息（题名 / 作者 / 朝代 / 卷次），只是不再存正文。
  （1391 这个数从哪来：主表 1331 条作品，把每条作品的 `entries` 逐条展开、去重
  再加起来就是 1391（120 条跨集重复的条目 + 1271 条单篇）。它与「各集子里带
  `textRef` 的条目数」是同一件事的两种数法，`test/canonical.test.js` 两头对账。）

  ⚠️ 小古文那一部是 **100 篇里的 99 篇**：第 100 篇《答谢中书书》与课内八年级上
  同篇，早在判重表收归时就只存 `textRef`（主条目 `poems-cz8-02`）了，
  部里其余 99 篇由本轮点名的清单收掉。

  **收归范围按部推进**（`build-text-master.js` 里的 `FULL_BOOKS` 清单）：

  | 顺次 | 部 | 篇数 | 状态 |
  |---|---|---|---|
  | 1 | 昭明文选 | 480 | ✅ 已收（`poems-zhaoming.js` 2.1MB → 154KB） |
  | 2 | 古文观止 | 167 | ✅ 已收（`poems-guwen.js` 728KB → 53KB） |
  | 3 | 宋词三百首 | 283 | ✅ 已收（`poems-songci.js` 275KB → 76KB） |
  | 4 | 唐诗三百首 | 301 | ✅ 已收（`poems-tangshi.js` 236KB → 64KB） |
  | 5 | 小古文 | 99 | ✅ 已收（`poems-classic.js` 90KB → 30KB） |

  点名一部，那一部**全部**条目（含单篇）的正文就进主表；清单没点名的部照旧内联，
  两种形态并存 —— 所以每部都能单独落地、单独回退。下一部要收归时，
  在 `FULL_BOOKS` 里加一个集子 id 即可（部内条目数不必改脚本）。

  **「昭明文选」那一部的长译文是「`translation:` 独占一行、值在下一行」的排法** ——
  `apply-text-master.js` 原先只认同行字段值，480 条一条也摘不掉。现在两种写法都认，
  且这条不静默通过：摘的行数不对会直接抛错，绝不半摘。

  **切条目的两个正则都曾把缩进写死，各吞掉过条目**（收《古文观止》那一部时才翻出来）：
  入口写的是 `/^  \{/`（恰好两格），而《齐桓晋文之事》那一条的 `{` 是行首顶格的，
  于是它从没被处理、一直保留内联正文；按 id 认条目那个正则又漏了多行标志 `m`，
  `^` 只认整串开头，`{` 与 `id:` 不同行的条目（`textRef` 插在 `id` 之前，这是绝大多数）
  一个都匹配不上、id 取成空串。两处都是**静默的**：页面照常、
  只有磁盘上少收了几条。现在缩进一律放宽成「至少一格」，
  并在脚本收尾加了一条**逐条对账**（主表登记的每条条目都得在语料里找得到 `textRef`，
  找不到就点名中断）。
- **引擎按 textRef 取回**（`js/reader-core.js`）：`canonicalOf()` 第一步先把
  `textRef` 展开成本条自己的正文，后面的列表、阅读器、朗读、排程、搜索
  都不必知道有这回事。页面须把 `data/text-master.js` 排在
  `data/site-index.js` 与 `js/reader-core.js` **之前**。

**显示层的裁定表随之收敛为空表。** `data/canonical-texts.js` 原是「各集子照旧各存一份、
显示时才替成主条目那一份」的显示层裁定 —— 存储层收归之后，各集子的正文本来
就取自主表，**两种写法不复存在**，这张表跑出来是 **0 条**（`build-canonical-texts.js`
输出「0 条」即说明语料里已无绕开主表的异文）。机制保留给日后真出现异文时用；
一旦它又非空，说明有语料没走主表、自己又存了一份正文 —— 那正是该去查的地方。

生成与应用的顺序（`text-master` 优先）：

```
node scripts/build-text-master.js   # 先算「同一篇的正文收哪一份」
node scripts/apply-text-master.js   # 再摘各集子的内联正文、加 textRef
node scripts/build-works-map.js     # 判重表（正文去标点后一致即同一篇）
node scripts/build-canonical-texts.js  # 显示层裁定表（预期 0 条）
```

`build-text-master.js` 带一道防线：内联正文已被摘掉时，从**旧主表**取那一份；
真取不到就让主表留空、**直接中断**——「主表是空的」这种错不报错、只让全站那一批
篇目正文空白，宁可生成时就亮红。

**主表收的是「字面完全相同」的那些。** 判重键是「正文去标点后逐字相同」，
可文献里常见的是一字之差的两种文本 —— 《将进酒》教材「但愿长醉**不**愿醒」与
选本「但愿长醉**复**醒」、《岳阳楼记》课本「**淫**雨霏霏」与古文观止「**霪**雨霏霏」、
《天香》「**剪**春灯」与「**翦**春灯」…… 这些**不是录入出错**，是选本原貌与
教材 / 通行字两条并存的文本传统，按 `data/works-index.js` 的裁定应当
**分成两条并列、各背各的**。

它们也是最容易被顺手合并 / 也最容易被漏掉的一批：正文差不多、题名往往只差一点、
搜出来还并排站着。**现已按上面那张裁定表全部合并**，
`data/works-map.js` 的 `window.WORKS_NEAR_DUP` 与 `data/text-master.js` 的
`window.TEXT_NEAR_DUP` 因此都收敛为**空表** —— 机制保留，给日后真出现
「裁不了的异文」时用；测试全站扫一遍，**任何「只差一字」的两条并存都会红**。

#### 孤儿背诵进度：删掉，不合流

课内那 12 组自身重复去重时，被删掉的高年级那一条上可能留有进度键。
用户口径是「**合并进度，暂时用户极少，可以删掉进度，清理无效数据**」——
所以 `js/storage.js` 的 `pruneUnknown()` 在**首页启动时**跑一次，
把「确认已不在语料里」的键删掉，不做合流：合流要猜「这一篇的进度算谁的」，
而这一批本就是同一份教材内容存了两遍，留着只会让老用户某天莫名看到「第 4 轮」的复习任务。
删掉之后这一篇按未学过排进每日新学，行为与「从没背过」完全一致。

- 只删**确认已不在语料里**的键，且在**拿到语料时**才动手：`POEMS_ALL` 为空时一个键都不删
  （宁可留孤儿，也不能误删一篇真实篇目的进度）
- 启动时只做一次，不挂在「改设置」那条路径上 —— 什么时候会动用户的进度，说得清

#### 分组顺序收归一处（`data/group-order.js`）

卷次 / 词牌 / 文体的先后原先写在各自的挂载脚本里（`js/tangshi.js` 的 `GROUP_ORDER` 等），
只有「进那一页读那一部」时才用得上。主表判重要用它（同一篇合并之后排谁的后面），
页面也要用它 —— 于是收进 `data/group-order.js` 一处给出：`window.groupOrderOf(bookId)`。
宋词的词牌表与昭明的文体表数据量大，仍留在各自脚本里，但挂在 `window` 上供总表引用，
顺序**只写一处**，两边不会各改各的。

### 1.5 导航：一套顶栏 + 底部三个页签

三页（首页 / 小古文 / 法务页）原先各写一份顶栏，标题、返回键、右侧按钮都不一样，
容易「不知道自己站在哪一页」。现在统一成一套：

- **顶栏第一行永远是「徽标 + 跬步 · 页面名」**，全站一致；
  徽标是篆意「步」字印（上「止」下反「止」），页面名与「跬步」**同字号、同字重、同一行**，
  中间的「·」由 CSS `::before` 生成（页面里不写死标点）
  - 首页：`跬步 · Ashley的古诗词`；小古文页：`跬步 · 小古文`；法务页：`跬步 · 隐私条款` / `跬步 · 用户协议`
- **顶栏第二行是「这一页是干什么的」**，由各页在 `<body>` 上写 `data-sub` 给出，不硬编码在 JS 里：
  - 首页：`按遗忘曲线安排复习 · 小古文想读哪篇点哪篇`
  - 小古文页：`想读哪篇点哪篇`（页面名已在第一行，第二行只补这句说明）
  - **刻意不写「一年级至高三」这类学段字样**：首页能自己选年级学期，
    固定写死一个学段反而让非该学段的用户觉得不是给自己用的
- **顶栏右侧一个动作位**：首页**留空**（设置交给底部页签，不再重复放一个齿轮），
  内页是「回首页」，阅读器打开时变成「关闭」；
  **小古文阅读器左上角的返回键就是同一颗按钮**（同样的 40px 圆形纸底、同一笔画粗细、
  同一 `.top-act` 样式），里面只有一个箭头，不再叠「小 古 文」三个字
- **页面可以往顶栏这一行里挂自己的小件，位置固定在右侧动作位左边**：
  小古文页就把「已读 / 总数」进度牌挂在这里，
  这一行的顺序固定为　`徽标 · 跬步 · 页面名 / 副标题 ｜ 页面小件 ｜ 返回键`
  - 这一行由 `js/chrome.js` 统一渲染，页面小件由 `renderBar()` 在重建前后**出栈再插回**，
    所以阅读器一打开（动作位换成「关闭」）小件也不会丢，更不会插出两块
  - 整行 `align-items: center`：徽标、两行文字的品牌区、进度牌、40px 返回键
    **共用同一条中轴**（`.count-badge` 用 `line-height: 1` + `flex: none` 保证只按自身高度居中）
- **底部三个页签：古诗词 / 小古文 / 设置**，页面之间统一从这里跳转；

### 3. 复习算法自动排期（可切换）

点开诗词后，如实选择自己的掌握程度，系统自动算出下次复习时间：

| 选择 | 效果 |
|---|---|
| 😄 记住 | 按当前算法推进（拉长间隔 / 往后挪一盒 / 抬高稳定性） |
| 🤔 模糊 | 停留原地，**12 小时**后再复习（所有算法一致） |
| 😵 忘记 | 退一级重来，**30 分钟**后再来（所有算法一致） |

**用哪一套算法算「下次什么时候复习」，在设置页选**（`设置 → 复习算法`），
四张模型各自说清来源与取舍；背诵页顶栏第二行会跟着写「按 X 复习」：

| 模型 | 出处 | 变量 | 一句话取舍 |
|---|---|---|---|
| **遗忘曲线**（默认） | 固定间隔计划表 | 阶段 | 零参数、一眼看得懂，短诗与词最省心；但它**不看你这篇是难是易** |
| **莱特纳盒** | Leitner 盒（1972） | 盒号 | 纸质卡片那一套：答对往后挪一盒、答错退回第一盒。无数学，家长看得懂 |
| **SM-2** | SM-2（1987，Anki 旧版默认） | 间隔、简易度 EF | 变量少、结果稳，对长篇（《琵琶行》这类）比固定表贴合 |
| **FSRS** | FSRS（2022，新版 Anki 内置） | 难度 D、稳定性 S、可提取性 R | 三变量，积压多、难易差别大时收敛最好；见下方「简化版」说明 |

关于这张表的几条实话：

- **「艾宾浩斯遗忘曲线」不是调度算法**。它是心理学规律（遗忘先快后慢）；
  网传的 1-2-4-7-15-30 天是后人自制的计划表，与艾宾浩斯本人的实验数据
  并不一一对应。项目照旧把它当**出厂默认**（零参数、可解释），
  但心里清楚它是一张固定表。
- **SM-17 / SM-19 / SM-20 不做**。SuperMemo 私有闭源、公式未公开，
  无法如实复现 —— 宁可明说不做，也不编一套「像 SM-17 的东西」冒充。
- **HLR 半衰期回归（多邻国）不单独成一套**。它「每条记忆算半衰期」的思路
  与 FSRS 的稳定性 S 同源；单独再摆一套只会重复，故并作 S 的解读
  （S 就是「记忆强度衰减到一半所需的天数」）。
- **FSRS 是简化可解释版**。官方完整版靠**用你的复习历史做机器学习拟合**，
  每个人参数都不同。本项目是纯前端、没有后端也没有训练数据，
  所以只落地公开的固定参数与公式骨架（`R = 2^(−t/S)`、间隔按
  「R 回落到 0.9」反推、D 随对错升降），**不做拟合**。

**换算法不清进度。** 已经背过的篇目一篇不丢，按最接近的落点接到新算法上接着走
（`ReviewModels.adopt()`：`level` 这个通用刻度原样保留，另按新模型补上它自己的量）。
换算**不动 `nextReviewAt`** —— 用户已经排好的到期时间，不该被换一套公式顺手挪走。
只有之后**新做的评价**才按新算法算。

三个展示口径跟着当前模型说，不各说各的：首页副标题（「按 FSRS 复习」）、
详情弹层的「记忆阶段」（Leitner 说「3 号盒 · 4 天后」、SM-2 说「间隔 7 天 · 简易度 2.5」、
FSRS 说「稳定 12.3 天 · 难度 5.2」）、进度页的阶段档名与「走完全程」那一行。

出厂默认的间隔序列（天）—— 也就是「遗忘曲线」那张表：

```
当天 → 1 → 2 → 4 → 7 → 15 → 30 → 60 → 120 → 240
```

规律即"先密后疏"：刚记住时反复得快，越牢固间隔越长，用最少次数把诗记进长期记忆。
其余三张的间隔是**走出来**的（Leitner 看盒号、SM-2 看 EF、FSRS 看稳定性），
没有一张固定表可列 —— 设置页「复习间隔」那一行会照实说当前这张的口径。

### 3.9 列表项序号：空心圆在标题行里，直径 = 字号

全站三处列表（首页「今日背诵」、首页「本年级本学期全部诗词」、小古文索引页）**同一套序号**：

- **圆挪进标题行、排在篇名前面**。原先序号是独占一列的 30px 圆（第二列才开始排标题），
  一列 30px + 列间距 12px，等于每行白送 42px；现在圆挂在标题行左侧，正文宽度全数还给文字
- **圆与下方正文左对齐**：标题行不再挂 `margin-left: -12px`（那是「圆探出内容块」年代的解法），
  改为 `margin-left: 0` —— 圆周左缘 = 篇名 = 下方「朝代 · 作者 · 年级」，三者同一条左基准线。
  代价与收益：圆不再「领先」正文，但条目内容块左右内缘对称（左 8px = 右 8px），圆左内缘与右侧箭头右内缘同宽
- **去掉淡绿底色，改为 1px 圆形描边**（`box-sizing: border-box`，圆外径仍是 16.5px）。
  实心底圆一百条排下来就是一百块淡绿色斑，视线先落到色块上；改成空心圆后只剩一圈细线，
  数字仍是同一个颜色 —— 边框色走 `currentColor`，所以换主题色只改 `color` 一处。
  `border-box` 保证描边占在盒子内、圆外径不变（「左对齐」的几何因此不受影响）
- **圆的直径 = 标题字号**（`--item-num: 16.5px` 与 `.item-title` 的 `font-size` 同一个数），
  横向与纵向都对得上；圆里的数字**单列一档 11px** —— 16.5px 的数字会顶满 16.5px 的圆边，
  11px 才留得出四周留白，也放得下第 10 篇起的两位数
- 数字**水平与垂直居中**：圆是 `inline-flex`，两轴都 `center`，`padding` 归零，
  圆心即数字盒中线（真浏览器里量过：左右、上下留白各自相等）
- 圈线颜色沿用原序号圆：古诗词走天青 `--green`、复习走琥珀 `--amber`、小古文走天水碧 `--blue`，
  课外必背那几篇走天青 —— 小古文课内 / 课外**只由圈线色与卡头分组名表达**
  （`jsdom` 不比布局、真浏览器量的是渲染后的盒子，两条断言分别在 `test/classic.test.js`
  与 `test/pwa.test.js` 里兜底）

#### 背诵进度总览（`/progress/`）：到期日历 + 全部到期篇目 + 掌握度分布

入口在**设置页 → 古诗词背诵 → 背诵进度 · 看进度总览**（底栏页签在进度页
保持「背诵」这一格选中 —— 它讲的就是课内背诵那本账，不是独立的一站）。

为什么要有这一页：原先「这篇在第几轮」「掌握度多少」「下次何时到期」只在
**单篇**的详情弹层里看得到。单篇视角够用，但它回答不了三个真正想知道的问题：

- 接下来哪天要复习几篇？今天要背几篇？
- 那天要背的**具体是哪几篇**？（只知道「周三 5 篇」帮不上忙）
- 整体到什么程度了 —— 都堆在「新学」，还是已经有一批「较牢固」？

三张图 + 一份清单：

| 图 / 清单 | 内容 | 口径 |
|---|---|---|
| 到期日历 | 未来 **14 天**每天到期的篇数，竖条越高那天越忙 | **逾期（一周以内）并进「今天」那一格**（逾期就是今天该复习，单列会让日历第一格永远是空的）；逾期**超过一周**的另计一条提醒。超出 14 天窗口的不占格 |
| 全部到期篇目 | 日历那一格摊开成**篇名清单**：哪天是**哪几篇**，每篇带阶段 / 掌握度 / 「逾期 N 天」或「还有 N 天」 | 与日历**同一本账**（同一套归档规则）：逐档的篇数与日历逐格的数必须相同。今天那一档下方另挂一截「逾期超过一周 · N 篇」—— 它**不并进**今天那一档的天数（与 `overview().overdue` 一样是另计），两处数才逐格对得上。⚠️ 汇总行的「今天 N 篇」也**只数今天那一档**（不含 backlog），与日历今天那一格同一个数 |
| 掌握度分布 | 五档：0-19 / 20-39 / 40-59 / 60-79 / 80-100% | 与 `Scheduler.mastery()` 同一把尺子（页面到处在用的是它），每 20% 一档 |
| 记忆阶段 | 十档：新学 / 1 天后 / …… / 120 天后 / 已牢固 | 与复习间隔 `INTERVALS` 同长，档名取自 `levelName()` |

「全部到期篇目」是这一轮补上的那一页（原先 README 里挂着的「看不到是哪几篇」）：
日历回答「哪天忙」、清单回答「那天是哪些」，**点日历某一格就滚到那一天那一档**
（格子挂了 `data-offset` 与 `role="button"`，键盘 Enter / 空格也接得上）。
清单里的篇名是指回首页的链接（`/?poem=<id>`）—— 这一页只读，
真正「背这一篇、记一次复习结果」仍在首页那一套里，两处不重复实现。

**首页那一头是接上的**：`/?poem=<id>` 进来，首页会直接打开那一篇的详情弹层
（课内 261 首与自选集合里的课外篇目都认），读完即用 `replaceState` 把地址栏
那一截抹掉（刷新不再弹、返回键回得到干净的首页），查不到的 id 安静放过。
⚠️ 这一条原先断着：链接形态有测试守着，但全站没有一处读 `location.search` ——
点过去首页照常画「今日背诵」，什么也不弹，用户只觉得「没反应」。

聚合口径在 `js/scheduler.js` 的 `overview()` / `dueList()` / `daysUntilDue()`：
`overview()` 出「形状」（每天几篇、各档多少），`dueList()` 出「名册」（哪天是哪几篇），
两者共用同一套归档规则 —— **日历说今天 3 篇，清单里今天就得是那 3 篇**，
`test/progress.test.js` 拿两边的数逐格对账。

两条容易踩的规矩：

- **这一页只读**。它不改任何一篇的排期、不写任何一部的「已读」、
  不排今日任务（`sessionStorage` 一个键都不落）。要改进度的操作都在首页那一套里
- **竖条按「最忙的那一天」归一**，横条按「最多的一档」归一 ——
  不归一的话每格都短得看不出差别，这张图就等于没画

`buildTodayPlan()` 只管「今天排哪几篇」，上面这三个函数管的是「全量的形状与名册」，
两者分开写 —— 前者的产物是任务列表，后者的产物是画图与列清单要用的数。

### 4.5 诗词详情页（与小古文对齐的阅读工具条）

课内诗词的详情弹层，现在与小古文阅读器用**同一套控件、同一顺序**，用户在两个页面不用重新学一遍：

| 行 | 控件 |
|---|---|
| 第一行 | `正文对齐`（左 / 中 SVG）· `A－ / A＋` 组合（六档 13 / 15 / 17 / 19 / 21 / 23，**古诗默认 17px**，比小古文再小一号）· `不注音 / 生字 / 全文` |
| 第二行 | `正文朗读`（**一个** ▶ / ⏸ 播放键，同键两态）· 译文开关（SVG 圆形图标） |

- **白话译文**：与小古文同一套译文框，默认折叠、点译文图标展开；
  展开后译文标题右侧出现它**自己那一颗**朗读键，可只读译文
  - **全库 261 首译文 100% 齐备**（含全部初高中长词与文言文）——
    **译文为本项目自拟的白话直译，不是任何一家出版社的现成版本**，
    每首都在数据里标了 `translationSource`，界面译文框下方会照实显示口径
    （四类含义见下文「译文的取舍标准」），用户知道自己看的是什么
  - 译文统一用「白话直译 + 必要的意译补充」，不加入教材之外的引申与评价；
    用了哪些字会被自动纳入字体子集，见下文「字体」一节
- **同一篇只有一个播放信号**：▶ 与 ⏸ 是同一颗键的两种状态，播放中在原地换成暂停；
  译文那颗键跟着译文框出现 / 消失，不再出现「原文、译文两个播放键并排、不知道点哪个」
- **互斥规则的写法有讲究**：`▶` / `⏸` 两个图标都写在按钮里，靠 `[data-on]` 显示其中一个。
  但「`.trans-read .btn-icon { display: inline-flex }`」是 0-2-0，
  若互斥规则只写 `.trans-read .pause-glyph`（同为 0-2-0）就会被它按
  「同特异性、后写胜出」压回去 —— 结果**两个图标并排同时显示**。
  所以互斥规则一律多带一个 `.btn-icon` 把特异性抬到 0-3-0。
  `test/pwa.test.js` 会在真实浏览器里量计算样式兜底防复发。
- **译文是两页共用的组件**：`.trans-box` / `.trans-head` / `.trans-read` 的样式住在

页面之间一律用绝对路径互链（`/classic/`、`/terms/` …），
无论当前在哪个目录，链接都指向同一处，不会有「相对路径越跳越深」的问题。
导航、页签、法务互链都由 `js/chrome.js` 的 `ROUTES` 一处给出。

三个容易踩的坑，已在代码里钉死并加了测试：
1. **资源引用**：住在子目录的页面若用相对路径（`css/style.css`）会去 `/settings/css/...` 找。
   小古文页显式声明 `<base href="/" />`，其余子目录页面统一用 `/css/...`、`/js/...` 绝对路径。
2. **Service Worker**：注册路径必须是站点根 `/sw.js`。用相对的 `./sw.js` 会解析成
   `/settings/sw.js` 而 404，整站离线能力静默失效。
3. **改了样式却「看起来没改」**：`sw.js` 里 css / js / 字体一律**缓存优先**
   ——命中缓存就直接返回，不回源比对。因此**只要动了 `css/` 或 `js/` 里的文件，
   就必须把 `CACHE_NAME` 的版本号 +1**，否则老用户会一直拿着旧副本，改多少遍都不生效。
   这条约定写在 `sw.js` 顶部，并由 `test/theme.test.js` 断言守住。

- **卡头与首条之间留 8px 间隙**（`.group-head` 下内边距），组名与右侧那颗圆键都因此**离开下面的分隔线**；

  条目 `.group-card .item` 左内边距 **12px**、右内边距 **8px**（左比右多 4px）。
  两层相加才是「文字距卡片左缘」= 2 + 12 = **14px**。
  条目左侧这一路是**逐轮只加左边**长出来的：8px（原）→ 10px → **12px**；
  右侧 8px 是「卡片右缘 → 播放键 / 箭头」的间距，一直不跟着动。所以这里写成四值
  `padding: 12px 8px 12px 12px`，而不是看起来更整齐的 `12px 12px`：
  后者会顺手把右边也推走，`test/classic.test.js` 有断言盯着这个区别（左 12 / 右 8，差恰好 4px）。
  卡片那层的左内边距只加在**卡片**上（而不是卡头的 padding）—— 卡头与条目共用同一条左缘，
  写在卡片上则卡头 / 条目 / 首条淡线整体右移，卡内相对关系不变。
- **卡头那一行多 4px**：`.group-head` 左内边距 8 → **12px**，写成四值
  `padding: 12px 8px 8px 12px`，右 / 上 / 下全不动 ——「这一行多 4px」指的是**行本身**：

  与条目里的右箭头同宽。卡头与条目是兄弟，两者都长在「卡片 2px」这层之上、
  自己的左内边距同为 12px，所以「卡头文字 ↔ 条目文字」仍严格对齐（2 + 12 = 14px，两处同值）。
  若写成 `12px 8px 8px` 的对称写法，那颗圆键会被一起往里推 4px，右侧 8px 的内缘就破了；

  播放键左缘与左侧正文**几乎贴着**（左侧间距 **0px**，见下方「间距的取舍」）
- **间距的取舍（条目右侧两颗图标）**：全站 `.item` 是 `gap: 12px`，首页今日条只有
  「正文 ↔ 一颗圆键」一段间隔；小古文条目右侧是「圆键 + 箭头」两颗图标，

  现在卡内 `gap: 0`，改由两颗图标自己的外边距逐项给：
  正文 … **0px** … 圆键 … **6px** … 箭头 …（条目 8px 右内边距）。

  首页的播放键不受影响
- **左侧正文的宽度（Issue #55 这一轮的正主）**：上面那条「间距减到 0」本身
  **不会**让正文变长一个字 —— `.item-main` 是全站那句 `flex: 1 1 0%`，
  一个 **flex 增长项**：宽度只由「条目宽 − 两侧图标 − 列距 − 内边距」分配而来，
  与自己的内容有多宽毫无关系。一行里唯一的可变项就是它，所以把播放键的
  `margin-left` 从 0 改到 -12px，多出来的 12px 只是记到内容块的宽度账上
  （首条：内容块由 287px 变成 299px），正文并没有变长；负外边距的效果是让
  圆键「压」在内容块右缘上画，视觉上反而更挤。
  真正的做法是把内容块从「按容器分配宽度」改成「**按内容取宽度**」：
  - 内容块 `flex: 0 1 auto`（宽屏下按自身内容取宽，窄屏放不下再收）；
  - 播放键左侧 `margin-left: 0`，那 12px 不再当空档，改成正文自己占用。
  效果：宽屏（≥ 820px）下条目不再留出大片空白，摘要在自身宽度用完处就结束，
  正文一路排到播放键跟前（首条：摘要右缘由 446.9px 推到跟圆键左缘齐）；
  窄屏（≤ 413px）下圆键左缘位置与改动前**分毫不动**，正文那一行的可用宽度也分毫不减，
  只是内容块的名义宽度由 299px 变成 287px（多出来的 12px 正是上一轮被负外边距
  吃掉、用来把圆键压到正文上的那一段）。
  不能写成 `flex: 0 0 auto`：自动宽度要在布局期算出来，而 `.item-meta` 末段
  （原文摘要）带 `ellipsis`，真分到宽度之前量不出要截多长 —— 两次布局互相依赖，
  Chrome 会退回最小宽那一档，正文反而被压到 200px 上下。`flex-shrink: 1` 才是
  同一条反馈回路：先按自动宽摆、放不下再按比例收
- **标题与副标题**：与首页同一套顶栏 —— 第一行「跬步 · 小古文」，下面补一句副标题「想读哪篇点哪篇」

    - 正文键读标题 + 朝代 + 作者 + 正文；▶ 与 ⏸ 是**同一颗键的两种状态**，
      播放中在原地换成暂停，绝不是两个图标并排
    - 译文那颗朗读键放在**译文框的标题右侧**，跟着译文框一起出现 / 消失，
      一篇文章任何一个时刻只看得到一个播放信号
  - 译文开关与「标记已读」是方形图标按钮，图标**真正水平 + 垂直居中**
    （flex 居中 + `line-height: 0`，压掉 SVG 作为行内元素时的基线留白）
- **正文对齐**：左 / 中两个 SVG 图标，用户自己选，选择记在本机（`poem_classic_align_v1`）；

  - 古诗短句**默认居中**（像碑帖）；《少年中国说》《古人谈读书》这类长古文**切左对齐**更好读

    阅读器打开时底部页签自动收起

## 🔊 生字注音与朗读

给小朋友解决两个卡点：**不认字**和**不会读**。

### 生字注音

- **在哪用**：课内诗词详情弹层、小古文整页阅读器，都有一组「不注音 / 生字 / 全文」三档按钮
- **默认「生字」档**（即原来的「只标生字」）：只给小朋友可能不认识的字压拼音，页面清爽。
  命中条件有两个，满足其一即注音：
  1. **生字** —— 不在 `data/common-chars.js` 的前 2500 字里（约等于小学阶段识字量）
  2. **多音字** —— 即使字很常见（`曲 / 还 / 间 / 行 / 少`）也照标，因为小朋友最容易读错，
     不标就会出现「整首诗一个字拼音都没有」的空档
  标出的字约占正文 **17%** —— 是「生字」，不是「全文」
- **「全文」**：给刚识字、需要全量辅助的小朋友，逐字标注
- **怎么实现**：`<ruby>` 把拼音压在汉字上方，标点与换行原样保留；正文本身不被改动
- **状态持久化**：档位记在 `localStorage`（`poem_helper_pinyin_v1`），旧版布尔值自动迁移（`1`→生字、`0`→关闭）
- **数据来源**：`data/pinyin-table.js` 收录 **2547 个汉字**，覆盖课内 261 首 + 课外 100 篇里出现的**全部**汉字，构建期用 `pinyin-pro` 离线生成；
  常用字表 `data/common-chars.js` 由 `jieba` 字频表导出前 2500 字。两份表都是只读数据，运行时**不依赖任何第三方库**
- **多音字**：值含斜杠表示多音（如 `曲:qū/qǔ`），`js/pinyin.js` 按上下文选读音：
  1. 先查内置词表（`曲项`→qū、`绿水`→lǜ、`一水间`→jiān、`应怜`→yīng、`知者乐水`→yào …）
  2. 再按变调规则处理「一 / 不」（见下）
  3. 都判定不了时取第一个读音（也是现代最常用读音）
- **「一 / 不」变调**（按普通话规则，不是简单取首读音）：
  - `不`：去声前读 `bú`（不尽 bú jìn），其余读 `bù`（不能 bù néng）
  - `一`：去声前读 `yí`（一片 yí piàn），阴平/阳平/上声前读 `yì`（一行 yì háng），
    序数或词尾读本调 `yī`（第一 dì yī、一九 yī jiǔ）
  - 词表里遇到「一 / 不」不直接返回，交给变调规则裁决，避免硬编码错调

> 拼音表是**只读数据**，不改动诗词正文，正文里不会混入拼音字符。

### 总开关：阅读辅助

设置里的「阅读辅助」开关是**总开关，也是权威**——课内弹层与小古文阅读器都听它的：

| 状态 | 打开一首诗 / 一篇古文时 |
|---|---|
| 开启（默认） | 正文按**当前注音档位自动注音**（出厂档位「生字」），随时可手动切档 |
| 关闭 | 正文**一律纯文本**，无论此前存过什么档位 |

- 注音共三档：**不注音 / 生字（默认）/ 全文**，弹层与阅读器里都能直接切
- **总开关与档位始终一致，不会打架**：
  - 在设置里关掉「阅读辅助」→ 即使 `poem_helper_pinyin_v1` 里残留着「全文」档，正文也是纯文本
  - 在弹层 / 阅读器里手动选「生字 / 全文」→ 自动把「阅读辅助」打开（设置面板里的按钮同步变亮）
  - 在弹层 / 阅读器里手动选「不注音」→ 自动把「阅读辅助」关掉
- 关闭后再打开，不必刷新页面：首页立即重渲染当前这首，小古文页监听 `storage` 与 `pageshow` 事件同步
- 朗读按钮两种状态下都可用（朗读必须由用户手势触发，本就不做自动播放）

## 🔁 自动朗读（不看手机也能听）

给「一边做事一边听」这个场景做的整套能力，全部基于系统语音，零音频文件、断网可用。

| 入口 | 行为 |
|---|---|
| 今日任务卡右侧的 **▶ 圆形播放键** | 依次朗读当天每一首，读到哪首，列表里那首自动高亮滚动 |
| 今日列表每首右侧的 **▶ 播放键** | 只读这一首，再点一次停止 |
| 小古文列表每篇右侧的 **▶ 播放键** | 只读这一篇，再点一次停止 |
| 小古文索引页工具栏的「**随机连读**」圆键 | 全页随机抽一篇开读，**读完自动跳下一篇**并打开阅读器，列表同步高亮 |
| 小古文每个分组右侧的小圆键 | 同上，但**只在本组内**抽（「蒙学经典」共 4 篇就只在这 4 篇里轮） |
| 详情页（诗词弹层、小古文阅读器）的「**▶ 播放键**」 | 只读当前这篇，播放中变 ⏸，**暂停中仍是 ⏸**，点一下停止（不会叠一层朗读） |
| 小古文阅读器的「**译文朗读**」 | 只读白话译文，不读原文（译文框里那颗 ▶ / ⏸，同键两态） |

朗读内容统一为：**标题 → 朝代 → 作者 → 正文**。

**凡「听」的动作，全站都是一枚圆键**

圆键只有一副形状：**正圆 + 纸底 + 描金细线 + 同一套按下回弹**（`transform: scale(.94)`）。
尺寸与主色随上下文走，形状与手感全站一致：

| 位置 | 尺寸 | 主色 | 状态 |
|---|---|---|---|
| 今日任务卡右侧 · 播放键与 0/5 进度环 | 画出来的圆 40px（两颗最大外径相等）· ▶ 图标框 17px | 缃色（压在深天青今日条上） | ▶ / ⏸ 同键两态 |
| 首页·小古文列表每篇右侧 | 36px | 天青 / 天水碧 | ▶ / ⏸ 同键两态 |
| 小古文工具栏「随机连读」 | 40px（与搜索框同高） | 天水碧 | ▶ / ⏸ 同键两态 |
| 小古文每个分组右侧 | 26px | 天水碧 | 只画 ▶（进行中由列表高亮 + 播放栏表达） |

两条容易踩的坑，都已写进断言：

- **宽高必须同源**，否则渲染出来是椭圆。CSS 写 `border-radius: 50%` 并不够 ——
  若 `height` 被 flex 拉高（或只给了 `min-height`），圆环会纵向变扁。
  `.gw-play-main` 的宽高都读 `--toolbar-h`，`.gw-play-sm` 宽高都写 26px，
  `test/pwa.test.js` 再在真浏览器里量一次 `getBoundingClientRect` 兜底。
- **圆环别给描边做补偿**（今日条踩过）。进度环的描边由 `<svg>` 画、`svg` 是
  `overflow: hidden`，骑在边界上的 `stroke` 会被裁进盒子内 ——
  **盒子尺寸就是环渲染出来的最大直径**。曾按「盒子 − 一圈描边」把 `.ring`
  收到 40px，真机量出环 40、播放键 46，环反而小了一圈。
  想调外径就改 `.today-actions` 上的 `--today-btn-size`（两颗圆唯一的尺寸来源），
  别在 `.ring` 里写第二个数。`test/pwa.test.js` 量的是「外盒 / 路径框 + 描边」取大者，
  两种实现都蒙不过去。
  现状 **画出来的圆 40px**：进度环的 `<svg>` 把 3px 描边裁在盒内，盒子 40px 就是最大外径；
  左侧播放键用 `box-sizing: content-box` + 外盒 40px —— 它自己那圈 1.5px 边框**往外长**，
  画出来的圆外缘同样是 40px，两颗圆逐像素相等、中线齐平（这是「一大一小」报了三轮后的正解：
  前几轮一直在改外径，而差的是 border-box 把 1.5px 边框算进了那 40px 之内）。
- **外径与内径各有一个唯一来源**。今日条这颗播放键分两层：
  **外径** = 圆本身，`.today-actions` 上的 `--today-btn-size`（40px），播放键与进度环共用；
  **内径** = 里面的 ▶ / ⏸ 图标框，同一个块上的 `--today-btn-inner`（17px），
  `.today-read svg` 读它 —— ▶ 与 ⏸ 同框，两态切换不会忽大忽小。
  想「外圈不动、图标收一点」就只改后者，别在 `<svg>` / `<path>` 上再写
  `width`、`height` 或 `transform`：那等于给内径加了第二个数，下次再调又得满文件找。
- **圆键不带可见文字**。状态一律由 ▶ / ⏸ 与 `aria-pressed` 表达，
  文字说明只放在 `title` 与 `.sr-only` 里；更不要写「连读 / 连读中」这种随状态改写的文案 ——
  那会让按钮在连读开始的一瞬间变宽变窄，一排按钮跟着抖。
- **页首间距写在 `.toolbar` 的 `margin-bottom` 上，别靠 `.group-head` 加倍**。
  分组标题的上内边距是「分组接分组」时用的，它同时也是列表最上面那一个标题的上内边距 ——
  页首那一段（工具栏 ↔ 列表）要改就改 `.toolbar` 的 `margin-bottom`（页首专属），
  别一味去动 `.group-head` 的 `padding`，否则从第二个分组起会挤在一起。
  这一段的取值又与上方 `.topbar` 的 `padding-bottom`（12px）对齐，搜索框上下等距；
  改一处记得另一处跟着看。

**朗读状态怎么判断（`Speech.active()`）**

界面按钮的文案（朗读 ↔ 停止）只认一件事：**现在有没有朗读任务在跑**。判断口径分三层：

1. `Speech.active()` 为真 —— 队列还在跑（含暂停）；
2. 单条朗读（阅读器「朗读 / 译文朗读」、列表播放键）单独记一个「暂停标记」，
   因为**部分设备 `pause()` 之后 `synth.speaking` 会变成 false**，只看引擎状态会误判成「已经读完了」；
3. 一条读完后的极短时间（600ms）内仍算「任务在跑」，按钮不会在收尾瞬间来回跳。

这样可以保证：**暂停中按钮仍显示「停止」，再点一次就是停下来**，
而不是重新叠一层朗读（曾经的问题：暂停后点「朗读」会重头再读一遍，
「显示译文 / 隐藏译文」「译文朗读」跟着错乱）。

> 实现细节见 `js/speech.js`：`active()` / `singlePaused` / `singleEndedAt`，
> 以及阅读器里的 `readingActive()` 与 `handleSpeechStopped()`。

**底部播放栏（宋式美学 · 音乐播放器）**

朗读开始后从底部**弹出播放栏**，占满整个底边宽度、**没有圆角、没有 margin 浮起**，
高度加大，深天青底 + 一支缃色描金细线，像手机底部弹出的播放器：

- 左侧大字是**当前这一首**（播放中前面有一缕缃色游标轻轻呼吸），
  下面一行小字「**下一首 · 江南**」——下一首的图标一激活，用户就知道该听哪首
- 右侧 4 个圆形图标按钮：**上一首 / 播放·暂停 / 下一首 / 停止**，
  全部是内联 SVG，**不出现「正在朗读 / 暂停 / 继续 / 下一篇 / 停止」任何文字**
- 播放键用缃色（与 0/5 进度环同色）做视觉重心；暂停时换成 ▶，一眼看出点它能继续
- 已去掉「今日 5 首」这类冗余信息：当前一首 + 下一首足够
- **声音开关**：`Speech.stop()` 直接 `cancel()` 语音合成，暂停 / 停止后不会再有声音；
  播放栏只在队列真的还在跑时显示，读完或被停止立刻收起

**键盘也能用**：`空格` 暂停/继续、`←` 上一首、`→` 下一首、`Esc` 停止（均为无障碍辅助，界面上不显示文字）。

| 位置 | 形态 | 说明 |

| 今日任务卡 | 圆形 ▶ / ⏸ | 与右侧 0/5 圆环同族，画出来的圆同为 40px、中线齐平；▶ 图标框 17px |

## 🎨 配色（宋式美学保留，只提升对比度）

需求 16 的疑问是「对比度不足，要不要放弃宋式美学」——**答案是保留，只把颜色压深**。
宋代审美本来就讲究「天青、素绢、琥珀、朱砂、缃色」这套低饱和的传统色，
问题不在色相，而在**明度差不够**。做法：

| 角色 | 调整前 | 对比度 | 调整后 | 对比度 |
|---|---|---|---|---|
| 主色·雨过天青（文字压卡片） | `#4d7d74` | 4.59:1 | `#2f6055` | **7.11:1** |
| 次要文字·淡墨 | `#7b6d5e` | 4.93:1 | `#6b5c4d` | **6.38:1** |
| 正文·墨 | `#322a24` | 13.84:1 | `#241d18` | **16.46:1** |
| 白字压深青底（今日卡） | `#4d7d74` 底 | 4.47:1 | `#2f6055` 底 | **7.06:1** |
| 琥珀（复习标签） | `#c07a3a` | 2.96:1 | `#a55c19` | **4.15:1** |
| 朱砂（忘记按钮） | `#b8473d` | 4.53:1 | `#a83b32` | **5.17:1** |
| 缃色（进度环） | `#d9b566` | 2.39:1 | `#f0cd7c` | **4.69:1** |

底色 `#f8f4ea → #f6f1e3`（素绢略压深）、卡片 `#fffdf8 → #fffefa`（宣纸提亮，
现为 **90% 不透明** 的 `rgba(255,254,250,.90)`，压住素绢底而不显死白），
一深一浅把层次拉开。**色相一个都没换**，宋式那套「天青 / 素绢 / 琥珀 / 朱砂 / 缃色」原样保留。

底部播放栏沿用同一套色：深天青底（`#26514a → #1c3f38`）压一支缃色描金细线（`rgba(240,205,124,.34)`），
主播放键用缃色实底圆环（与 0/5 进度环同色），其余图标为浅描边式，层级分明又不跳出宋式调子。
键面的 ▶ 一律是空心描边三角，色取各自圆键的 `color`；主键暂停时整颗翻成纸底 + 深天青，
三角随之变深 —— 环与三角始终同色。

需要注意：`test/theme.test.js` 里锁定了这些色值，
**改色时请同步更新断言**，避免主题被无意改回低对比版本。

> 两条 `npm i` 分开写时，**后一条会清掉前一条**——因为这两个包没写进 `package.json`，

> ```
>

> `^22.22.2 || ^24.15.0 || >=26.0.0`，而 CI 镜像还是 Node 20：

> 锁 `^26` 后红绿不再随 jsdom 版本跳；将来升 Node 再同步放开。
>
> `test/run.sh` 在发现 jsdom 缺失时会自己临时装一次（同样用 `jsdom@^26`），
> 并在装完先 `require` 验证能加载；加载不了会直接停下说清原因，

关于 PWA 测试：

- 需要真实浏览器，依赖 `puppeteer`；未安装时自动跳过，不影响其它测试
- 覆盖 iPhone Safari、iPad、微信内置浏览器、安卓 Chrome、桌面 Chrome 五种环境
- 校验 iOS meta 标签、四种 `apple-touch-icon` 尺寸是否可访问、Service Worker 注册、**断网后主页面 / 小古文页 / 设置页 / 用户协议 / 隐私条款都能打开**、**中文字体断网仍可用**、诗题计算样式确实命中 `Poem Serif SC`、引导条按平台正确显示、弹层按钮是否被遮挡等
- **底部导航栏几何验证**：注入与真实播放栏同结构的导航栏后，断言设置页底部留白 ≥ 导航栏高度、页脚中心点不被它盖住
- **按钮两态计算样式回归**：▶ / ⏸ 是同一颗键的两种状态，靠 CSS `[data-on]` 切换。
  只看 DOM「有两个图标」查不出问题，这里在真实浏览器里量 `getComputedStyle`，
  断言任意时刻**只有一个图标可见**，并顺带断言页面底 `background-image` 为 `none`（无纹样）
- **搜索页的机上布局（Issue #69）**：搜索框真的渲染成 52px（布局高度等于视觉高度，
  四个角同半径）、候选下拉贴住框下沿（间隙 8px 以内）、候选行高 ≥ 44px、
  聚焦描边是天青而不是 UA 的黑框（`outline` 必须是 `none`，
  光晕是天青系且不是黑 —— 不写死用哪个 token，两个入口各用各的、都合法）；
  软键盘用**把 `visualViewport.height` 压小 336px** 来模拟 ——
  这正是键盘弹出时浏览器给页面的唯一信号 —— 断言整块贴到顶栏下方、
  键高写进 `--kb-space`、搜索框与整条候选下拉都落在键盘上方的可视区里、
  候选**压在结果列表上面**（在候选正中央做 `elementFromPoint`，命中的必须是候选）、
  下拉下方仍给结果卡片留出可见可点的一片、键盘弹着时候选比平时更矮；
  **三态逐条量**：有内容时失焦仍停在页顶、清空内容且没焦点后回到页面中心
  （量「框是否压回 `.search-hero` 这段的中线」，偏差 ≤ 2px）、
  点结果列表下方的空白收下拉、点搜索框自己不收；
  搜索框与第一张结果卡片的间距 ≤ 40px（不再是当年那一大段空白）

### 译文的取舍标准

**先说清楚：译文是本项目自拟的。** 白话译诗没有法定教科书版本 ——
教材本身只给原文和注释，市面上的《XX 全解》都是各家编者的演绎。
所以本库**不宣称「以某个版本为准」**，而是逐首标出真实可追溯的口径，
界面译文框下方照实显示，用户不必猜。

四类口径（`data/index.js` 的 `TRANSLATION_SOURCES`，取值写在每首的 `translationSource`）：

| 取值 | 含义 | 篇目数 |
|---|---|---|
| `school` | 依据统编版教材与教师用书课后释义 | 208 |
| `academic` | 依据《唐诗鉴赏辞典》《宋词鉴赏辞典》等工具书的通行讲法 | 61 |
| `public-domain` | 原文属公有领域，依据公认注本与通行译注 | 100（小古文） |
| `modern` | 依据现行通用选本与通行讲法 | 4 |

> **没有把任何一家的译文逐字搬进来**。教材配套教参受版权保护，
> 逐字进仓库有风险；本库只借「口径」与「讲法」，文字是自己写的。
> 想核对具体某一句，请以孩子课本、老师的讲法为准。

写法上守住四条：

- **白话直译为主，必要处意译**：先保证字词句一一对应，读得懂；
  典故、双关（如「道是无晴却有晴」）再加一句点破
- **不加教材之外的引申与评价**：不写「表达了作者……的思想感情」这类赏析，
  那些交给老师讲，App 只负责把字面意思说清楚
- **不替用户决定背还是读**：译文只是帮读懂的辅助，展开折叠由用户点
- **长度与原文相称**：短诗译文不该比原文还短（`test/scheduler.test.js` 会拦）

补标注用 `scripts/tag-translation-source.js`（幂等，只补缺的、不覆盖手写的）：

```bash
node scripts/tag-translation-source.js --dry   # 先看会改哪些
node scripts/tag-translation-source.js         # 写回数据文件
```

`node scripts/audit-translations.js` 会连标注一起体检：缺译文 / 译文过短 /
译文抄原文 / **没标来源 / 标了不认识的取值**，任何一项不达标都退出码 1。

### 字体：自托管思源宋体 / 黑体

- **诗词的标题、朝代、作者、正文**统一使用 **Noto Serif SC（思源宋体）**——宋体本就源于宋代刻本，横细竖粗、笔画有顿挫，最贴合线装书里的诗
- 其余界面文字用 **Noto Sans SC（思源黑体）**打头
- 字体放在 `fonts/` 目录**自托管**，不请求任何第三方 CDN：
  - 按本站实际会用到的 **4524 个字形**（界面文案 + 课内诗词 + 小古文 + 唐诗 + 宋词
    + 古文观止已收录篇目 + 全部白话译文）做了子集化，四个文件共约 **6.7 MB**
  - 每次新增诗词 / 译文都要**同步补字体**，否则新字的笔画会被吃掉：
    `scripts/supplement-fonts.py` 会扫描 `data/` 下全部诗词与小古文数据 +
    全部页面 / 脚本 / 样式（**译文里的字也算**），界面上出现的字一个不漏
  - 脚本走「**只增不减**」的路子：老字形原样保留，只把缺的字从 Noto 源字体
    取轮廓补进去。因为目标是 CID-keyed CFF（字形名必须是 `cidNNNNN` 且 ≤ 65535，
    而原字体 CID 稀疏、最大已到 65530），补完会把全部字形重排成连续编号
  - 加译文那次一口气补了 **116 个新字**（亘、仑、仕、佝、锻、酋、鲛 …）
  - 后来加译文来源注脚时又补了 **2 个**（幂、绎）—— 这类界面小字也算站点用字，
    漏了同样会吃掉笔画，所以改文案后照样要跑一遍补字脚本
  - 每次补完都用 fontTools 逐字核过轮廓（不是空白也不是方块），
    再跑 `node test/theme.test.js` 拿站点全部用字复核
  - 子集「只多不少」：漏字会表现为字被吃掉半边（如「用户协议」显示成「用户」），
    `test/theme.test.js` 会**拿站点全部 4524 个用字**逐字读 cmap 校验覆盖度
    （此前只抽查几个固定词，查不出新增译文带来的缺字）
  - 宋词 + 古文观止入库那次又补了 **753 个新字**（蝉、鬓、纨、萼、繇 …）
  - 昭明文选入库那次补了 **2403 个字**；随后《子虚赋》《吴都赋》那批
    鸟兽名、地名又带出 **183 个字**（𠆩、𡶒、𩨒、𪃩 …），
    这些是 **United Ideographs Extension B**（U+20000 起）的扩展区字，
    **Noto CJK 全系列都没有字形** —— 连 44810 字的 NotoSansCJKsc 也只覆盖到 10 个。
    改用公开领域的**花園明朝**（HanaMin，ExtB/d 分片）逐字取轮廓补进四款子集
  - 现在全站用字**零缺字**：`test/theme.test.js` 的断言已从
    「缺字总数 ≤ 90」收紧成 **「一个都不能缺」**
  - ⚠️ 扫描口径必须带上扩展区（U+20000–U+2FA1F）。曾经两处都只扫 BMP，
    导致扩展区缺字查不出来：`scripts/supplement-fonts.py` 的 `CJK_RE`、
    以及 `test/theme.test.js` 里那段 python 的扫描正则
    （后者更隐蔽：写在 JS 模板字符串里，`\U` 被 JS 先吃掉，
    python 收到的是字面量 `U00020000`，于是扩展区一个字也扫不到，
    「缺 28 字」就这么空转了整整一轮，实际页面缺 183 个字）
  - 极少数生僻异体字（如「煣」）Noto 与花園明朝都没有，脚本会明确列出来；

## 💡 设计说明

- **为什么要"不点击就只显示诗名"**：先给孩子回忆的机会，避免直接看到正文产生依赖，符合"主动回忆"的记忆原理。
- **为什么要如实评价掌握程度**：记忆曲线的排期完全依赖真实反馈。忘记却选"记住"，会导致间隔拉得过长而彻底遗忘。
- **为什么跨年级复习**：已经学过的诗即使升了年级也要按期复习，因此到期诗会在任意年级的任务列表中出现，保证不遗忘。
- **为什么默认只背本册**：先跟着课内进度走，需要时再用「背诵范围」扩到之前学期或整段学段。
- **为什么小古文单独开一个页面**：篇幅长（手机上卡片弹窗装不下）+ 不想占用每日任务名额，所以独立成 `/classic/`，逐篇列出点击进入阅读，读完打个「已读」标记。这纯粹是排版与入口安排，应用不对「背还是读」作任何引导。

## 🔒 关于数据与隐私

- 所有学习进度与用户名只存在**本机浏览器**（localStorage），不上传任何服务器
- 无账号、无统计脚本、无第三方请求，断网可用；打开页面不会向外发任何数据
- 想在手机和电脑之间同步，可用设置里的「导出备份 / 导入备份」
- 页脚常驻「用户协议」「隐私条款」两个入口，条款针对**学生保护**（不收集儿童个人信息、
  不填真实姓名、控制使用时长）与**所有者免责**（按现状提供、数据自理、不承诺成绩）写明了边界
- 联系邮箱不会以明文出现在源码/HTML 里：由 `js/contact.js` 在运行时拼装，
  页面默认只显示「显示邮箱地址」，点击复制。这样搜索引擎与爬虫抓不到地址，
  真人一到两步就能拿到（详见该文件顶部注释）

### 底部导航栏不遮挡内容

底部导航栏（朗读播放栏 `#reader-player`）高度是浮动的：按钮行高、iPhone 横条安全区都会影响它。
页面自己写死 `padding-bottom` 就会在窄屏上差几像素，把「忘记 / 模糊 / 记住」或页脚压住一点。因此：

- `js/pwa.js` 的 `syncBottomGap()` 实测导航栏高度（底部页签与播放栏取较高者 + iOS 引导条），
  写进 CSS 变量 `--nav-h`
- 页面留白、iOS 引导条、吐司提示全部按 `--nav-h` 这条基准线避让，不再写死 86 / 96 / 150 / 196px
- 没有底部导航栏时 `--nav-h` 为 0，页面不会多出一段空白条
- 设置页底部常驻版权与两个法务链接，任何底部导航栏都压不到它
- `test/pwa.test.js` 用真实浏览器做几何断言：注入播放栏后，页脚中心点不能被它盖住
