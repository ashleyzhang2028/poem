# 跬步 · 古诗词背诵

面向小朋友的**古诗文复习与背诵**应用。覆盖**小学一年级到高中三年级**（人教/统编版教材）共 **242 首**古诗文；
另设独立的**小古文**学习库（100 篇，想读哪篇点哪篇，可注音、朗读、随机连读）。

> 应用正式名称为 **跬步**（kuibu.app）。填了用户名后标题显示为「跬步 · 小明的古诗词」。

纯前端单页应用（PWA），**打开即用、无需注册、可离线**，所有学习进度保存在手机/电脑本机浏览器里。

支持**电脑、安卓手机、苹果手机（iPhone / iPad）**；苹果手机上可通过 Safari「添加到主屏幕」当独立 App 使用。

## 📚 两类内容，两套用法

| 内容 | 数量 | 使用方式 | 入口 |
|---|---|---|---|
| 课内古诗文（含长文言文） | 242 首 | 按遗忘曲线排每日任务，点击背诵 | 首页「今日背诵」 |
| 小古文 | 100 篇 | **只列出来，点击学习，不排复习** | 首页「本年级本学期全部诗词」下方的「小古文」卡片 |

为什么小古文要单独一套：
- **篇幅长**：小古文动辄上百字，手机上卡片式弹窗装不下，所以阅读改成**整页阅读器**，可以一路滚下去
- **目标不同**：古诗词求「背下来」，小古文求「读懂」，用同一套遗忘曲线一天排几篇并不合适
- **不打扰主线**：小古文独立成页 `classic.html`，有自己的「已读」标记（与古诗词进度互不干扰），不会占用每日 5 首任务的名额

## ✨ 核心功能

### 1. 在设置里改用户名 + 选年级学期
- 「用户名」输入框：填谁的名字，顶栏第一行显示为「**跬步 · XX的古诗词**」
  - **留空则用默认名 Ashley**，不会出现空档：首页永远显示「跬步 · Ashley的古诗词」
  - 默认名走淡墨，与用户自己填的名字在视觉上区分开
  - 页面标题与 iOS 主屏幕应用名同步为「跬步 · XX的古诗词」
  - 最长 12 个字，边输入边生效，无需保存按钮
- 年级/学期选择收进右上角设置弹层，首页不再常驻显示
- 设置内按「小学 / 初中 / 高中」分学段，再选具体年级

### 1.5 导航：一套顶栏 + 底部三个页签

三页（首页 / 小古文 / 法务页）原先各写一份顶栏，标题、返回键、右侧按钮都不一样，
容易「不知道自己站在哪一页」。现在统一成一套：

- **顶栏第一行永远是「徽标 + 跬步 · 页面名」**，全站一致；
  徽标是篆意「步」字印（上「止」下反「止」），页面名与「跬步」**同字号、同字重、同一行**，
  中间的「·」由 CSS `::before` 生成（页面里不写死标点）
  - 首页：`跬步 · Ashley的古诗词`；小古文页：`跬步 · 小古文`；法务页：`跬步 · 隐私条款` / `跬步 · 用户协议`
- **顶栏第二行是「这一页是干什么的」**，由各页在 `<body>` 上写 `data-sub` 给出，不硬编码在 JS 里：
  - 首页：`按遗忘曲线安排复习 · 小古文想读哪篇点哪篇`
  - 小古文页的说明已写进第一行（`跬步 · 小古文`），第二行留空即自动不占高度
  - **刻意不写「一年级至高三」这类学段字样**：首页能自己选年级学期，
    固定写死一个学段反而让非该学段的用户觉得不是给自己用的
- **顶栏右侧一个动作位**：首页**留空**（设置交给底部页签，不再重复放一个齿轮），
  内页是「回首页」，阅读器打开时变成「关闭」；
  **小古文阅读器左上角的返回键就是同一颗按钮**（同样的 40px 圆形纸底、同一笔画粗细、
  同一 `.top-act` 样式），里面只有一个箭头，不再叠「小 古 文」三个字
- **底部三个页签：古诗词 / 小古文 / 设置**，页面之间统一从这里跳转；
  小古文页也有自己的设置面板（用户名 / 阅读辅助），不必退回首页
- 法务页（用户协议 / 隐私条款）是深页，不显示页签，只用顶栏返回

> 页面图标（徽标、书本、古卷、设置、播放键）均为内联 SVG，不依赖系统 emoji 字体，跨设备显示一致。

### 1.6 宋式纹样与按钮分级

- **纹样**（内联 SVG data URI，不请求图片、断网也在）：
  - **大背景 = 宋「祥云纹」（祥云 / 云卷）**：一朵祥云由云头（三叠云肩 + 平云脚）
    与中心一枚「云卷」螺旋组成 —— 云卷是祥云纹区别于其他云纹的关键：
    外圈顺着向内一路卷进去，正是宋人织锦、漆器与《营造法式》彩画上
    「祥云朵朵」的写法，取「祥云瑞气、从容不迫」之意。
    由两组祥云（80×80）+ 一枚云纹团花（320×320）叠成循环大纹样，
    不透明度 **4%~13%**，核心是「螺旋云卷 + 三叠云肩」——
    静看是一张有暗花的宋锦，退开一臂远只剩纸的温度
    （历次大背景：落花流水纹 → 球路纹 → 如意云头纹 → 祥云纹）
  - 云纹 / 角隅：同步调淡到 8%~17%，只在角落「露一角」
  - 只在角落「露一角」，不支持 `mask` 的浏览器自动不出，不影响布局
- **卡片背景 95% 不透明**：卡片 / 列表项 / 弹层统一为
  `rgba(255,254,250,.95)`，留 5% 让底部祥云纹隐隐透出 ——
  既有纸的厚度，又不把新纹样完全盖死。
- **按钮分四级**：一级（天青实底 + 描金内边）/ 二级（宣纸底 + 天青描边）/
  三级（只留一条界行细线）/ 危险（朱砂，仅用于「清空进度」）

> 三页的顶栏与页签由 `js/chrome.js` 统一渲染，样式在 `css/style.css` 末尾的「全站导航」一节；
> 各页面只需在 `<body>` 上写 `data-nav` / `data-page` / `data-dock` 说明「我是哪一页」。
>
> 诗词的标题 / 朝代 / 作者 / 正文统一使用**自托管的思源宋体**，图标与评价按钮也全部是内联 SVG，
> 因此苹果、安卓、Windows 上看到的是同一套字形，不会出现 emoji 豆腐块。
- 一键切换「上学期 / 下学期」，只看当前进度对应的教材内容
- 「背诵范围」7 选 1，决定每日任务从哪些内容里抽：

| 选项 | 含义 |
|---|---|
| 本册 | 当前年级 + 当前学期（默认） |
| 本册及之前 | 当前年级当前学期 + 此前所有学期 |
| 小学随机 | 小学 1~6 年级任意学期随机 |
| 初中随机 | 初中 7~9 年级任意学期随机 |
| 小学+初中随机 | 小学与初中任意学期随机 |
| 高中随机 | 高中 10~12 年级任意学期随机 |
| 全部随机 | 全部阶段任意学期随机 |

  - 随机范围每天重新洗牌，同一天内刷新页面保持不变
  - 每日任务从范围内取；范围外已学过且到期的诗仍会排入复习，避免遗忘

### 2. 每日 5 首背诵任务（可调 3/5/8/10 首）
每次进入应用，自动列出**今天要背的诗词名称**（默认 5 首）：

- 🟠 **复习** —— 按记忆曲线到期、今天必须回顾的诗
- 🟢 **新学** —— 还没学过的诗，逐首补齐

不点击就只是"今天要背这 5 首"的清单；**点击某一首**才会展开：

- 诗题
- **作者**
- **朝代**
- 完整正文（保留原文换行、宋体展示，适合跟读）

### 3. 遗忘曲线记忆法自动排期
点开诗词后，如实选择自己的掌握程度，系统自动算出下次复习时间：

| 选择 | 效果 |
|---|---|
| 😄 记住 | 升级到下一记忆阶段，间隔翻倍 |
| 🤔 模糊 | 停留当前阶段，**12 小时**后再复习 |
| 😵 忘记 | 降级一级，**30 分钟**后立刻重来 |

复习间隔序列（天）：

```
当天 → 1 → 2 → 4 → 7 → 15 → 30 → 60 → 120 → 240
```

规律即"先密后疏"：刚记住时反复得快，越牢固间隔越长，用最少次数把诗记进长期记忆。

### 4. 进度可视化
- 今日环形进度（已完成 / 总数）
- 每首诗的记忆阶段与掌握度进度条
- 「本年级本学期全部诗词」折叠面板：诗词总数 / 已学 / 较牢固 / 待复习（选随机范围时改为显示该范围全部诗词）
  - 折叠箭头是**空心描边三角**（内联 SVG），与列表右侧的 `›` 同一套描边语言、同一淡墨色；
    收起朝下、展开靠 CSS 旋转 180° 朝上，不再用实心 `▾` 那种另一套风格的字形
- 小古文学习库（不占每日任务名额）从**底部页签「小古文」**进入；
  首页不再单放一张入口卡片（与页签重复，已删除）

### 4.5 诗词详情页（与小古文对齐的阅读工具条）

课内诗词的详情弹层，现在与小古文阅读器用**同一套控件、同一顺序**，用户在两个页面不用重新学一遍：

| 行 | 控件 |
|---|---|
| 第一行 | `正文对齐`（左 / 中 / 右 SVG）· `A－ / A＋` 组合（五档 15 / 17 / 19 / 21 / 23，**古诗默认 17px**，比小古文再小一号）· `不注音 / 生字 / 全文` |
| 第二行 | `正文朗读`（**一个** ▶ / ⏸ 播放键，同键两态）· 译文开关（SVG 圆形图标） |

- **白话译文**：与小古文同一套译文框，默认折叠、点译文图标展开；
  展开后译文标题右侧出现它**自己那一颗**朗读键，可只读译文
- **同一篇只有一个播放信号**：▶ 与 ⏸ 是同一颗键的两种状态，播放中在原地换成暂停；
  译文那颗键跟着译文框出现 / 消失，不再出现「原文、译文两个播放键并排、不知道点哪个」
- **与小古文的唯一差别**：这里**不设「已读」按钮** —— 掌握程度由「忘记 / 模糊 / 记住」评价，比一个已读勾更有意义
- **不再被底部页签压住**：弹层高度扣掉 62px 页签与安全区，**底部内边距再垫出同样的 62px**，
  最下面的「忘记 / 模糊 / 记住」整排落在页签上方，完整可见、可点
  （法务页等没有页签的深页不受影响；设置面板走内容自适应高度，只避让 iPhone 底部横条）
- 字号与对齐都记在本机（`poem_font_v1` / `poem_align_v1`），翻篇、重进都在

## 🚀 使用方法

### 方式一：直接打开
用浏览器打开根目录的 `index.html` 即可。

### 方式二：本地起服务（推荐，避免个别浏览器 file:// 限制）
```bash
# Python 3
python3 -m http.server 8080
# 然后访问 http://localhost:8080
```

### 方式三：手机上使用

把整个目录放到任意静态服务器（GitHub Pages / CNB Pages / Nginx 均可），用手机浏览器打开即可。
应用已内置 PWA 能力，**安装到桌面后可以离线背诵**（首次打开需联网加载一次）。

#### 🍎 苹果手机 / iPad（iPhone / iPadOS）

iOS 不会弹「安装」按钮，需要手动添加到主屏幕，步骤：

1. 必须用 **Safari** 打开应用地址
   （微信 / QQ / 钉钉等 App 内置浏览器都不支持「添加到主屏幕」，应用会自动提示您改用 Safari）
2. 点屏幕**底部中间的「分享」按钮**（方框 + 向上箭头 ⬆️）
3. 在弹出的菜单中向下滑动，选择 **「添加到主屏幕」**
4. 右上角点 **「添加」**

完成后桌面会出现「跬步」图标（设了用户名则显示「跬步 · XX的古诗词」），点开即为**全屏运行**，没有 Safari 地址栏和工具栏，体验与原生 App 一致。

针对 iOS 已做的适配：

| 项目 | 说明 |
|---|---|
| `apple-mobile-web-app-capable` | 从主屏幕启动时全屏运行，不显示浏览器界面 |
| `apple-mobile-web-app-status-bar-style` | 状态栏样式适配，内容不被状态栏遮挡 |
| `apple-touch-icon` ×4 | 提供 120 / 152 / 167 / 180 四种尺寸，覆盖 iPhone、iPad、iPad Pro，图标清晰不模糊 |
| `viewport-fit=cover` + `env(safe-area-inset-*)` | 适配刘海屏、灵动岛与底部横条，内容不被遮挡 |
| Service Worker | 首次打开后缓存全部资源，**断网也能正常背诵** |
| 输入框 16px | 避免 iOS 聚焦输入框时页面自动放大 |
| 弹层避让 | 弹层打开时自动隐藏安装引导条，不会挡住操作按钮 |

#### 🤖 安卓手机

用 Chrome / Edge 打开，浏览器若支持会提示「安装应用」；也可在菜单中选择「添加到主屏幕」。

#### 💻 电脑

浏览器直接打开即可；也可在浏览器地址栏右侧点安装图标，装成独立窗口应用。

## 📖 小古文（`classic.html`）

### 标题与副标题

- 页面主标题：**跬步 · 小古文**（与首页同一套「跬步」品牌；填过用户名时为「跬步 · 小明的古诗词 · 小古文」）

### 页面交互

- **列表**：按主题分类聚合；搜索框（篇名 / 出处 / 作者）+「全部 / 未读」**组合按钮**筛选（同一时刻只有一个选中态），分组标题带篇数，每组右侧有「随机连读」
- **点击**：打开**整页阅读器**（不是卡片弹窗），长文整屏滚动，一眼看到底
- **单项播放**：每行右侧一个圆形 **▶ 播放键**，点一下直接读这一篇，再点一次停止（不用先进阅读器）
- **标题与副标题**：与首页同一套顶栏 —— 第一行「跬步 · 小古文」，下面补一句副标题「小古文 · 想读哪篇点哪篇」
  （填过用户名时为「跬步 · 小明的古诗词 · 小古文」，iOS 桌面名同步）
- **阅读器阅读辅助（两行，每行都排成一行）**：
  - **上一行**：`正文对齐`（左 / 中 / 右 三个 SVG 图标）+ `A－ / A＋` 组合按钮（五档 15 / 17 / 19 / 21 / 23，**默认 17px**）+ `不注音 / 生字 / 全文` 组合按钮
  - **下一行**：**正文朗读键**（**一个** ▶ / ⏸，同键两态）+ **译文开关**（SVG 图标）+ **✓ 标记已读**，整行**水平居中**
    - 正文键读标题 + 朝代 + 作者 + 正文；▶ 与 ⏸ 是**同一颗键的两种状态**，
      播放中在原地换成暂停，绝不是两个图标并排
    - 译文那颗朗读键放在**译文框的标题右侧**，跟着译文框一起出现 / 消失，
      一篇文章任何一个时刻只看得到一个播放信号
  - 译文开关与「标记已读」是方形图标按钮，图标**真正水平 + 垂直居中**
    （flex 居中 + `line-height: 0`，压掉 SVG 作为行内元素时的基线留白）
- **正文对齐**：左 / 中 / 右三个 SVG 图标，用户自己选，选择记在本机（`poem_classic_align_v1`）；
  两个工具条（第一行 对齐/字号/注音，第二行 正文播放键/译文开关/已读）都整行居中，与正文同一条中轴
  - 古诗短句**默认居中**（像碑帖）；《少年中国说》《古人谈读书》这类长古文**切左对齐**更好读
  - 右对齐时文字靠右，正文块仍保持居中不越界
- **翻篇**：阅读器底部有**上一篇 / 下一篇**（带目标篇名），读完直接翻，不必退回索引页；到头时按钮禁用并提示
  - 导航底部预留 `118px + 安全区` 的空白，不会被底部播放栏 / 页签压住（此前被压掉约三成、点不着），
    阅读器打开时底部页签自动收起
- **随机连读**：索引页顶部或分组上的「随机连读」= 随机抽一篇开读，读完自动跳下一篇，可暂停 / 继续 / 停止
- **进度**：只记「已读 / 未读」，存在 `localStorage` 的 `poem_classic_read_v1`，与古诗词复习进度完全独立
- **离线**：Service Worker 已把 `classic.html`、样式、脚本、100 篇数据一起预缓存

### 和每日任务的关系

小古文**不进**遗忘曲线调度：`js/scheduler.js` 只认 `window.POEMS_ALL`（242 首），
小古文放在 `window.POEMS_CLASSIC`，两边数据互不污染，所以每日 5 首不会混进小古文。

## 🔊 生字注音与朗读

给小朋友解决两个卡点：**不认字**和**不会读**。

### 生字注音

- **在哪用**：课内诗词详情弹层、小古文整页阅读器，都有一组「不注音 / 生字 / 全文」三档按钮
- **默认「生字」档**（即原来的「只标生字」）：只给小朋友可能不认识的字压拼音，页面清爽。
  命中条件有两个，满足其一即注音：
  1. **生字** —— 不在 `data/common-chars.js` 的前 2500 字里（约等于小学阶段识字量）
  2. **多音字** —— 即使字很常见（`曲 / 还 / 间 / 行 / 少`）也照标，因为小朋友最容易读错，
     不标就会出现「整首诗一个字拼音都没有」的空档
  标出的字约占正文 **17%** —— 是「生字」，不是「全文」
- **「全文」**：给刚识字、需要全量辅助的小朋友，逐字标注
- **怎么实现**：`<ruby>` 把拼音压在汉字上方，标点与换行原样保留；正文本身不被改动
- **状态持久化**：档位记在 `localStorage`（`poem_helper_pinyin_v1`），旧版布尔值自动迁移（`1`→生字、`0`→关闭）
- **数据来源**：`data/pinyin-table.js` 收录 **2515 个汉字**，覆盖课内 242 首 + 课外 100 篇里出现的**全部**汉字，构建期用 `pinyin-pro` 离线生成；
  常用字表 `data/common-chars.js` 由 `jieba` 字频表导出前 2500 字。两份表都是只读数据，运行时**不依赖任何第三方库**
- **多音字**：值含斜杠表示多音（如 `曲:qū/qǔ`），`js/pinyin.js` 按上下文选读音：
  1. 先查内置词表（`曲项`→qū、`绿水`→lǜ、`一水间`→jiān、`应怜`→yīng、`知者乐水`→yào …）
  2. 再按变调规则处理「一 / 不」（见下）
  3. 都判定不了时取第一个读音（也是现代最常用读音）
- **「一 / 不」变调**（按普通话规则，不是简单取首读音）：
  - `不`：去声前读 `bú`（不尽 bú jìn），其余读 `bù`（不能 bù néng）
  - `一`：去声前读 `yí`（一片 yí piàn），阴平/阳平/上声前读 `yì`（一行 yì háng），
    序数或词尾读本调 `yī`（第一 dì yī、一九 yī jiǔ）
  - 词表里遇到「一 / 不」不直接返回，交给变调规则裁决，避免硬编码错调

> 拼音表是**只读数据**，不改动诗词正文，正文里不会混入拼音字符。

### 总开关：阅读辅助

设置里的「阅读辅助」开关是**总开关，也是权威**——课内弹层与小古文阅读器都听它的：

| 状态 | 打开一首诗 / 一篇古文时 |
|---|---|
| 开启（默认） | 正文按**当前注音档位自动注音**（出厂档位「生字」），随时可手动切档 |
| 关闭 | 正文**一律纯文本**，无论此前存过什么档位 |

- 注音共三档：**不注音 / 生字（默认）/ 全文**，弹层与阅读器里都能直接切
- **总开关与档位始终一致，不会打架**：
  - 在设置里关掉「阅读辅助」→ 即使 `poem_helper_pinyin_v1` 里残留着「全文」档，正文也是纯文本
  - 在弹层 / 阅读器里手动选「生字 / 全文」→ 自动把「阅读辅助」打开（设置面板里的按钮同步变亮）
  - 在弹层 / 阅读器里手动选「不注音」→ 自动把「阅读辅助」关掉
- 关闭后再打开，不必刷新页面：首页立即重渲染当前这首，小古文页监听 `storage` 与 `pageshow` 事件同步
- 朗读按钮两种状态下都可用（朗读必须由用户手势触发，本就不做自动播放）

## 🔁 自动朗读（不看手机也能听）

给「一边做事一边听」这个场景做的整套能力，全部基于系统语音，零音频文件、断网可用。

| 入口 | 行为 |
|---|---|
| 今日任务卡右侧的 **▶ 圆形播放键** | 依次朗读当天每一首，读到哪首，列表里那首自动高亮滚动 |
| 今日列表每首右侧的 **▶ 播放键** | 只读这一首，再点一次停止 |
| 小古文列表每篇右侧的 **▶ 播放键** | 只读这一篇，再点一次停止 |
| 小古文索引页 / 分组「**随机连读**」 | 随机抽一篇开读，**读完自动跳下一篇**并打开阅读器，列表同步高亮 |
| 详情页（诗词弹层、小古文阅读器）的「**▶ 播放键**」 | 只读当前这篇，播放中变 ⏸，**暂停中仍是 ⏸**，点一下停止（不会叠一层朗读） |
| 小古文阅读器的「**译文朗读**」 | 只读白话译文，不读原文（译文框里那颗 ▶ / ⏸，同键两态） |

朗读内容统一为：**标题 → 朝代 → 作者 → 正文**。

**朗读状态怎么判断（`Speech.active()`）**

界面按钮的文案（朗读 ↔ 停止）只认一件事：**现在有没有朗读任务在跑**。判断口径分三层：

1. `Speech.active()` 为真 —— 队列还在跑（含暂停）；
2. 单条朗读（阅读器「朗读 / 译文朗读」、列表播放键）单独记一个「暂停标记」，
   因为**部分设备 `pause()` 之后 `synth.speaking` 会变成 false**，只看引擎状态会误判成「已经读完了」；
3. 一条读完后的极短时间（600ms）内仍算「任务在跑」，按钮不会在收尾瞬间来回跳。

这样可以保证：**暂停中按钮仍显示「停止」，再点一次就是停下来**，
而不是重新叠一层朗读（曾经的问题：暂停后点「朗读」会重头再读一遍，
「显示译文 / 隐藏译文」「译文朗读」跟着错乱）。

> 实现细节见 `js/speech.js`：`active()` / `singlePaused` / `singleEndedAt`，
> 以及阅读器里的 `readingActive()` 与 `handleSpeechStopped()`。

**底部播放栏（宋式美学 · 音乐播放器）**

朗读开始后从底部**弹出播放栏**，占满整个底边宽度、**没有圆角、没有 margin 浮起**，
高度加大，深天青底 + 一支缃色描金细线，像手机底部弹出的播放器：

- 左侧大字是**当前这一首**（播放中前面有一缕缃色游标轻轻呼吸），
  下面一行小字「**下一首 · 江南**」——下一首的图标一激活，用户就知道该听哪首
- 右侧 4 个圆形图标按钮：**上一首 / 播放·暂停 / 下一首 / 停止**，
  全部是内联 SVG，**不出现「正在朗读 / 暂停 / 继续 / 下一篇 / 停止」任何文字**
- 播放键用缃色（与 0/5 进度环同色）做视觉重心；暂停时换成 ▶，一眼看出点它能继续
- 已去掉「今日 5 首」这类冗余信息：当前一首 + 下一首足够
- **声音开关**：`Speech.stop()` 直接 `cancel()` 语音合成，暂停 / 停止后不会再有声音；
  播放栏只在队列真的还在跑时显示，读完或被停止立刻收起

**键盘也能用**：`空格` 暂停/继续、`←` 上一首、`→` 下一首、`Esc` 停止（均为无障碍辅助，界面上不显示文字）。

**图标按钮一览**

| 位置 | 形态 | 说明 |
|---|---|---|
| 今日任务卡 | 圆形 ▶ / ⏸ | 与右侧 0/5 圆环同族，尺寸同为 46px |
| 今日列表每行右侧 | 圆形 ▶ / ⏸ | 播放中变成 ⏸，点即停 |
| 小古文列表每行右侧 | 圆形 ▶ / ⏸ | 天水碧配色 |
| 底部播放栏 | ▶ / ⏸ + ⏮ / ⏭ / ⏹ | 纯图标，无文字 |
| 详情页（诗词 / 古文） | 圆形 ▶ / ⏸ | 与列表、播放栏同款图标，不再出现「小喇叭 + 朗读」文字 |

> 语音引擎没有「朗读整篇」的接口，所以队列是自己按条推进的：
> 一条读完触发 `onend` 再读下一条。因此**暂停发生在两条之间更稳**，
> 个别设备上 `speechSynthesis.pause()` 无效时，表现为当前这条读完后停住。

## 🎨 配色（宋式美学保留，只提升对比度）

需求 16 的疑问是「对比度不足，要不要放弃宋式美学」——**答案是保留，只把颜色压深**。
宋代审美本来就讲究「天青、素绢、琥珀、朱砂、缃色」这套低饱和的传统色，
问题不在色相，而在**明度差不够**。做法：

| 角色 | 调整前 | 对比度 | 调整后 | 对比度 |
|---|---|---|---|---|
| 主色·雨过天青（文字压卡片） | `#4d7d74` | 4.59:1 | `#2f6055` | **7.11:1** |
| 次要文字·淡墨 | `#7b6d5e` | 4.93:1 | `#6b5c4d` | **6.38:1** |
| 正文·墨 | `#322a24` | 13.84:1 | `#241d18` | **16.46:1** |
| 白字压深青底（今日卡） | `#4d7d74` 底 | 4.47:1 | `#2f6055` 底 | **7.06:1** |
| 琥珀（复习标签） | `#c07a3a` | 2.96:1 | `#a55c19` | **4.15:1** |
| 朱砂（忘记按钮） | `#b8473d` | 4.53:1 | `#a83b32` | **5.17:1** |
| 缃色（进度环） | `#d9b566` | 2.39:1 | `#f0cd7c` | **4.69:1** |

底色 `#f8f4ea → #f6f1e3`（素绢略压深）、卡片 `#fffdf8 → #fffefa`（宣纸提亮，
现为 **95% 不透明** 的 `rgba(255,254,250,.95)`，让底部祥云纹隐隐透出），
一深一浅把层次拉开。**色相一个都没换**，宋式那套「天青 / 素绢 / 琥珀 / 朱砂 / 缃色」原样保留。

底部播放栏沿用同一套色：深天青底（`#26514a → #1c3f38`）压一支缃色描金细线（`rgba(240,205,124,.34)`），
播放键用缃色实心（与 0/5 进度环同色），其余图标为浅描边式，层级分明又不跳出宋式调子。

需要注意：`test/theme.test.js` 里锁定了这些色值，
**改色时请同步更新断言**，避免主题被无意改回低对比版本。

## 💡 设计说明

- **为什么要"不点击就只显示诗名"**：先给孩子回忆的机会，避免直接看到正文产生依赖，符合"主动回忆"的记忆原理。
- **为什么要如实评价掌握程度**：记忆曲线的排期完全依赖真实反馈。忘记却选"记住"，会导致间隔拉得过长而彻底遗忘。
- **为什么跨年级复习**：已经学过的诗即使升了年级也要按期复习，因此到期诗会在任意年级的任务列表中出现，保证不遗忘。
- **为什么默认只背本册**：先跟着课内进度走，需要时再用「背诵范围」扩到之前学期或整段学段。
- **为什么小古文单独开一个页面**：篇幅长（手机上卡片弹窗装不下）+ 目标不同（读懂 ≠ 背熟）+ 不想占用每日任务名额，所以独立成 `classic.html`，只列出来点击学习，读完打个「已读」就好。

## 🔒 关于数据与隐私

- 所有学习进度与用户名只存在**本机浏览器**（localStorage），不上传任何服务器
- 无账号、无统计脚本、无第三方请求，断网可用；打开页面不会向外发任何数据
- 想在手机和电脑之间同步，可用设置里的「导出备份 / 导入备份」
- 页脚常驻「用户协议」「隐私条款」两个入口，条款针对**学生保护**（不收集儿童个人信息、
  不填真实姓名、控制使用时长）与**所有者免责**（按现状提供、数据自理、不承诺成绩）写明了边界
- 联系邮箱不会以明文出现在源码/HTML 里：由 `js/contact.js` 在运行时拼装，
  页面默认只显示「显示邮箱地址」，点击复制。这样搜索引擎与爬虫抓不到地址，
  真人一到两步就能拿到（详见该文件顶部注释）
