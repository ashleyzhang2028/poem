# 事件上报怎么加、怎么设计（Issue #535）

> 需求方 2026-10-10：「给『开始连读』『切换集子』等动作加 `gtag('event', …)`。
> 这个怎么加，如何规划和设计」

先说结论：**base tag 只管 page_view，事件是另一层**。这一层不是「把 gtag 塞进
各处点击里」，而是先定一张**事件表**，再决定它**由谁上报、在哪儿上报、报失败了
怎么办**。下面按这三步来。

---

## 一、先划边界：什么该报，什么不该报

上报是「问产品问题」。没想清楚要问什么就先埋点，出来的是一堆没人看的数字。
所以先列她真正想知道的：

| 想知道的 | 对应的问题 |
|---|---|
| 连读键按了没有、按了多长 | 这个功能有人用吗？按了却没读起来的是不是很多？ |
| 从哪个集子切到哪个集子 | 哪些集子是真入口，哪些只是摆设？ |
| 一篇读完之后往下翻还是退出去 | 内容撑不撑得住「一篇接一篇」？ |
| 搜索、未读筛选用得凶不凶 | 列表上的控件值不值得留在第一屏？ |

反过来，**有意不报**的四类，都在源码里写了原因：

1. **不报「连读结束」**（只有开始与中途按停）。连读结束有三种由头 —— 用户
   按停、播完了、读失败 —— 而播放器的 `onEnd` 对三者一视同仁。要分开就得从
   `js/speech.js` 再引一路状态上来，为一个统计维度不值。
2. **不报搜索词**。`query_length` 给的是敲了几个字，字本身不出站。隐私条款刚
   为 GA 改过一轮措辞，再把搜索词送出去就是另一回事了。
3. **不报「是否登录 / 哪个账号」**。统计里不带账号标识，隐私页那句话才说得住。
4. **不报内部动作**。翻页补记已读、跨设备同步回来，都不算「人按了」。

## 二、事件表

命名 `snake_case`，动词在后；参数一律是**有限取值的字符串**（不是自由文本），
这样在 GA 里才聚得成列。

| 事件名 | 什么时候 | 参数 |
|---|---|---|
| `play_start` | 连读键按下去、队列非空、真的开始读了 | `source` `mode` `source_view` `gradeGroup` `item_count` |
| `play_stop` | 连读中途按停 | `source` |
| `play_blocked` | 按了但被语音门挡住（要登录 / 浏览器不支持 / 有译文门槛） | `source` |
| `play_empty` | 按了但这一类没有可读篇目 | `source` `mode` `source_view` `gradeGroup` |
| `play_mode_switch` | 长按菜单里换了读法（原文 / 白话 / 随机…） | `mode` `source` |
| `read_start` / `read_stop` | 单篇朗读（阅读器那颗、列表行那颗） | `source_view` `source` `ok` |
| `nav_switch` | 页底「上一篇 / 下一篇」 | `direction` |
| `reader_open` / `reader_close` | 打开 / 关掉阅读器（连读翻页也会开到下一片） | `item` |
| `list_filter` | 「全部 / 未读」切换 | `filter` |
| `mark_read` | 手动标已读 / 取消 | `read` `source` |
| `daily_toggle` | 加入 / 移出今日背诵 | `item` `on` |
| `recite_toggle` | 加入 / 移出自选集合 | `collection` `on` |
| `book_open` | **切换集子**：网格点卡，或栏里换一部 | `book` `from` `group` `kind` `items` |
| `nav_go` | 底部导航切页 | `to` `from` |
| `search` | 敲搜索框（**只给词长**） | `query_length` |

`source` 的取值就三个 —— `all`（顶上那颗）/ `group`（分类卡右上那颗）/ `book`。
这三者的区别是**用户自己看得见的区别**（顶上那颗读全库，卡片上那颗只读这一类），
所以在统计里也必须分得开。

参数字典（白名单）写在 `js/analytics.js` 的 `PARAM_KEYS`：不在表里的钥匙一律丢掉。
这不是洁癖 —— 少送一个字段，隐私那句话就少一个要圆的洞。

## 三、代码怎么搭

```
页面（43 个 HTML）
   └─ <script src="/js/analytics.js">   ← 只比 gtag 晚一点，比业务脚本早
        └─ window.Analytics.track(名字, 参数)
             ↓ 没 gtag 就静默丢掉
        gtag('event', 名字, 清洗过的参数)
```

三处约定，都是为了「加事件」这件事别扩散：

- **一个出口**：`window.Analytics.track`。业务代码只写业务参数，拼名字、判
  gtag 在不在、失败怎么办都在模块里。`gtag` 不存在（脚本被拦、页面没挂 base tag）
  直接返回 `false`，**绝不抛** —— 统计挂了不能把连读也带垮。
- **就近上报，不做全局委托**。本想写一套「给元素挂 `data-ga`，document 上代理」
  的通用层，否决了：这个站的按钮大多是脚本拼出来的，还要区分分类卡 / 顶上、
  译文 / 原文，通用层的判断会比埋点本身还长。就近写一行 `track(…)` 反而看得懂。
- **集子名认 `data-gw-root` 上的 `data-page`**，不认 `<title>`。集子页不止 18 个，
  但都是同一份引擎渲染的，`data-page` 是它们本来就有的稳定标识 —— 靠这个，
  「切换集子」报出来的 `book` 与 `js/library.js` 的 `ENTRIES` 是同一套名字。

### 两个坑，踩过了记在这

**1 · 片段里的事件认不出上下文。** 作者索引第二层是把行先拼进 `DocumentFragment`、
再一次性贴进 DOM 的。点击落在片段里时 `closest(".group-head")` 往上走到片段就断了，
「顶上那颗」与「分类卡上那颗」分不出来。所以模块里留了 `Analytics.defer(fn)`：
把上报推迟到事件循环的下一步，那时节点已经贴进 DOM，`closest` 照常能用。
（现在这条链上还没人用，留着是因为它是这类页面的通用坑。）

**2 · 别挂在自定义事件上偷懒。** `reader-read-change` 这条事件看着是「已读变了」
的好挂点，但它不说「谁改的」—— 翻页补记、跨设备同步回来都会发它。
`mark_read` 因此只在阅读器那颗按钮上就近报，不挂在事件上。

## 四、怎么验

界面测试层按 Issue #278 删了（要的是构建时间），所以这一层守两道：

1. **`test/analytics-events.test.js`** —— 模块本体用 `vm` 跑起来：没 gtag 时不抛、
   有 gtag 时参数**只出白名单里的**、事件名与参数各自就位、`pageOf` 认得出集子页；
   再静态判「挂了 GA 的页面都引到了 `analytics.js`」，**反向也守 `admin/*` 一个
   gtag 都不带**，以及那十几处埋点还留在原位。
   判定的是「那一句还在」，拦得住手滑删掉，拦不住重构 —— 但比没有强。
2. **GA 后台的实时报表**：`DebugView` 里点一遍连读、换一次集子，看事件有没有落下来。
   这一步替不了，因为「报了什么」最终是 GA 那边说了算。

## 五、要她拍板的一件事

1. **隐私条款怎么措辞**。事件里带了「是否开启连读」「从哪个集子切到哪个集子」
   这类**行为**，比 page_view 细。已经按事实把隐私页那句访问统计改写成
   「统计页面访问量与功能使用情况（…）」，并写明搜索词不上报；如果她认为行为级
   统计超出了当初「只统计访问量」的承诺，那就得砍掉一半事件（见第一节的边界）。

---

## 六、`admin/*` 不上统计（Issue #538）

`admin/*` 是内部页，PR #537 依「所有页面」一并挂了 GA。内部页的行为进了同一个
媒体资源会把外部数字搅浑，所以这五个页面（`accounts` `feedback` `index`
`pinyin` `reports`）的 gtag base tag 与 `/js/analytics.js` 一并撤掉，一个事件
都不发。`admin/index-old.html` 本就是死文件，照旧两样都没有。

撤掉之后带 GA 的页面从 42 个降到 37 个。这是**统计口径**的收窄，不涉及功能：
`js/analytics.js` 里没有 gtag 就静默丢掉的约定（见第二节）正好兜住 —— 内部页
上的埋点照旧调 `Analytics.track`，只是落到空处，不会抛。
