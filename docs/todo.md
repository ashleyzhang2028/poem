## 0. 怎么读这份文件（三条纪律）

1. **这里的每一条都是「不做」的现状，不是「即将上线」。**
   界面上不许把这里的任何一条写成「即将上线」（`docs/architecture.md` §5.0 末尾那条），
   本文档也不许写成排期承诺。这里的条目**没有日期、没有工期** ——
   全看「有人真要」，不被「排期到了」推着走。
2. **做完一件就搬走一件。** 某一条真开工并落地时，它的设计写进
   `docs/architecture.md`（或 `docs/auth-design.md`），本文档只留一行删掉的痕迹
   （从表里拿掉 + 在「已搬走」里记一句搬到哪一节），
   **不在两个地方各留一份口径** ——「限制写在 A 处、读取在 B 处」正是本项目反复踩的坑。
3. **卡点是「日历时间」的，就得如实写出来。** 下面几条里有的是等人点头（产品口径），
   有的是等**资质 / 备案 / DNS 生效**（日历时间，不是人日）。写清楚，
   免得下一次翻这份文件的人又把「等资质」当成「没人做」。
