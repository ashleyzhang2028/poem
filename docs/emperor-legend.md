# 帝王「中国」· 传说时代（三皇五帝与同时诸家）

> 2026-09-29，Issue #407 的两条追问：
>
> > 「三皇（伏羲、神农、燧人），史记五帝，鲧、禹、丹朱。
> >   少昊、女娲、有巢氏、玄嚣、象、蚩尤、共工、祝融、帝俊 等？」
> >
> > 「这些要写吗 靠谱吗？」
>
> 这一份就是那两问的回答：**写哪些、为什么不写另几个、每一位的靠谱度
> 各到什么程度。**

## 一句话的回答

**写，但与夏以后分开另立一段**，段的抬头写清它是什么史料；
**鲧、丹朱、象、禹这几位不以帝王身份入卷**（各有各的去处，见下）。
「靠谱」这三个字，逐位分开说 —— 有的在《史记》里直书，有的只是神话，
不能一概而论。

## 为什么另立一段

这批人不是「帝王」这个制度里的角色：三皇五帝是部落联盟时代的传说首领，
**尧舜的禅让与禹启的「家天下」之间才是王位的起点**。把他们混进「夏」段，
等于把传说当信史。

但他们又确实在**传世文献与教科书**里都站着：《史记》开篇就是《五帝本纪》，
《尚书》始于《尧典》，统编版初中历史第一课讲的就是炎黄、尧舜禹。
孩子读到那一课就会来问 —— 装作没有，反倒不如把话说清楚。

所以本卷的办法是：**另立一段，段内按传世文献的谱系列序，每位在【生平】
里如实交代其史料性质**。既不把神话写成信史，也不因为它是传说就不写。

|---|---|---|---|
| 三皇 | 伏羲 | 风姓之君，画八卦、教佃渔 | 《易·系辞》《史记》有载；三皇之名汉以后才排定 |
| | 神农 | 姜姓（一说即炎帝） | 农、药、市三事都托名于他，**神农 ≠ 炎帝**之说与合一之说并存 |

## 谁没写，为什么

用户在追问里点了名、本卷**没有**以帝王身份收的几位。这不是漏，是各人的
去处不同：

| 谁 | 去处 | 为什么 |
|---|---|---|
| 鲧 | 只在相关正文里出现 | 禹之父、治水无功。他是臣，不是君 —— 本卷收的是帝王 |
| 丹朱 | 只在《尧》的【生平】里 | 尧之子，与舜争位而败。同上 |
| 象 | 只在《舜》的【生平】里 | 舜之弟，三次谋害舜的那一位。同上 |
| 三苗 | 只在《尧》《舜》的【军事】里 | 是部落之名，不是人名 |
| 禹 | **在「夏」段**（第一位） | 他跨传说与信史，是夏的开国者 —— 只入一处，入「夏」 |
| 炎帝 | 与神农合并处理 | 一说即神农；本卷在《神农》正文里写清这个异说 |

## 「靠谱吗」——三档

**第一档：有完整的传世文献**
尧、舜。有《尚书·尧典》这一篇在，官制、历法、五伦之说都落到实处 ——
文献上远较三皇为实，虽仍是传说时代。

**第二档：《史记》直书，但司马迁自己存疑**
黄帝、颛顼、帝喾。《五帝本纪》开篇即写「学者多称五帝，尚矣」，
意思是：传下来的话多，可信的不多。本卷在正文里把这句话的意思写进去。

**第三档：只有诸子的追述或纯是神话**
燧人、有巢氏（只有《韩非子》那一两句）；帝俊、女娲（神话系统里的角色）；
蚩尤、共工、祝融（一人多说的类型）。本卷照收，但正文里点明出处与分量。

## 三个字段为什么填「无」

传说时代诸位的「年号 / 谥号 / 庙号」三格一律标「—（无纪年）」
「—（无谥法）」「—（不立庙）」，理由分别是：

- **年号**：纪年之制起于汉武帝（建元），此前只有「某王某年」。传说时代
  连「某年」都无从考，所以填「—（无纪年）」，年代只在【生平】里用「相传」
- **谥号**：谥法行于周。黄帝 / 颛顼 / 帝喾 / 尧 / 舜这些是**名号**，
  不是谥法上的谥号 —— 填「谥号」等于承认谥法已经在用了
- **庙号**：庙号始于汉，更不必说

## 一个技术上的取舍：新段为什么要另起号段

传说时代那 16 位排在**卷首**（段序最前），但确实是后补的。壳里的 id
（`em-c-01`…）是按列表次序生成的，而主表 `data/text-master.js`
**拿 id 当「同一人」的钥匙** —— 若照位次编号，已有 340 位的 id 会整体
推后一位，主表里的正文全部错位。

所以这一段另起号：`em-c-legend-01` … `em-c-legend-16`，老号段一位不动。
同一条纪律写进了两处：

- `scripts/build-emperor.js` 里 `shells()` 的注释（新增段落写在源表末尾）
- `scripts/lib/entry-patch.js` 的 `applyAll()`：换正文而身份行（表头第一格）
  与标题对不上时**当场报错**，不许写盘

> 这条纪律不是凭空加的：名著导读那一卷的 `mingshu-ms-440` / `441`
> 两条就吃过这个亏 —— 正文改了、`version` 没跟上，客户端据 `version`
> 判「这条是不是新的」时会漏掉它们。这一轮一并修正了（见 PR）。
