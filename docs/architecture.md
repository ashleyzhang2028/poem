## 0. 一句话结论

**用 Supabase，免费版不休眠，但它只当「账号目录」和「跨设备进度库」；
发信不走 Supabase，走自己的 `/api` 云函数（**主 Resend**；SendGrid 已转向收费，见 §2.5）；
前端不上 Next.js，继续静态站；后端**每个业务需求一个函数**，不合并成框架。**

> ⚠️ **原始口径是「不超过 6 个 Serverless 函数」**，2.2（权威发放）把它变成 **9 个**，
> 3 期 P0（古诗词大会判分）再加 1 个，Issue #197（完整登录流程）再 +7，
> Issue #163（头像上云）再 +1 —— 业务上是 **19 条路由**。
> 这条改动是有意的，理由不是「想要更多」，而是**原来那 6 个里没有一处能写
> `accounts.plan`** —— 于是「权益由服务端判定」（§2.4 第 8 条）这句话在代码里
> 一直是一条断链：库里所有账号的 `plan` 永远是 `free`，只有手改库才发得动。
> 见 §4.14。**「不超过 6 个」要守的是「不引入框架 / 不引入微服务」那条纪律，
> 不是这个数字本身** —— 所以现在写成「每个业务需求一个函数」，并逐条列出
> 「为什么不能更少」（§2.2）。
>
> ⚠️⚠️ **Issue #205：Vercel Hobby 档一个部署最多 12 个 Serverless 函数。**
> 19 条路由按「一个文件 = 一个函数」数就是 19 个，构建**直接失败**：
> `No more than 12 serverless functions can be added to a deployment on the
> hobby plan`。所以「每个业务一个文件」这条纪律**保留**，但部署时收口成
> **一个函数**（§2.2 末尾那张「函数数」表）：
>
> - 19 个实现文件放在 `api/_routes/`（`_` 开局 = Vercel 不当函数）；
> - `api/handler.js` 是**唯一那个函数**（固定路径），按
>   `api/_lib/routes.js` 那张**唯一的路由表**把请求交给 handler；
> - `vercel.json` 里**一条 rewrite**（`/api/:path*` → `/api/handler?__path=:path*`）
>   把外部地址接进去。
>
> **外部 URL 一个都没变。** 档位若不是 Hobby，把 `api/_routes/*.js`
> 挪回 `api/*.js` 即可，一行代码不用改。
>
> ⚠️ **收口必须是「固定函数 + 一条携带原路径的 rewrite」。** `index.js`
> 目录兜底和 `[...path].js` 动态入口都曾在线上返回平台层 404。详见 §2.2.1.1。

## 1. supabase 免费版不休眠：可行，但必须认清代价

### 1.1 为什么它会休眠（官方口径）

Supabase 免费档（Free plan）的官方规则：

| 项 | 免费档 |
|---|---|
| 活跃项目数 | 2 个 |
| 数据库 | 500 MB |
| 月活用户（MAU） | 50,000 |
| 出口流量 | 5 GB / 月 |
| **空闲暂停** | **项目连续 7 天没有任何请求 → 自动暂停（paused）** |
| 唤醒方式 | 到控制台手工点，或发一个能打到数据库的请求让它自动恢复 |

暂停不是「睡一会儿」，是**整个项目停机**：数据库不可连、Auth 不可用、
REST API 全部返回错误。对用户的表现是「打不开了」，而不是「有点慢」。

> ⚠️ 这条是本方案里**唯一一个会直接砸在用户身上**的平台限制。
> 用户背了一个月，第 8 天打开发现进度拉不下来 —— 这是产品级事故，必须在架构里消掉。

### 1.2 让它不休眠的四种办法（按推荐度排序）

#### 办法 A：GitHub Actions 定时探活（**推荐，零成本，唯一真解**）

原理：暂停的判定是「7 天内没有任何请求」。那么**每 5 天发一个真请求**即可。

本项目现成的条件：代码已经在 GitHub（`ashleyzhang2028/poem`），
`.github/workflows/` 加一个 cron 就完事，**不引入任何新服务、不需要服务器**。

```yaml
# .github/workflows/keepalive.yml
name: supabase-keepalive
on:
  schedule:
    - cron: '0 3 */5 * *'      # 每 5 天一次，留 2 天缓冲
  workflow_dispatch:           # 也留一个手动按钮
jobs:
  ping:
    runs-on: ubuntu-latest
    steps:
      - name: ping supabase
        run: |
          curl -sS -o /dev/null -w '%{http_code}\n' \
            "${{ secrets.SUPABASE_URL }}/rest/v1/accounts?select=uid&limit=1" \
            -H "apikey: ${{ secrets.SUPABASE_ANON_KEY }}" \
            -H "Authorization: Bearer ${{ secrets.SUPABASE_SERVICE_KEY }}"
```

**四个必须做对的地方，否则探活本身会失效：**

1. **必须打到数据库**，不能只 ping 域名或健康检查页 —— Supabase 的状态页
   与根路径不触发数据库活动，只有 PostgREST / Auth 的真实查询算「活动」。
2. **必须每 5 天，不能每 7 天** —— GitHub 的 `schedule` 在高负载时可能延迟数小时，
   偶尔会跳过（官方文档明确：「可能延迟、在高负载时可能被丢弃」）。
   每 5 天一次，即使偶尔跳过一次也仍在 7 天窗口内。
3. **GitHub Actions 对 60 天无提交的仓库会停掉定时任务** —— 本项目天天在改，不成问题；
   但要在 workflow 里留 `workflow_dispatch` 手动口，万一停了能一键补上。
4. **探活失败必须能被发现** —— curl 的非 2xx 要让它红，否则「探活挂了 3 个月」
   会以「某天用户突然登不上」的形式暴露出来。上面的 `-w '%{http_code}\n'`
   配合 `-f` 或后续断言即可。

**这条办法的真实成本：** 每 5 天一次请求，一个月 6 次。
免费档流量 5 GB/月，这个量级可以忽略。

#### 办法 B：把邀请来的「每日真实访问」当探活（**不推荐作为唯一手段**）

有真实用户访问就是真请求，理论上不需要额外探活。**但不能靠它**：
- 跬步现在「打开即用、未登录不用后端」，绝大多数访问**根本不碰 supabase**
- 一旦连续 7 天没人发起登录/同步请求（比如一个寒假），项目就暂停，
  而**第一个想登录的用户恰好撞上暂停**——最坏的时机

所以 B 只能当 A 的补充，不能替代 A。

#### 办法 C：UptimeRobot / cron-job.org 之类的免费监控（**备选**）

可以，但它是**多一个第三方**：多一个能访问你数据库的账号、多一条要写进隐私条款的
数据处理者。既然 GitHub Actions 已经现成，没有理由再引一个。

#### 办法 D：升级 Pro（$25/月）（**现阶段不做**）

这是唯一「官方保证不休眠」的办法，也是唯一能拿到：
- 不暂停的 SLA
- 每日自动备份 + 7 天 PITR
- 可自选区域

**判断：现阶段不做。** 理由不是钱，是**顺序错了** ——
一个还没有一个付费用户的产品，先付每月 175 元保「后端不睡」，
而它的核心问题（没有主体资质、收不了钱）一点没解决。
（顺带：用户 2026-09-17 已决定**不做收费**，「收不了钱」这件事从「还没做到」
变成了「不做」—— §5.0。所以这里更没有必要为「后端不睡」付月费。）
探活方案在工程上等价，只在「忽然被 DDoS / 数据库爆掉」这类场景有差别，
而那时你早就该升级了。

### 1.3 但请记住：探活只是「可用性兜底」，不是「可靠性方案」

即使不休眠，免费档还有几条**探活解决不了**的限制：

| 限制 | 影响 | 应对 |
|---|---|---|
| **没有自动备份**（免费档无 PITR） | 误删数据 = 数据永久消失 | 每周一次 `pg_dump`（同样用 GitHub Actions）导出到仓库 artifact |
| 数据固定在美国 / 新加坡等共享区域，**不能自选** | 机房位置不可控 | 与合规无关（本站不以「国内项目」为前提，见 §4.2）；只按「最小化上传」设计 |
| 出口流量 5 GB/月 | 大文件不能走它 | 进度数据是 KB 级，不会触到 |
| 无 99.9% SLA | 平台故障只能等 | **进度数据必须本机也是完整副本**（见 §3.2 的「本机优先」） |

**最后这条最重要，它决定了整个同步架构的形状：**
> **supabase 里的进度永远不是唯一副本。本机 localStorage 始终是完整、可用的那一份。**
> 后端挂了、暂停了、欠费了，用户照样能背，只是不同步而已。

### 2.3 前端为什么**不**上 Next.js

这是本轮最该说清的一条，因为它是你最初的问题之一。

**Next.js 能带来的东西，这个项目一个都不需要：**

| Next.js 的能力 | 跬步需要吗 | 为什么 |
|---|---|---|
| SSR / ISR（服务端渲染） | ❌ | 内容全在客户端、本地生成，**没有任何一页的内容依赖服务端** |
| 路由框架 | ❌ | 13 个静态页面已经跑通，URL 约定（目录化、无 `.html`）是刻意的 |
| API Routes | ⚠️ 部分需要 | 但 Vercel 的 `/api/*` **原生就支持**，不需要 Next.js |
| React 组件化 | ❌ | 现在 25 个模块全是 IIFE + `window`，逻辑层 0 行 DOM（见下） |
| 图片优化 / 字体优化 | ❌ | 字体已**手工子集化**自托管（11 MB，比 Next.js 的自动优化更可控） |
| 打包器 / tree-shaking | ⚠️ 想要 | 但可以用 **不带框架的 Vite/Rollup 单独解决**，成本远低于上 Next.js |

**上 Next.js 的代价（真实存在，不是理论风险）：**

1. **26 个测试文件、12730 行测试几乎全部返工** —— 它们是 jsdom（加载真实 HTML）+
   源码扫描 + puppeteer。改成 React 后 HTML 是运行时生成的，
   「页面加载 js/storage.js」这类断言的对象不复存在
2. **`sw.js` 的缓存策略要重做** —— 现在是「静态资源缓存优先 + 导航在线优先」，
   写得很清楚（`README.md` 的 Service Worker 约定）。Next.js 的资源指纹变了，
   那套约定要重新推一遍
3. **首屏会变慢** —— 现在是「一个 HTML + 4 个字体 + 按需数据」，秒开。
   Next.js 客户端组件 + hydration 至少要加一个 runtime chunk，
   而**离线优先是跬步最硬的产品特性**，不能拿它换架构先进性
4. **PWA 离线承诺要重新验证** —— app shell 预缓存的清单会变（`PRECACHE` 现在是手写的，
   这恰恰是它的优点：改了什么、缓存什么，一眼看得见）

**判断：不迁移。** 如果你想要打包器，正确做法是
**只把 `js/` 那 25 个模块换成 ES modules + Rollup，页面保持静态 HTML 不动** ——
这是 0 期顺带能做的事（见 §3.1），成本约 2 人日，收益是 tree-shaking + 依赖显式化，
且**不需要动任何一页 HTML 的结构**。

#### P4：飞花令「闯关模式」（2026-09-30 · 回答 Issue #356）

`docs/dahui-redesign-plan.md` 里排最后一件：**让飞花令更像真飞花令**。
原话是「目前飞花令是『选字 → 一次性看全部命中句』，与真飞花令『轮流对句、
说不出就输』有距离」。计划给的方向是「加一个可选的闯关模式，与现有查一查
并列，不删旧功能」——照做了。

**两条并排的形态，不是把旧的改造成新的。** 飞花令屏顶部加了「查一查 / 闯关」
分段（`.game-fly-kind`，走站内既有的 `.seg`），默认仍是从前的「查一查」：

- **查一查**（`renderFlyLook()`）：原封不动——令字卡、难度段、换令、自己写
  一句 + 核一核、页底看答案。一个字没改。
- **闯关**（`renderFlyLevel()`）：一个令字一关，45 秒内自己写一句，写对了翻
  下一个字、连对累计；写不出就断在这儿。**这一屏不给「看答案」**——把答案
  清单摊开，这一关就白闯了（`render()` 里按 `flyKind` 分派）。

**判分内核放在 `js/quiz.js`，不塞进渲染层。** 一句作答算不算「写对了」是
语料问题，与谁在屏幕上敲字无关；放纯逻辑层才能不起浏览器就测（界面测试层
已按 Issue #278 删掉）：

- `judgeSetLine({poems, chars, said})` → `{ok, why, row}`。判分上「整句一字不差」
  最容易过（界面不引导用户抄，但抄对了照样算对）；标点（全角半角、带不带逗号）
  **不算门槛**——把标点与空白都丢掉，只要那些
  **连着的汉字**对得上就算（`hanRuns()`）。只写其中一段也行，前提是那一段是
  语料里**连着**的一段，跨句拼出来的不算。`why` 分五种：`empty` / `short` /
  `nochar` / `notfound` / `ok`——「写对了但没带令字」与「像诗但不是语料里的
  句子」是两件不同的事，回显的话也不一样。
- `levelChars()` 排关卡，种子写法照抄既有的 `pickChars()`（令字 + 池长 +
  轮次），同一个范围同一轮**前后端算出来是同一关**。

**两处踩过的坑，都在这一轮补上：**

1. **「换一关」差点又是个坏按钮。** `startFlyLevel()` 原先在「重来」时把
   `lvRound` 归零再 +1，于是点多少次都算出第 1 副牌——与 Issue #356 第四轮
   修过的「换令点了没反应」（种子取自身、永远同一副）**是同一个坑**。
   现在 `lvRound` 只增不减：换一关 = 轮次 +1 换牌，「重来」只清零分数。
   真机核过连点五次，令字依次是 闻色 → 下河 → 三成 → 人欲 → 人水。
2. **句库里不许留判不过的短句。** 从长句切出来的碎段（「水」「水长流」）
   也带令字，会进句库；用户照着那条抄，反而被判「太短，写整一点」。
   现在判分门槛与句库筛子共用同一个数（`MIN_SAY_HAN = 4` / `passable()`），
   `levelPool()` 与 `levelChars()` 都过这道筛子；挑不出能作答的令字就
   换一个顶上，实在没有再落到「这个范围挑不出能闯的关 → 换范围」。

**三处「鼓励口吻」**（与 P3 的成绩横幅同一套纪律，不出现否定字眼）：
倒计时到点不是判错，是「这一关先放着」（`levelDoneRow` 的 `timeout` 那格）；
卡住 20 秒给一句提示——「这一关还有 N 句别的写法」（N 是真从这一关的句库里
数出来的，不是写死的话术），不报答案；答对是令字那格缩放+绿描边一闪，
答错是轻抖（复用 P3 的 `gameOptFlashOk/Bad` 两个关键帧）。

另外三处顺手修的：**空关那颗「换一个题型」原先挂的是 `data-game-back`**——
这个属性全场没有处理函数，又是一颗点了没反应的死按钮（正是本 Issue 在修的
那类），改走既有的回大会首页那条路；**闪光动画原先在 `render()` 之前触发**，
闪的是马上要被换掉的旧节点、等于没放，现在放到 `render()` 之后；
**闯关那张卡自己造了一个「整句照抄，含『闻』」的引导**——与第五轮刚撤掉的
「整句照抄，例如日月之行」当面顶上了（那次的裁决是：这一格要的是用户**自己
想起来**的那一句，不要「照抄」这个引导），改成同一条口径，示例句也与「作答」卡
共用一个常量（**不能拿这一关句库里的句子当例子**，那是把答案摊给用户看）。

**两端同一个范围。** 这一条最容易漏：查一查按 `state.setup.scope` 过滤语料、
服务器却扫全站，就会出现「界面说没有、服务器说对上」各说一套。现在
`api/_lib/game.js` 新增 `scoped(scopeId)`，`checkFly()` 用它取语料，前端
`AccountApi.gameAnswer` 把 `scopeId` 一起带上去。服务端的语料是**按集子拼的**，
课内三学段（`poems:primary` 等）在服务端**没有 grade 数据**——这时它如实回
`scopeExact: false`（「我其实按全站判的」），前端据此**不拿它的「没找到」
去否掉本机按范围判出的「对上了」**：宁可认用户对，也不要因为服务端收窄不了
范围而误判。

> ⚠️ **这一节的口径后来被推翻了，见 4.118。** 上面那句「判分跟着范围走」
> 只对了一半：范围该收的是**令字**（题），不该收**作答**（答）。用户报
> 「令为风、我答『春风不度玉门关』被判不在范围内」，根子就是这一节的写法。
> 「服务端没有 grade 数据」这个前提也在 4.118 一并修掉了（补了 grade/term）。

**验证**：新增 `test/fly-level.test.js`（47 条：判分内核的宽与严 / 关卡排布 /
两种形态并存 / 句库筛子 / 两端范围一致），`bash test/run.sh` 28 层全绿。
真机（Chromium + CDP，390×844）核过：分段切换、连对两句跨两关、超时说
「这一关先放着」、换一关真换牌、查一查的看答案与核一核照旧。
`sw.js` v325 → **v326**（分支落后 main 三个提交，rebase 后按当时的最新版本号往后走）。

### 4.118 飞花令：范围只管令字，不管作答（2026-09-30 · 回答 Issue #356）

用户原话：

> 「关于飞花令的结果检查，例如 令为风字，我回答了 春风不度玉门关，结果答案说
>   不在范围内，这个有点违背常理，我的初始出题范围确实是目标范围内的令字，
>   但我的回答可以超出当前范围吧 否则没法回答了」

**用户是对的。** 这不是「放宽一点」的体验问题，是把**题**与**答**混成了一件事。

#### 一、根因：判分语料错用了出题范围

令字是 **风**、范围选的**小学**，答「春风不度玉门关」——
那是王之涣《凉州词》，在**乐府集**（`yf-28`）里，不在课内 251 首里，
小学那 119 篇里更没有它。

真机复现（390×844，Chromium + CDP）：

| | 语料 | 找得到「春风不度玉门关」吗 |
|---|---|---|
| 出题（令字） | 小学 119 篇 | —— |
| **判作答（修前）** | 小学 119 篇 | ❌ `notfound` |
| **判作答（修后）** | 全站 4651 首 | ✅ 凉州词 |

问题出在「判分跟着范围走」这个口径本身（§4.117 那一节写的）。上一轮为了解决
「界面说没有、服务器说对上」，把**两端**都改成按范围判 —— 方向反了：
范围收的是**令字**（出什么题），不该收**作答**（你想起来的是哪一句）。
拿范围去卡作答，就会把一句真诗判成「合集里没有」——那不是飞花令，是背范围。

#### 二、做法：`answerCorpus()` 与 `scopedCorpus()` 分家

- **`js/game.js` 新增 `answerCorpus()`**：判作答用的语料 = **整份语料**。
  两处判分都改用它 —— `checkSaid()`（查一查）与 `checkLevelSaid()`（闯关）。
  整份语料为空（各集子脚本都没加载出来）才退回 `scopedCorpus()`，
  免得判成「一句都不认得」。
- **`scopedCorpus()` 留着，用途收窄为「题」**：令字挑选、闯关句库
  （「这一关有几句」）、看答案清单、令字命中句数 —— 这四处照旧按范围走。
  选了小学就从小学挑令字，这一条不变。
- **`api/_lib/game.js` 的 `checkFly()` 同步**：判分改扫 `corpus()`（全站）。
  `scoped()` 保留 —— 令字候选池仍按 range 挑。回答里带回
  `inScope`（这一句在不在用户选的范围里），前端据它在回执里补一句
  「（不在小学里，但算对 —— 范围只管令字。）」。
  `scopeExact === false` 时 `inScope` 报 `null`（说不清），不假装。
- **顺手补上服务端的 `grade` / `term`。** 从前服务端语料只留了 `gradeGroup`，
  于是 `Ex.select(cps, "poems:primary")` 恒为空、`scoped()` 一律退全站、
  `scopeExact` 永远 `false` —— 「服务端没有 grade 数据」这句写在注释里好久的话，
  根子是那一行漏了两个字段。补上后服务端也能按学段收窄：小学 **119** 篇、
  初中 **81** 篇，与 README 的表逐字对得上。

#### 三、宽在哪、严在哪

宽：**只宽在「不按范围卡」**，不是「什么都算对」。

| 作答 | 结果 |
|---|---|
| 春风不度玉门关（乐府集，小学范围外） | ✅ 对上了 · 凉州词 |
| 夜来风雨声（课内，小学范围内） | ✅ 对上了 · 春晓 |
| 春风不度阳关道（语料里没有） | ❌ 合集里没有一字不差的一句 |

#### 四、一处不做的

闯关的过关回执**不加**「这句不在本范围」那半句。那是 45 秒一关的快节奏，
每答对一句都插一段说明反而拖沓；「算对」这个事实本身就够了。
查一查是一问一答的慢动作，那里才把出处与范围说清。

**验证**：`test/fly-level.test.js` 第四节整节重写（从「判分跟着范围走」改成
「范围只管令字，不管作答」），并把用户报的那一句**原样**钉成回归用例 ——
`checkFly({chars:["风"], said:"春风不度玉门关", scopeId:"poems:primary"})`
必须 `found:true`；反向三条（课内那句照旧算对、集子范围答课内也算对、
假句子照旧判没找到）一并钉住。真机核过：查一查答「春风不度玉门关」→
`在合集里对上了：凉州词`；闯关同一句 → 连对 +1、清单里落一行
「风 / 春风不度玉门关 / 凉州词」。`bash test/run.sh` 全绿、`doctor.js` 无告警。
`sw.js` v327 → **v328**。

### 4.119 答题音效：四种声音、四个题型、四个发声点（2026-09-30 · 回答 Issue #356 第六轮）

用户原话：

> 「考试以及飞花令闯关模式，开了答题音效……也没听到任何声音，一点都不活跃和
>   游戏闯关的感觉。包括出结果也应该有音效」

§4.117 的 P3 已经把「答题音效」写进过文档，用户却一个字也没听见。所以这一节
不写「新增了什么」，写**原先错在哪**——两处，都不是耳朵的问题。

#### 一、发声点只有三处，而且考试与出分根本走不到

第一版（P3）在 `js/game.js` 里自己造了个 `AudioContext`，只在三行调过：
`data-game-opt`（逐题即时判分）、`levelPass`、`levelFail`。哪里漏了：

| 题型 | 判分方式 | 第一版响不响 |
|---|---|---|
| 题库 / 模拟题 | `judge: instant` | ✅ 逐题响 |
| **考试（formal）** | `judge: after` | ❌ `reveal` 恒为假，那三行**永远走不到** —— 这就是用户说的「考试……没听到任何声音」 |
| 飞花令 · 查一查 | 核一核（服务器复核） | ❌ 一行都没有 |
| **交卷出分那一屏** | `renderScoreBanner` + 数字滚动 | ❌ 用户点名要的那一处，一行都没有 |
| 飞花令 · 闯关 | 答对 / 答错 | ✅ |

换句话说：用户玩的恰好是**没接线的那两半**。

#### 二、Web Audio 的静默失效：三件事凑不好就一声不响

`new AudioContext()` 造出来是 `suspended`；`resume()` 是**异步**的；而
`start()` 必须排在 `currentTime` **之后**。第一版把这三件事同时丢给浏览器安排：
在同一个 tick 里 `resume()` 完就 `start()`，运气不好（尤其中文语音正占着音频
通道）一个音符都排不出去——**控制台不报错**。这正是本 Issue 一路在修的那类毛病
（「换令」的种子取自身、空关那颗没有处理函数的死按钮），只不过音频上它不报错。

现在按 Web Audio 的规矩来：

- **解锁必须在用户手势里**。`js/sfx.js` 的 `ready()` 只由点击入口调
  （`js/game.js` 的 `unlockSound()` 挂在 `data-game-opt` / `data-game-submit` /
  `data-game-say` / `data-game-lv-say` 四处，设置页那颗「试听一声」与音效开关
  同理），没有一处从定时器里自己响。
- **`resume()` 的 then 里补一声很轻的过门**（gain × 0.35，只补一次）。Safari 与
  部分安卓 Chrome 要这么一下才算真解锁；之后每一声都稳，**包括交卷那一屏**——
  它等服务端复核，早已不在那次点击的调用栈里了。
- **`start()` 一律排在「现在 + 24ms」之后**，并给每个音符配一条 3ms 起音 +
  指数收尾的包络 Gain（同 `start` 时刻排两个节点，老 Safari 会丢后面的）。

#### 三、声音抽到 `js/sfx.js`：四种声音一张音符表

放全局文件而不是塞在 `js/game.js` 里，是因为设置页那颗「试听一声」也要发声——
**声音的出处与开关的出处得是同一个**，不然两边会各响各的。开关键仍是
`poem_sound_v1`（设备域，`js/sync-coverage.js` 里登记过的那把）。

| 声音 | 什么时候 | 音符（十二平均律） |
|---|---|---|
| `ok` | 答对 | C5 → E5 → G5（分解三音，上扬） |
| `no` | 答错 | G3 → A3，0.18s 的闷响 —— 长下行音听着像「报错」，这里只要「不对」那一下 |
| `pass` | 闯关过关 | E6 · C6 · E6 → G6（比 `ok` 更长更亮，听着才知道是「过关」不是「答对」） |
| `rank` | 交卷出分 | 前奏 G4 A4 B4 + 按分数档收尾（见下） |

出分那一声的档位与成绩横幅**同一套边**（`SCORE_BANDS` 的 90 / 60）：90+ 是
C5 E5 G5 C6 → E6 五音上冲（金）、60~89 是 C5 E5 → G5 三音（绿）、<60 是
D5 → G5 两句温柔的上行（蓝）。**三档没有一档是下行音** —— 与横幅「再练一次，
会更好」同一套纪律，不做「失败」声。

分档边写成 `Sfx.bandOf()`，`test/sfx.test.js` 里同时断言 `js/game.js` 的
`SCORE_BANDS` 还是 90 / 60 / 0：两边同源，改一边就得改另一边。

#### 四、四处新接线

- **考试（formal）**：走 `judge: after` 的用户，其声音体验就是**交卷那一屏**。
- **交卷出分**：`playRank(state.graded)` 放在 `animateScoreBanner()` 里、
  `state.gradedAnimated = true` 之后 —— 与数字滚动同起同落，且那个标志位顺带
  挡住重复播放（`submit()` 为了推服务器记录会再 `render()` 一次）。
- **飞花令·查一查**：核一核按**本机那一条**立刻响（`playSound(!!local)`），
  服务器那一趟只用来补「由服务器核对 / 服务端没接通」并覆盖判定。等一个来回
  再响就晚了半拍，听着像反应迟钝。这是本地结果先行、服务端复核的一处例外，
  写在这里备查。
- **闯关**：答对从 `ok` 换成 `pass`；答错与倒计时到点仍走 `levelFail` → `no`
  （到点是「这一关先放着」，不是判错，声音也不给「错误感」更重的那一档）。

#### 五、设置页那颗「试听一声」

`settings/reader/index.html` 的音效开关旁边加了一颗 `#sound-try`，点一下响
`ok`；打开开关时也顺手响一声。理由是**这台设备到底出不出声**（静音键、没插耳机、
浏览器拦自动播放）不该等下次考试才知道。响不出来时给一句实话
（`js/settings.js` 的 `trySound()`：没有 `window.Sfx` 说「这台设备放不了提示音」，
开关关着说「先把「答题音效」打开」），不装作响过了。

这一页原先只引 `css/style.css`（`.link-btn` 住在 `css/account.css`），这颗按钮
因此是裸的浏览器默认样式 —— 顺手补上 `account.css`（`.link-btn`）与
`classic.css`（`.settings-*` 的卡片与开关），与 `/login/`、其它设置页同一套外观。

**验证**：新增 `test/sfx.test.js`（42 条：四种声音的音符与走向 / 分档与横幅同源 /
解不开不静默失效 / 解锁只补一次 / 四个发声点与手势解锁 / 页面真的引了脚本），
`bash test/run.sh` 29 层全绿。真机（Chromium + CDP，390×844，假 `AudioContext`

### 4.120 加入背诵弹框那一行：提示语比输入的字还大、「新建」折成两行（2026-09-30 · 回答 Issue #370 第三轮）

用户原话：

> 「加入背诵的弹框 新建集合，例如：我要背的 这里的 placeholder 字号有点大，
>   应该去掉变大的字号。右侧 新建按钮居然两行显示，极其丑陋」

两处都不是「随手调个像素」，是两个**真回退**。

#### 一、提示语比输入框自己的字还大：16px 那条规矩选错了对象

`css/style.css` 里有一条 700px 以下的规矩，原先是为了治 iOS 上「小于 16px 的
输入框一聚焦，页面自己放大」：

```css
@media screen and (max-width: 700px) {
  input:not([type="checkbox"]):not([type="radio"]):not([type="file"]),
  select, textarea, .settings-input, .search-input { font-size: var(--input-font-narrow); }
}
```

它选中的是 **input 本体**。于是窄屏上：

| | 字号 |
|---|---|
| 输入框自己的字（`.settings-input`，`--ctl-font-md`） | 14px → **被顶成 16px** |
| 提示语（`.settings-input::placeholder`，写死 14px） | **14px，没被顶** |

数字上「提示语更小」，眼睛看到的是反过来的：一句「新建集合，例如：我要背的」
比用户在同一个框里打出来的字又大又稀。用户说的「placeholder 字号有点大」，
其实是**输入框的字变大了、提示语没跟上**——同一处界面，两个字号。

改法是让 16px 只管**真实输入**：

```css
.recite-new .settings-input::placeholder { font-size: var(--ctl-font-md); }
```

两边现在同一个变量，谁也不会反超谁。600 多行外那条 700px 的规矩**留着不动** ——
iOS 聚焦放大还得靠它。

#### 二、「新建」两个字折成两行：`.btn` 是「一排通栏按钮」的料，被塞进了单行

`.recite-new` 是一行 flex（输入框 `flex: 1` + 这颗键），键是 `.btn.ghost-btn`。
`.btn` 的通身本领本来是给「一排等宽通栏按钮」用的：

- `flex: 1` —— 在这行里跟输入框抢宽，**键被分到的只有 54px**；
- `height: var(--ctl-h-lg)` 44px、`line-height: var(--ctl-leading-lg)` 20px ——
  框比输入框高一档；
- `padding: 0 var(--ctl-pad-x)`（14px），而 `.ghost-btn` 只给它 `border-radius` 与描边。

390px 上量：键 54×44，里面要摆两个 15px 的字（约 30px），字就折了行 ——
「新建」竖着排，一行里最丑的正是它。

不给它换 class（`.btn.ghost-btn` 是全站同心的一颗「次一级动作」，换来换去会把
别处的好看弄坏），只在**这一行里**按住它：

```css
.recite-new .ghost-btn {
  flex: 0 0 auto;                       /* 不再吃 .btn 的 flex: 1 */
  height: var(--ctl-h-md);              /* 38px，与旁边输入框同高 */
  padding: 0 18px;                      /* 两个字不贴边 */
  font-size: var(--ctl-font-md);        /* 14px，收到输入框那一档 */
  line-height: var(--ctl-leading-md);   /* 是行高把它挤折的，必须一起收 */
  white-space: nowrap;                  /* 兜底：再也不许折 */
}
```

输入框补一条 `min-width: 0`：窄屏上先压输入框，不把键挤变形。

#### 三、验证（真浏览器量到的数）

Chromium 131 · CDP · `Emulation.setDeviceMetricsOverride`，三档宽度逐个量：

| 视口 | 提示语 | 输入框的字 | 「新建」 | 同一行？ |
|---|---|---|---|---|
| 320px | 16px ❌ → **14px** | 16px | 54×44 ❌ → **66×38** | ✅ |
| 360px | 16px → **14px** | 16px | 54×44 → **66×38** | ✅ |
| 390px | 16px → **14px** | 16px | 54×44 → **66×38** | ✅ |
| 430px | — → **14px** | 16px | — → **66×38** | ✅ |

那一行的高度从 44px 收到 38px（与输入框齐平），横向不溢出
（`scrollWidth == innerWidth`，四档都是）。截图逐张看过：提示语与键同档，
「新建」两个字横着摆、不折行、不贴边。

### 4.59 切子用户：首页标题不跟、头像串脸（2026-09-29 · 回答 Issue #444）

用户原话：

> 「目前创建子用户，子用户切换时，我的页面 顶部卡片内的头像应该要跟随子用户
>   切换而变化，然后右下角我的里面的头像也应该跟随子用户切换而更换头像
>   当设置子用户昵称，顶部卡片名称会跟着自动更新，但是回到背诵首页，标题中
>   跬步后面 xxx 的背诵没有应用子用户的昵称」

#### 一、根因：昵称与头像各有**两份落点**，接的却不是同一份

| 谁 | 权威落点 | 谁在读 | 切子用户时 |
|---|---|---|---|
| 子用户昵称 | `poem_family_v1` 名册里那条 `nickname` | `Avatar.nickname()`、「我的」页身份行、名册面板 | ✅ 跟着走 |
| 同一个昵称的**副本** | `poem_recite_settings_v1::<id>.username` | **首页标题**（`js/app.js` 的 `userName()`）、阅读器 `currentUsername()` | ❌ 不动 |
| 头像地址 | 名册里那条 `avatar.img` | `Avatar` | ✅ 跟着走 |
| 本机那份头像**字节** | `poem_avatar_local_v1::<id>` | `Avatar`（优先显示的那一份） | 见下 |

三处症状、两条根因：

1. **首页标题读的是副本**。`Family.rename()` 只写名册，副本停在旧名；而
   `js/app.js` 的 `userName()` 只读 `settings.username`（那份副本）——
   于是「改了名，标题不跟」。阅读器那一页的 `currentUsername()` 更早一层：
   它直接读**未分家**的 `localStorage["poem_recite_settings_v1"]`，
   连当前是哪个孩子都不问。
2. **本机那份头像字节的回落串脸**。`Avatar.localRaw()` 在「当前子用户名下
   没有字节」时会回落到不分家的老键 `poem_avatar_local_v1`。老键是设备域的
   一份，谁都能读 —— 于是任何「自己没传过头像」的子用户都顶着上一个人的脸：
   切过去头像不变，正是用户报的那件事。

#### 二、做法：昵称以名册为唯一真相，老键不再当公共的那一张

- **首页标题改口**：`js/app.js` 新增 `currentNickname()`，先问
  `Avatar.nickname()`（名册那条），名册没有才回落 `settings.username`。
  `syncBrandPage()` 的 `is-default` 判据同源。
- **改名把副本写平**：`js/family.js` 的 `rename()` 新增
  `syncSettingsUsername()`，把被改那个孩子名下的那份 `settings.username`
  一并写平 —— 老副本不再各说各的（导出备份、其它页面的兜底还读它）。
- **阅读器改口**：`js/reader-core.js` 的 `currentUsername()` 也先问
  `Avatar.nickname()`；`saveUsername()` 改走 `Avatar.saveNickname()` +
  `ProgressStore.saveUsername()`，写得进名册，不再只手写老键。
- **接上 `family-change`**：`js/app.js` 从前只接 `storage`（跨页签），
  而切子用户 / 改名都发生在同一页里，`storage` 不响 —— 标题要等刷新才换。
  现在另接一道 `family-change`，把标题、进度、计划按新的那个孩子全部重来。
- **头像不再串脸**：`Avatar.localRaw()` 有「你是谁」这一层时**只读名下那一把**，
  名下没有就回自己的首字印；老用户那张图不丢 —— 建名册时
  `Family.ensure()` 已把它搬给第一个孩子并撤掉老键（`adoptLegacyAvatarBytes`）。

  就归当前选中的那一个再撤掉（老键没记 owner，只能这么判）。

#### 三、这一层怎么守

`test/family.test.js` 七之三：改名后老副本一起写平、新建另一个孩子不动当前
副本、切过去副本读的是对应那条。

七之四：老键上留着一张图时，「自己没传过头像」的孩子回自己的首字印、
画出来的图不含别人的字节；名册已在时 `ensure()` 补认领后老键撤掉、

### 4.118 注音勘误：某一篇的某一处读错了，谁来兜（2026-09-19 · 回答 Issue #243）

用户原话：《滕王阁序》「秋水共长天一色」的「长」注音算错了，能不能按篇修正？
本节是这一层设计记录的**唯一一份**（原先的 §4.40 随一轮文档清理被误删，
本轮按测试 `test/pinyin-fix.test.js` 的守卫补回）。

#### 一、为什么开勘误表而不是继续补词表

注音是**算**出来的：`data/pinyin-table.js` 给候选读音，`js/pinyin.js` 的词表消歧
多音字，两者都不中取第一个。这类错补不完 —— 近两千篇古文，任何一篇都可能出现
词表没料到的组合，逐词补词表意味着每补一次都要发版。所以单开一层**勘误表**：
「某篇 · 某句 · 第几次出现 → 读什么」，增删随账号同步、立即生效。

用户点名那一处仍**正本清源进词表**（`WORDS` 补 `长天 / 长空`），这是通例；
勘误层管的是词表照顾不到的个例，两者分开看。

#### 二、数据形状：五个字段

```
{ wid: "book-…", line: "秋水共长天一色。", at: 1, ch: "长", py: "cháng" }
```

`wid` 是 `WorksIndex.widOf()` 归并后的作品 id（一处改、处处生效）；`line` 定位到句；
`at` 是该句里第几次出现这个字（同一句两个同字各读各的）；`ch` 冗余一份方便管理页显示。

三个前提：只有多音字才查（单音字硬改等于制造新错）；必须显式声明「现在注哪篇哪句」
（`Pinyin.begin(wid, line)`，不声明不查，纯增强，输出与改前逐字相同）；
勘误优先于词表。页面用入口 `annotatePoem(wid, text, mode)`，按换行逐句调 `begin()`。

#### 三、存储：`poem_pinyin_fix_v1`，progress 里一行

本机键 `poem_pinyin_fix_v1`（跟孩子走），云端行号 `pinyin_fix:v1`（不新开表），
合并规则**谁最后改谁赢、不进冲突裁决**，客户端上限 500 条；服务端各字段截断
（句 120 字 / 读音 12 / 字 1），半条丢弃整条不生效。服务端走自己的
`sanitizePinyinFix()`（不是通用进度那一套）。

#### 四、管理页面按点击定位（2026-09-29 改版）

原「选句 + 填第几个字」按位置手填、引擎按第几次出现读，几乎全部不生效。改版后：
① 搜篇目；② 点读错的字（全文摊开，多音字虚线可点，已改标绿）；③ 点正确读音
（候选来自读音表，标出「自动」那一个，也可手填）—— `line/at/ch` 全由点击位置算出，
管理员不再手填。查表键同时带上 `ch`，避免同句别的多音字被误套读音；
超过 120 字的段落按截断后前 120 字匹配。

#### 五、这一层怎么守

`test/pinyin-fix.test.js`：键名 / 云端行号 / `add` / `cloudRow` / `applyCloud`
（整份替换、更旧则 `keepLocal`）/ 服务端白名单与清洗（含截断与半条丢弃）/
SW 预缓存清单 / 缓存版本号往上推 / 同步边界总表登记 / `ProgressStore` 的
`KEYS` 与分域表（上云 + 跟孩子走），以及**本节的存在**。

### 4.119 搜索页「敲几个字再删」为什么卡（2026-10-05 · 回答 Issue #370）

用户报：「搜索页输完三个字四个字，进行删除的时候，性能特别差。」真机（Chromium 153 · CDP）
量出来是这一段 —— 注意卡的不是「删」，是**单字那一刻**：

| 操作 | 改前 | 改后 |
|---|---|---|
| 「春」（1 字） | **5.3 s** | 4.8 s（同为未截断的 1149 行） |
| 「春江」 | 339 ms | 258 ms |
| 「春江花月夜」 | 172 ms | 176 ms |
| 删回「春江花」 | 185 ms | 176 ms |
| 删回「春」 | **5.7 s** | 5.6 s |

#### 一、两笔真账

① **为两千条不展出的条目白建行**。搜索页每敲一个字都
`api.setItems(allItems())` —— 阅读器于是把 5405 行 DOM 建起来（实测 981 ms），
再拿 keyword 滤出命中集重画一遍。单字（「春」「一」「月」）在 5405 条里命中
两千上下，两笔账叠在一起就是秒级。删字时把链子往回走一遍，就是同一件事反复做。

② **每条重算一遍折叠字段**。`matchScore` 每个字对 5405 条的正文 / 译文 /
释义 / 注脚各折一次大小写 —— 单次翻出去一个字就是十兆字符。

#### 二、做法：建索引、不建行

先在**索引**里筛出命中集（只算不建 DOM），按分数排好，截到 `SEARCH_MAX`（100）
条，再交给阅读器。查询串本身带缓存（`QUERY_CACHE_MAX` 12 条）—— 删一个字落回
刚看过的那串时，命中的是缓存里那同一批对象，一行都不重画。

截断只砍**分数最低**那一档的后半（「春」的 1149 条里 4 分 82 / 3 分 4 / 2 分 432 /
1 分 631），所以截掉的一定排在展出之后 —— 原先展出的九条一条不少，只是不再为
剩下的两千条白建行。

顺带两处：`allItems()` 的判重结果不再每敲一字重算；`annotateMatches()` 每行
不再 `allItems().filter(...)` 找自己（页均两三千次 × 5405），改成按 id 建一张小表。

#### 三、守卫

`test/search-typing.test.js`（静态判据，读源码）：缓存与上界在不在、
分数四档是不是照旧、喂给阅读器的是不是截过的命中集、`keyword` 是不是先清再
`setItems`、`annotateMatches` 有没有回到每行扫全表。

**验证**：`bash test/run.sh` 全绿（5150 条）。

### 4.120 背诵卡片一天只算一次，以最后一次的选择为准（2026-10-06 · 回答 Issue #481）

用户报：「今日背诵 古诗背诵的弹出卡片，忘记、模糊和记住三个按钮，理论上每天这三个
互斥按钮总共只能点击一次，如果再点击，不要累加结果，而是更新结果。用户点完记住，
再点忘记，只能更新数据为忘记存到数据库。掌握度、已复习次数每天只能统计一次，
按最后一次的选择统计。」

#### 一、问题在哪儿

改前 `ReviewModels.review()` 是「读旧值 → 加一笔」：每按一下 `reviewCount += 1`，
遗忘次数、阶段、下次复习时间都在**当前**这份上继续往前推。于是同一天连点三下，
「已复习」就变成 3 次，阶段也被推了三格 —— 而用户当天其实只复习了这一首。
「掌握度」是从阶段与遗忘次数算出来的，跟着一起虚高。

#### 二、做法：留一份「今天的底」，改判时退回去重算

点在**头一次**时，把「点之前」那份记录原样存进 `dayBaseRec`，并记下日期
`dayBase`（本地日界，与首页「今天」同一口径）。同一天再点（`dayBase === 今天`
且 `lastReviewAt` 也在今天）就是**改判**：先 `adopt()` 退回 `dayBaseRec`，再按
新选择算一遍。

这样阶段 / 遗忘次数 / 下次复习时间**一起翻**，不会出现「阶段是忘记的、遗忘次数
却算了两次」这种自相矛盾的记录；`reviewCount` 因为底里就已经含着头一次那一笔，
退回再 `+1` 天然只算一次。跨过 0 点 `dayBase` 作废，下一次点击是全新的一天，
计数才重新 +1。

⚠️ 「有底」不能拿 `dayBaseRec` 有没有值来判：新学的一首头一次点之前是**一张
空记录**，`dayBaseRec` 就是 `null`。所以判据是 `dayBase` 这个日期标记 —— 它就是
为了把「今天点过、且底是一张白纸」记下来。

⚠️ 改判时要把 `dayBase` / `dayBaseRec` 显式搬过去：`adopt()` 读的是底本身，
底里没有底，不搬第二次改判就丢了（第三次点击会当成头一次）。

#### 三、界面

弹卡片时 `paintResultButtons()` 把今天选过的那颗点亮（`✓` + 一圈实边），
提示语换成「今天已选「X」，再点只改不算新的一次」；改判后再点，toast 说
「已改为「忘记」 · ……」。判定出口是 `ReviewModels.gradedToday()` 与
`todayResult()`（都按最后一次那条历史记录算）。

#### 四、守卫

`test/review-models.test.js` 新增一组：同日连点五下只算一次、记住→忘记→记住
三样数值完整回到第一次那份、空记录上改判也对、跨 0 点重新计数、换算法不清底。

⚠️ 同一份测试里原有的「连续记住 N 次」用例**必须一天一步地走**（新的
`overDays()` 帮手），否则它们跑的是同一天连点，测的已经不是原来的事了。

#### 五、顺带修一处同步白名单的旧账

服务端 `sanitizePayload()` 的进度白名单里只认一个 `reps` —— 那是**改名前的旧字段**，
客户端早就写 `reviewCount` 了。于是「已复习 N 次」「忘过 N 次」，以及 `algo` /
`box` / `interval` / `ef` / `stability` / `difficulty` 一到云端就被悄悄抹掉，换台设备
读回来全是空白。这次一并按客户端**实际会写**的字段收齐，并把 `dayBase`（当天点过
哪一天）也带上云 —— 快照 `dayBaseRec` 不上云（那是本机的事），计数跟日期走、
不跟快照走，所以两端同一天各点一次也只会算一次。

**验证**：`bash test/run.sh` 全绿。

### 4.121 「以后再背」拆成两颗明说的键，名单落到「我的」页（2026-10-06 · 回答 Issue #481 第二轮）

用户原话：「今日背诵按钮右侧的以后再背 **右键和长按功能在手机上很难使用**，请拆分成
明日再背以及月后再背，使用合适的 SVG 图标，这三个图标右对齐，而不是贴着左侧的文字……
另外，在 我的页面 列出 明日再背和月后再背的古诗词，如果用户删除他们，**可以恢复正常
背诵次序**。」

#### 一、一颗键上的两条路，在手机上根本不成立

上一版把两档压在**同一颗键**上：短按 = 顺延一天、长按 550ms = 搁一阵子，另给右键与
数字键当替代。问题是这三样在手机上都不可靠 ——

- **长按**：移动端先触发文本选中与「放大镜」，`pointerdown` 之后手指一飘就落到
  `pointerleave`，`clear()` 把定时器撤了，键没点着、字倒是选上了；
- **右键**：触屏上没有；
- **数字键**：没有实体键盘就没有。

更要紧的是**它本来就该是两件事**：「今天不想背」与「这一阵子别上榜」是不同的意思，
只在按住的时长上差着 550 毫秒 —— 用户点错了根本看不出自己点错了哪一档。所以两颗键
各写各的名字，是这一轮的正解，不是「换一种手势」。

#### 二、两档不是两套台账，是同一个「哪天之前不排」

改前「顺延一天」那条只记 `day`（点它的日期），`holdUntil()` 再拿 `day + 1 天` 去算；
「搁一阵子」那条另记 `until`。两条路各算各的，`normalize()` 还得区分「有 until /
没 until」。这一轮把**两档都写成 `until`**，只差一个 `span`：

| 档位 | `span` | `until` | 排期怎么看 |
|---|---|---|---|
| 明日再背 | 1 | 点它的**第二天** 0 点 | `until` 之前不上榜 |
| 月后再背 | 30 | 点它那天 + 30 天 0 点 | 同上（到日子自己回来，没到再点一次就续一期） |

于是 `holdUntil()` 只剩一句「取最远的那条 `until`」，`resting` / `restUntil` /
`unrest` 都多收一个 `tier` 参数（认的是 `span`：1 天 = 明日、30 天 = 月后）。

⚠️ **一条一个人在同一档上只留最近点的那一次**：`normalize()` 的排重键从
`wid@day` 换成 `wid@span`。改前「点两天」会攒成两条（`days()` 数出 2）；现在改的是
那一条的日子（`days()` 数的是「点过几档」）。`days()` 口径随之一并收窄 —— 它是给
「这一首在名单里躺着吗」用的，不是「点过几次」的计数器。

⚠️ **老条目按明日档补**：拆档之前的条目没有 `span` / `until` 两格，`normalize()` 按
1 天补上（`until = day + 1`），读回来的行为与改前一致。存量数据不用迁。

⚠️ **`until` 一律是 `Y-M-D` 字符串，不是毫秒**：`new Date("2026-11-5")` 会按 **UTC**
解析，往西的时区上退回前一天。所以页面上的 `fmtDay()` 认的是字符串，`listByTier()`
另给一份 0 点的时间戳（那个才走本地时间）。

#### 三、三颗键右对齐，靠 `margin-left: auto`

今日列表一行是 `.item-main` + `.item-actions` 两格 flex。改前键紧跟着正文（字数少
时看着贴在左边）；这一轮给 `.item-actions` 加 `margin-left: auto`，把它推到行尾，
排内 `justify-content: flex-end` 收拢。

⚠️ **`.item-actions` 是两张表共用的 class**：`css/classic.css` 里那一条把它做成
2 列的 grid（集子列表的朗读 / 加背 / 报告），`margin-right: var(--item-gap)`。两张表
一起加载，谁靠后谁赢 —— 首页那一排会被顶成 grid 并换行。所以：

- `classic.css` 那条改成 `.item-actions:not(#today-list *)`（排掉今日列表）；
- 今日列表那一排在 `classic.css` 末尾**再明写一遍**（同时加载的两张表之间，靠
  `:not()` 一条还不够稳）。

⚠️ **`.item { min-width: 0 }`**：三颗键之后正文那一边撑住了最小内容宽度，把键挤到
第二行（`.item-actions` 是 `flex: 0 0 auto`，不会自己缩）。加上这一条才折得下去。

#### 四、那两份名单（第三轮搬去了「背诵进度」页 —— 见 4.122）

`ReciteDefer.listByTier(tier)` 按档列出来，一条一个人（同一条只带一个档位），**到期的
不列**（日子一到它就上榜了，还挂着会让人以为它没回来）。台账只存作品号（那是有意的，
换台设备也对得上），标题 / 作者由页面从课内主表与全站目录里现查 —— 出口是
`useRef(fn)`，`clear()` 时摘掉（不留闭着整页内存的函数）。

「删除」= `unrest(wid, tier)` —— 只摘那一档，当场回到正常次序，不必等日子到。删的
那一刻 `recite-defer-change` 派发出去，首页那一趟跟着重排。

⚠️ 这一页原先是「今天」与「我的」两处**同一批键名**（`poem_recite_defer_v1`），实际
上 `ProgressStore.keyFor()` 会按子用户缩成 `poem_recite_defer_v1::<子用户 id>` ——
`recite-defer.js` 已经引了 `progress-store.js`，走的是同一个出口，不额外处理。

#### 五、守卫

### 4.122 两份名单搬到「背诵进度」页，与到期日历上下相望（2026-10-06 · 回答 Issue #481 第三轮）

用户原话：「把 我的页面里的 以后再背 中的 **明日再背和月后再背分两张卡片** 放到
`./progress/` 页面的 **到期日历 卡片的上方**，明日再背和月后再背使用**和到期日历一样的
字体，字号，样式**。删除 以后再背……删除 明天照旧上榜……删除 到日子自己回来。」

#### 一、为什么是「两张卡」而不是「一张卡里两段」

上一轮它们挤在「我的」页**一张卡**里，`<h3>` 当小标题分了 `day` / `month` 两段。用户这
一轮要的是**两张卡片** —— 两档各占一张 `<section class="card progress-card">`，各写各的
名字，谁空谁收（`hidden`）。

判据也很直白：一张卡里分两段，月后那一档就永远躲在明日底下；两张卡，两档各自跟到期
日历比肩。段还省掉了「这一档空着、那一档有」时那半张空卡的尴尬 —— 空的那张直接收
起来，不必占日历上方的位置。

#### 二、「和到期日历一样的字体，字号，样式」= 直接用这一页现成的卡头

没有新写一套样式，而是复用 `progress-head`（`h2` 走 `var(--font-poem)` / 16px / 600 /
`letter-spacing: .5px`）+ `progress-sub`（12px / `var(--ink-3)`）—— 与「到期日历」那张卡
同一对 class、同一副长相。

⚠️ 所以 `css/account.css` 里那一段 `.later-group` / `.later-group-hint`（`<h3>` 那套小标
题）**整段删掉**，不留死样式；`.later-row` / `.later-title` / `.later-meta` / `.later-del`
那一套（一条一行、右边一颗「删除」）搬到 `css/classic.css` 的 `.progress-sub` 后面 ——
`/progress/` 只加载 `style.css` + `classic.css`，不加载 `account.css`，搬错文件就是
一条都不生效。

#### 三、用户点名要删的三句

| 删掉的那句 | 在哪儿 | 怎么处理的 |
|---|---|---|
| 「以后再背」 | 「我的」页那张卡的标题 | 整张卡连 `js/mine.js` 里的 `laterRef` / `laterMeta` / `renderLater` / `bindLater` 一并删干净 |
| 「明天照旧上榜」 | 「我的」页那张卡的说明里 | 卡头小字只留「几篇」；删除后的提示改成「回到正常次序」（删掉 = 当场回来，不是「明天才回来」） |
| 「到日子自己回来」 | 同上 | 不写进小字；台账内部（`js/recite-defer.js`)那几个词是注释，不是界面 |

⚠️ `/progress/` 这页原先**没有引** `data/site-index.js`（它只引到 `works-index.js`），而
「作品号 → 标题」的现查要 `POEMS_ALL + SITE_INDEX` 一起找 —— 这一轮补上那一行脚本。
`recite-defer.js` 本来就在 `sw.js` 的预缓存表里（两页共用），不用另加。

#### 四、删除那块走 `unrest()`，日历不必重画

`ReciteDefer.listByTier(tier)` 按档列出来（**到期的不列**：日子一到它就上榜了，还挂着会让人
以为它没回来）。删除 = `unrest(wid, tier)` —— 只摘那一档，当场回到正常次序。删完只重画
两张卡：被摘掉的那一首本就「还没到日子」，不在日历的账上，日历重画是白费。

⚠️ 「明日再背」那条的 `until` 是**明天** 0 点（`span: 1`），所以它每天都在自己走动；卡上
不写日子（只搁一天，写出来反而是废话）。月后那一档写「到哪天」—— 页面的 `fmtDay()` 认的
是 `listByTier()` 给的**毫秒时间戳**（本地时间），不拿 `Y-M-D` 字符串去 `new Date()`
（那种写法会被当成 UTC，往西的时区上会退回前一天）。

#### 五、守卫

`test/recite-defer.test.js` 的第五组改名成「『背诵进度』页那两张卡」，加了十条静态判据：
两张卡各一份名单、都在 `<h2>到期日历</h2>` **之前**、明日在前月后在后、卡壳 / 卡头 /
小字用的都是这一页现成的 class；并守着「我的」页那一处**真搬走了**（`mine/index.html`
里没有那张卡、`js/mine.js` 里没有那套画法、`css/account.css` 里没有那段样式），以及
用户点名要删的三句不再当界面文案。

**验证**：`bash test/run.sh` 全绿；另起 `python3 -m http.server` 在 390×844 视口上种了
1 明日 + 2 月后，截了图（两张卡在到期日历上方、卡头与日历一致），并按顺序点掉三条
「删除」—— 每条删完行就少一条、两档都空了那两张卡自己收起来。
